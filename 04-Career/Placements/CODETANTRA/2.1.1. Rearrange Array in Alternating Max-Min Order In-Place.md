## 🧩 Problem
Given a **sorted array**, rearrange it as:

max, min, 2nd max, 2nd min...

### Example
[1,2,3,4,5,6] → [6,1,5,2,4,3]

### Constraints
- Modify **in-place**
- **No extra space**

---

## 🚧 Challenge
Direct swapping fails because:
- Overwriting destroys values needed later

---

## 💡 Core Idea (Encoding Trick)
Store **two values in one index**:

```
arr[i] = old_value + new_value * maxElem
```

Where:
- `maxElem = max_value + 1`

### Why it works
- `arr[i] % maxElem` → original value
- `arr[i] / maxElem` → new value

---

## ⚙️ Algorithm

### Step 1: Initialize
- `maxIdx = n-1`
- `minIdx = 0`
- `maxElem = arr[n-1] + 1`

---

### Step 2: Encode values
- Even index → insert max
- Odd index → insert min

---

### Step 3: Decode values
Divide all elements by `maxElem`

---

## 🧪 Code
```java
static void rearrange(int[] arr, int n) {
    int maxIdx = n - 1;
    int minIdx = 0;
    int maxElem = arr[n - 1] + 1;

    for (int i = 0; i < n; i++) {
        if (i % 2 == 0) {
            arr[i] = arr[i] + (arr[maxIdx] % maxElem) * maxElem;
            maxIdx--;
        } else {
            arr[i] = arr[i] + (arr[minIdx] % maxElem) * maxElem;
            minIdx++;
        }
    }

    for (int i = 0; i < n; i++) {
        arr[i] = arr[i] / maxElem;
    }
}
```

---

## 🔍 Key Insight
`% maxElem` ensures we always get the **original value**, even after modification.

---

## ⚠️ Pitfall
Integer overflow:
- Use `long` if values are large

---

## ⏱ Complexity
- Time: O(n)
- Space: O(1)

---

## 🧠 Memory Hook
“Hide new value inside old value, then extract later”
