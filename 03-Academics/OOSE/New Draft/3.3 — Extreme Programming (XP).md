# 3.3 — Extreme Programming (XP)

An Agile methodology focused on:
- rapid feedback
- code quality
- continuous improvement

Best for:
- small teams
- changing requirements

---

# XP Values

- Communication
- Simplicity
- Feedback
- Courage
- Respect

---

# Core XP Practices

## Planning Game
- user stories
- estimation
- iteration planning

---

## Small Releases
Release working software frequently.

---

## Simple Design
Build only what is needed now.

YAGNI:
> You Aren’t Gonna Need It

---

## TDD

Flow:
Test → Fail → Code → Pass → Refactor

Red → Green → Refactor

---

## Refactoring
Improve structure without changing behaviour.

---

## Pair Programming
- Driver → writes code
- Navigator → reviews/thinks ahead

---

## Collective Code Ownership
Anyone can modify any code.

---

## Continuous Integration (CI)
Frequent integration into shared repository with automated builds/tests.

---

## Sustainable Pace
Avoid burnout and excessive overtime.

---

## On-Site Customer
Customer closely involved with the team.

---

## Coding Standards
Shared coding conventions across the team.

---

# User Story Format

As a [role],
I want [feature],
so that [benefit]

---

# XP vs Scrum

| XP | Scrum |
|---|---|
| Engineering practices | Workflow framework |
| TDD, CI, Pair Programming | Sprint management |
| Technical focus | Team organization |

---

# Important Insight

Agile = philosophy  
Scrum = work management  
XP = engineering practices
