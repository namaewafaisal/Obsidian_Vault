# 2.4 — Specialized Process Models

Specialized process models are designed for specific software development needs.

Main models:
1. Component-Based Software Engineering (CBSE)
2. Formal Methods
3. Aspect-Oriented Development (AOD)

---

# 1. Component-Based Software Engineering (CBSE)

Build software using:
> reusable software components.

## Component
A reusable and independently deployable software unit with a defined interface.

## Examples
- Maven dependencies
- npm packages
- Spring Boot starters

## Advantages
- faster development
- reduced cost
- better reliability
- easier maintenance

## Disadvantages
- dependency issues
- integration complexity
- limited customization

## Important Insight
Modern software development heavily uses CBSE concepts.

---

# 2. Formal Methods

Use:
> mathematics to verify software correctness.

Used in:
- aerospace
- defense
- medical systems

## Core Idea
Mathematically prove software behaves correctly.

## Concepts
- formal specification
- logic
- proofs
- verification

## Z Notation
A mathematical specification language.

## Advantages
- very reliable
- detects defects early
- rigorous verification

## Disadvantages
- expensive
- difficult
- requires mathematical expertise

## Important Insight
Mainly used for safety-critical systems.

---

# 3. Aspect-Oriented Development (AOD)

Handles:
> cross-cutting concerns.

## Cross-Cutting Concerns
Features used across many modules:
- logging
- security
- transactions
- authentication

## Core Idea
Separate common concerns into:
> aspects

Applied automatically where needed.

## Example
Spring AOP for:
- transactions
- logging
- security

## Advantages
- reduces duplicated code
- cleaner business logic
- easier maintenance

## Disadvantages
- harder debugging
- hidden behavior
- added complexity

---

# Comparison

| Model | Main Focus |
|---|---|
| CBSE | Reusable components |
| Formal Methods | Mathematical correctness |
| AOD | Cross-cutting concerns |
