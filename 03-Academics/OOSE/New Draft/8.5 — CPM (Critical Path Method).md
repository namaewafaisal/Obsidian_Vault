# 8.5 — CPM (Critical Path Method)

CPM:
> project scheduling technique used to identify the longest sequence of dependent tasks.

Goal:
> determine minimum project completion time.

---

# Main Concepts

| Concept | Meaning |
|---|---|
| Activity | Task/work item |
| Dependency | Task depends on another |
| Path | Sequence of activities |
| Critical Path | Longest path in project |
| Float/Slack | Allowable delay without affecting project |

---

# Example

```text
A (2 days)
↓
B (4 days)
↓
C (3 days)
```

Total duration:

```text
2 + 4 + 3 = 9 days
```

If longest path:
> becomes critical path

---

# Parallel Paths Example

```text
Path 1:
A → B → C = 9 days

Path 2:
D → E = 5 days
```

Critical path:

```text
A → B → C
```

because it has longest duration.

---

# Float / Slack

Float:
> extra delay allowed without delaying project completion

Critical path activities usually have:

```text
Float = 0
```

---

# CPM Characteristics

| Characteristic | Meaning |
|---|---|
| Deterministic | Fixed task durations |
| Dependency-based | Activities connected |
| Scheduling-focused | Timeline optimization |

---

# CPM Steps

1. List activities
2. Identify dependencies
3. Estimate durations
4. Draw network diagram
5. Find longest path
6. Calculate float/slack

---

# CPM vs PERT

| CPM | PERT |
|---|---|
| Fixed durations | Probabilistic durations |
| Predictable projects | Uncertain projects |
| Scheduling focus | Uncertainty focus |

---

# Common Mistakes

- choosing shortest path instead of longest
- ignoring task dependencies

---

# Important Insight

Critical Path:
> longest sequence of dependent tasks controlling total project duration
