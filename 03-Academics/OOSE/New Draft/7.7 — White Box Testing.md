# 7.7 — White Box Testing

White Box Testing:
> tests internal code logic and execution paths.

Tester has knowledge of:
- source code
- control flow
- conditions
- loops

Also called:
- structural testing
- glass box testing

---

# Example

```java
if(age >= 18) {
    allowAccess();
} else {
    denyAccess();
}
```

Testing ensures:
- true branch works
- false branch works

---

# Characteristics

| Characteristic | Meaning |
|---|---|
| Code knowledge required | Internal logic visible |
| Path-focused | Tests execution paths |
| Developer-oriented | Usually done by developers |
| Structural testing | Focus on code structure |

---

# Main Techniques

- Statement Coverage
- Branch Coverage
- Path Coverage
- Condition Coverage

---

# Statement Coverage

Every statement executes at least once.

```java
a = 5;
b = 10;
c = a + b;
```

---

# Branch Coverage

Every branch outcome tested.

```java
if(x > 0)
```

Need:
- true branch
- false branch

---

# Path Coverage

Different execution paths tested.

Example:

```text
Login success
Login failure
Account locked
```

---

# Condition Coverage

Tests boolean condition combinations.

```java
if(a > 0 && b > 0)
```

Need combinations for:
- a true/false
- b true/false

---

# White Box vs Black Box

| White Box | Black Box |
|---|---|
| Internal logic visible | Internal logic hidden |
| Code/path-focused | Behaviour-focused |
| Developer perspective | User perspective |

---

# Advantages

- detects hidden logic errors
- improves code quality
- identifies dead code
- measures code coverage

---

# Disadvantages

- requires programming knowledge
- difficult for large systems
- may miss missing requirements

---

# Dead Code Example

```java
if(false) {
    executeSomething();
}
```

Block never executes.

---

# Loop Testing

Test:
- zero iterations
- one iteration
- multiple iterations
- boundary iterations

---

# Important Insight

White Box Testing verifies:
> internal code structure and execution logic
