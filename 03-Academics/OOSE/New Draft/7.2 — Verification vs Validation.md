# 7.2 — Verification vs Validation

| Verification | Validation |
|---|---|
| "Are we building the product right?" | "Are we building the right product?" |
| Technical correctness | User/business correctness |
| Checks implementation | Checks user satisfaction |

---

# Verification

Focus:
- code correctness
- design correctness
- specification compliance

Common activities:
- code reviews
- inspections
- static analysis
- unit testing

---

# Validation

Focus:
- user expectations
- business needs
- usability

Common activities:
- acceptance testing
- beta testing
- user testing
- usability testing

---

# Example

## Verification Passed

- login works
- APIs function correctly
- calculations correct

System technically works.

---

# Validation Failed

Users complain:
- confusing UI
- poor workflow
- difficult navigation

Technically correct product,
but poor user satisfaction.

---

# Static vs Dynamic

| Verification | Validation |
|---|---|
| Often static | Usually dynamic |
| May not execute code | Usually executes software |

---

# Important Insight

A system can:
- pass verification
- fail validation

Meaning:
> technically correct but wrong for users

---

# Verification vs Validation Flow

```text
Requirements
   ↓
Verification
   ↓
Implementation
   ↓
Validation
   ↓
User Satisfaction
```

---

# Important Insight

Verification ensures:
> correctness of implementation

Validation ensures:
> usefulness of the product
