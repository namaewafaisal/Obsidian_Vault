# 6.5 — Object-Oriented Design (OOD)

Object-Oriented Design:
> organizes software around objects/classes.

Focus:
- entities
- object interaction
- encapsulation
- modularity

Modern software systems heavily use OOD.

---

# Main Idea

Ask:
> what objects/entities exist in the system

instead of:
> what functions exist

---

# Example

```text
ECommerce System
- User
- Product
- Cart
- Order
- Payment
```

Objects contain:
- data
- related behaviour

---

# Main OO Concepts

| Concept | Meaning |
|---|---|
| Class | Blueprint/template |
| Object | Instance of class |
| Encapsulation | Hide internal details |
| Abstraction | Show essential features only |
| Inheritance | Reuse parent features |
| Polymorphism | Same method, different behaviour |

---

# Class and Object Example

```java
class User {
    String name;

    void login() {}
}
```

```java
User u1 = new User();
```

---

# Encapsulation

Data + behaviour grouped together.

```java
class BankAccount {
    private double balance;

    public void deposit(double amount) {}
}
```

Prevents direct access to internal data.

---

# Abstraction

Expose important behaviour while hiding complexity.

Example:

```text
Car
- start()
- stop()
```

User does not need engine internals.

---

# Inheritance

```java
class Admin extends User
```

Represents:
> IS-A relationship

---

# Polymorphism

```java
shape.draw()
```

Different implementations:
- Circle
- Rectangle
- Triangle

---

# OOD Characteristics

| Characteristic | Meaning |
|---|---|
| Object-centric | Focus on entities |
| Encapsulation | Data + behaviour together |
| Reusability | Inheritance/composition |
| Modularity | Independent classes |
| Interaction-based | Objects communicate |

---

# OOD vs Function-Oriented Design

| OOD | FOD |
|---|---|
| Objects/classes focus | Functions focus |
| Encapsulation | Data separated from functions |
| Interaction-oriented | Process-oriented |
| Better scalability | Simpler for small systems |

---

# Advantages

- maintainability
- scalability
- modularity
- code reuse
- easier large-system management

---

# Disadvantages

- higher complexity
- abstraction overhead
- overengineering risk for small systems

---

# Important Insight

OOD organizes software around:
> entities and their interactions

instead of:
> sequences of functions
