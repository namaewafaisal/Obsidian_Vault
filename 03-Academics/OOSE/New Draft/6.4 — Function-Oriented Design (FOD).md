# 6.4 — Function-Oriented Design (FOD)

Function-Oriented Design:
> organizes system design around functions/processes.

Focus:
- operations
- processing steps
- data flow

Common in:
- procedural programming
- structured design

---

# Main Idea

Start with:
> what functions the system performs

Then divide into:
- smaller subfunctions/modules

---

# Functional Decomposition

Large functions broken into smaller functions.

Example:

```text
Process Transaction
├── Validate Account
├── Check Balance
├── Transfer Amount
└── Generate Receipt
```

---

# Top-Down Design

FOD usually follows:
> top-down decomposition

High-level function
→ smaller detailed functions

---

# Example

```text
Library System
├── Manage Books
│   ├── Add Book
│   ├── Remove Book
│   └── Search Book
├── Manage Members
└── Generate Reports
```

---

# Main Characteristics

| Characteristic | Meaning |
|---|---|
| Function-centric | Focus on operations |
| Top-down decomposition | Progressive refinement |
| Data flow oriented | Functions transform data |
| Procedural thinking | Sequence-based design |

---

# Function-Oriented vs OO Design

| Function-Oriented | Object-Oriented |
|---|---|
| Functions/processes focus | Objects/classes focus |
| Data passed between functions | Data + behaviour together |
| Procedural style | Encapsulation-based |

---

# Function-Oriented Example

```text
processPayment()
generateInvoice()
sendNotification()
```

Functions dominate design.

---

# Advantages

- simple for small systems
- clear functional decomposition
- easy process understanding

---

# Disadvantages

- difficult scaling
- harder maintenance in large systems
- data and behaviour separated
- dependency issues

---

# Important Insight

Function-Oriented Design organizes software around:
> operations/functions

instead of:
> objects/entities
