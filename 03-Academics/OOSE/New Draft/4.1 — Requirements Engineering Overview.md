# 4.1 — Requirements Engineering Overview

Requirements Engineering:
> discovering, analyzing, documenting, and managing system requirements.

---

# Requirement Types

## Functional Requirements
Define:
> what the system does.

Examples:
- login
- payment processing
- report generation

---

## Non-Functional Requirements
Define:
> how the system behaves.

Examples:
- performance
- security
- reliability
- usability
- maintainability

---

# Need vs Requirement vs Specification

| Term | Meaning |
|---|---|
| Need | User/business problem |
| Requirement | System capability |
| Specification | Formal detailed requirement |

---

# Good Requirement Properties

- Complete
- Consistent
- Unambiguous
- Verifiable
- Traceable
- Feasible

---

# Important Insight

Many software failures are:
> requirement failures, not coding failures.

---

# Exam Trap

Bad:
> System should be fast.

Good:
> System shall respond within 2 seconds.

Requirements should be:
- measurable
- testable
- clear
