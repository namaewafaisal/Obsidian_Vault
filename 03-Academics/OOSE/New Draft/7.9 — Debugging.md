# 7.9 — Debugging

Debugging:
> process of identifying, analyzing, and fixing software defects.

Testing finds:
> defect exists

Debugging finds:
> why defect exists and how to fix it

---

# Debugging Flow

```text
Testing
→ Defect Detected
→ Debugging
→ Fix Applied
→ Retesting
```

---

# Common Causes of Bugs

- logic errors
- incorrect conditions
- null handling issues
- concurrency issues
- integration failures
- wrong assumptions

---

# Debugging Process

| Step | Purpose |
|---|---|
| Reproduce Bug | Make failure occur consistently |
| Isolate Cause | Narrow down problem area |
| Analyze | Find root cause |
| Fix | Correct issue |
| Retest | Verify fix works |

---

# Example

Bug:

```text
Login succeeds with wrong password
```

Debugging investigates:
- authentication logic
- database query
- condition checks

---

# Common Debugging Techniques

| Technique | Purpose |
|---|---|
| Print/Logging | Inspect values/state |
| Breakpoints | Pause execution |
| Stack Trace Analysis | Locate failure source |
| Step Execution | Execute line-by-line |
| Rubber Duck Debugging | Explain logic aloud |

---

# Logging Example

```java
System.out.println(userInput);
```

Used to inspect:
- variable values
- execution flow

---

# Stack Trace Example

```text
NullPointerException
at UserService.login()
at AuthController.authenticate()
```

Shows method call sequence leading to failure.

---

# Debugging vs Testing

| Testing | Debugging |
|---|---|
| Finds defects | Fixes defects |
| Detects failures | Finds root cause |
| QA/testing activity | Developer activity |

---

# Common Mistakes

- random fixes without analysis
- fixing symptoms only
- ignoring logs/stack traces

---

# Important Insight

Good debugging requires:
> systematic investigation,
not random guessing
