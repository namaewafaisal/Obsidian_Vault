# 6.6 — Architectural Design

Architectural Design:
> defines the high-level structure of the system.

Focus:
- major components/modules
- communication between components
- overall system organization

---

# Main Goals

- scalability
- maintainability
- modularity
- performance
- security

---

# Layered Architecture

System divided into layers.

```text
Presentation Layer
Business Logic Layer
Data Access Layer
Database
```

Example:

```text
Frontend
→ Controller
→ Service
→ Repository
→ Database
```

Benefits:
- separation of concerns
- easier maintenance
- modularity

---

# Monolithic Architecture

Entire application deployed as one unit.

```text
Single Backend Application
- auth
- payment
- orders
- notifications
```

Advantages:
- simple deployment
- easier initial development

Disadvantages:
- scaling difficulty
- tightly coupled modules

---

# Microservices Architecture

Application divided into independent services.

```text
Auth Service
Payment Service
Order Service
Notification Service
```

Advantages:
- scalability
- independent deployment
- fault isolation

Disadvantages:
- distributed system complexity
- communication overhead

---

# Client-Server Architecture

Clients communicate with central server.

```text
Browser → Web Server → Database
```

Common in:
- web applications
- mobile backends

---

# Architectural Components

| Component | Meaning |
|---|---|
| Component/Module | Major system part |
| Connector | Communication path |
| Interface | Interaction contract |

---

# Architecture vs Detailed Design

| Architectural Design | Detailed Design |
|---|---|
| High-level structure | Low-level implementation |
| Modules/services | Classes/methods |
| System organization | Internal logic |

---

# Important Insight

Architecture decisions strongly affect:
- scalability
- maintainability
- deployment
- team organization

Architectural Design answers:
> "How should the entire system be organized structurally?"
