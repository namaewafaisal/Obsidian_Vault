# 7.5 — System Testing

System Testing:
> tests the complete integrated system as a whole.

Goal:
> verify entire application works according to requirements.

---

# Example

```text
User Login
→ Browse Products
→ Add to Cart
→ Payment
→ Order Confirmation
```

Entire workflow tested together.

---

# Scope

Covers:
- frontend
- backend
- database
- APIs
- integrations
- overall behaviour

---

# System Testing vs Integration Testing

| Integration Testing | System Testing |
|---|---|
| Module interaction | Entire system behaviour |
| Partial scope | Full application scope |
| Technical integration focus | Requirement/business focus |

---

# Characteristics

| Characteristic | Meaning |
|---|---|
| End-to-end testing | Full workflow tested |
| Requirement-based | Compared against specifications |
| Black-box oriented | Focus on external behaviour |
| Near production-like | Realistic environment |

---

# Types of System Testing

- Functional Testing
- Performance Testing
- Security Testing
- Usability Testing
- Stress Testing
- Recovery Testing

---

# Functional Testing

Checks:
- features work correctly

Example:
- login
- checkout
- search

---

# Performance Testing

Checks:
- response time
- scalability
- load handling

Example:

```text
1000 concurrent users
```

---

# Security Testing

Checks:
- authentication
- authorization
- vulnerabilities

---

# Usability Testing

Checks:
- user experience
- navigation simplicity
- UI clarity

---

# Common Problems Found

- workflow failures
- performance bottlenecks
- security issues
- configuration problems
- integration inconsistencies

---

# Important Insight

System Testing ensures:
> the complete software system behaves correctly as a whole
