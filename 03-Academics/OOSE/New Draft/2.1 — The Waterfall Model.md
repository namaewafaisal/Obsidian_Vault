# 2.1 — The Waterfall Model

A linear and sequential software process model where each phase must finish before the next begins.

---

# Waterfall Phases

1. Requirements
2. Design
3. Implementation
4. Testing
5. Deployment
6. Maintenance

Flow is strictly sequential.

---

# 1. Requirements Phase

Goal:
> Understand customer needs.

Output:
- SRS document

---

# 2. Design Phase

Goal:
> Plan system structure.

Includes:
- architecture
- database design
- module design

Output:
- design documents

---

# 3. Implementation Phase

Goal:
> Write code based on design.

Output:
- source code/modules

---

# 4. Testing Phase

Goal:
> Detect and fix defects.

Includes:
- unit testing
- integration testing
- system testing

Output:
- validated software

---

# 5. Deployment Phase

Goal:
> Release software to users.

---

# 6. Maintenance Phase

Goal:
> Handle changes after release.

Includes:
- bug fixes
- updates
- feature additions

---

# Main Characteristic

Each phase must be completed before moving to the next phase.

Very little backtracking.

---

# Advantages

- simple and structured
- easy project management
- strong documentation
- suitable for stable requirements

---

# Disadvantages

- inflexible to change
- customer sees product late
- testing occurs late
- unsuitable for rapidly changing projects

---

# Suitable For

- defense systems
- medical software
- aerospace systems

Projects with:
- fixed requirements
- strict documentation

---

# Important Insight

Waterfall assumes:
> Requirements are known completely at the beginning.

This often fails in modern software projects.

---

# Key Concept

Output of one phase becomes input for the next phase.

Example:
Requirements → Design → Code → Testing
