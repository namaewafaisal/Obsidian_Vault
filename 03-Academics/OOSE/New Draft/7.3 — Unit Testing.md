# 7.3 — Unit Testing

Unit Testing:
> tests smallest individual components of software.

Usually tests:
- functions
- methods
- classes
- small modules

Goal:
> verify each unit works correctly independently.

---

# Example

```java
int add(int a, int b)
```

Test cases:

```text
add(2,3) → 5
add(-1,1) → 0
```

---

# Characteristics

| Characteristic | Meaning |
|---|---|
| Small scope | Tests single component |
| Isolated | Independent from other modules |
| Fast execution | Runs quickly |
| Developer-focused | Usually written by developers |

---

# Isolation

Unit tests should avoid:
- real databases
- real APIs
- external systems

Instead use:
- mocks
- fake services

---

# Assertions

Compare:
> expected result vs actual result

Example:

```java
assertEquals(5, add(2,3));
```

---

# Positive Test Case

Tests valid input.

Example:

```text
valid login credentials
```

---

# Negative Test Case

Tests invalid/error conditions.

Example:

```text
wrong password
empty input
```

---

# Boundary Testing

Tests edge values.

Example:

```text
password length:
7
8
9
```

Common source of bugs.

---

# Example JUnit Test

```java
@Test
void testAddition() {
    assertEquals(5, add(2,3));
}
```

---

# Mocking

Uses fake dependencies during testing.

Examples:
- fake database
- fake API response

Purpose:
> isolate unit being tested

---

# Benefits

- early bug detection
- safer refactoring
- easier debugging
- regression prevention
- improved reliability

---

# Unit Testing vs Integration Testing

| Unit Testing | Integration Testing |
|---|---|
| Single component | Multiple components together |
| Isolated | Interaction-focused |
| Fast/small scope | Broader scope |

---

# Important Insight

Unit Testing ensures:
> small components behave correctly independently
