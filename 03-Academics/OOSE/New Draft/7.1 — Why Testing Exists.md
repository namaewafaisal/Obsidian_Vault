# 7.1 — Why Testing Exists

Testing:
> process of finding defects/errors in software.

Goal:
> verify software behaves as expected.

---

# Important Insight

Testing does NOT prove:
> software is bug-free

Testing only shows:
> defects may exist under tested conditions.

---

# Why Testing Is Needed

Software bugs occur because of:
- logic mistakes
- misunderstood requirements
- edge cases
- integration failures
- system complexity

---

# Main Testing Goals

| Goal | Meaning |
|---|---|
| Defect Detection | Find bugs |
| Verification | Check technical correctness |
| Validation | Check user/business needs |
| Reliability | Improve stability |
| Quality Assurance | Increase confidence |

---

# Error vs Fault vs Failure

| Term | Meaning |
|---|---|
| Error | Human mistake |
| Fault/Bug | Incorrect code/design |
| Failure | Incorrect system behaviour |

Example:

```text
Developer mistake
→ Bug in code
→ Runtime failure
```

---

# Testing Levels

```text
Unit Testing
→ Integration Testing
→ System Testing
→ Acceptance Testing
```

---

# Verification vs Validation

| Verification | Validation |
|---|---|
| "Building product right?" | "Building right product?" |
| Technical correctness | User/business correctness |

---

# Exhaustive Testing Is Impossible

Cannot test:
- every input
- every path
- every state

Testing focuses on:
- important paths
- risky areas
- representative cases

---

# Defect Clustering

Small number of modules often contain:
> most bugs

---

# Early Testing

Earlier bug detection:
> cheaper fixing cost

---

# White Box vs Black Box

| White Box | Black Box |
|---|---|
| Internal logic visible | Internal logic hidden |
| Code-focused | Behaviour-focused |

---

# Manual vs Automated Testing

| Manual | Automated |
|---|---|
| Human executes tests | Scripts/tools execute tests |
| Flexible | Faster repetitive testing |

---

# Important Insight

Testing should happen:
> throughout development lifecycle

not only after coding ends.
