# 5.10 — Petri Nets

Petri Nets:
> formal modelling technique used for concurrent and distributed systems.

Focus:
- concurrency
- synchronization
- parallel execution
- resource sharing
- conflicts

---

# Motivation

FSMs are good for:
> sequential systems.

But FSMs struggle with:
- parallel activities,
- distributed systems,
- synchronization.

Reason:
> FSM state space grows rapidly.

Petri Nets model concurrency:
> naturally and compactly.

---

# Main Components

| Component | Meaning |
|---|---|
| Place | State/condition |
| Transition | Event/action |
| Token | Active state marker |
| Arc | Directed connection |

---

# Notation

| Element | Symbol |
|---|---|
| Place | Circle |
| Transition | Rectangle/bar |
| Token | Dot inside place |
| Arc | Arrow |

---

# Basic Structure

```text
(Place) --> [Transition] --> (Place)
```

---

# Main Idea

Tokens move through the network when:
> transitions fire.

Current system state represented by:
> token distribution.

---

# Simple Example

```text
   (Idle •)
        |
        v
   [Start Process]
        |
        v
    (Running)
```

Meaning:
- token initially in `Idle`
- after transition fires,
- token moves to `Running`

---

# Firing Rule (VERY IMPORTANT)

A transition is:
> enabled

when:
- all input places contain at least one token.

When transition fires:
- consumes one token from each input place,
- produces one token in each output place.

---

# Example

Before firing:

```text
(A •) --> [T] --> (B)
```

After firing:

```text
(A) --> [T] --> (B •)
```

Token moved:
```text
A → B
```

---

# Concurrency Modelling

Petri Nets model parallel execution naturally.

Fork transition can:
> produce multiple tokens simultaneously.

---

# Concurrency Example

```text
           (OrderPlaced •)
                  |
                  v
             [Fork Process]
              /         \
             v           v
      (SendEmail •) (UpdateInventory •)
```

Meaning:
- both activities can execute in parallel.

---

# Synchronization

Multiple tokens may be required before continuing.

---

# Synchronization Example

```text
(EmailDone •) ----\
                   > [CompleteOrder] --> (Finished)
(InventoryDone •)-/
```

Transition fires only if:
- BOTH places contain tokens.

---

# Conflict Modelling

Petri Nets can model:
> non-deterministic choices/conflicts.

Occurs when:
- multiple transitions share same input place.

Only one transition can fire.

---

# Conflict Example

```text
          (Request •)
             |
      ----------------
      |              |
      v              v
 [Approve]      [Reject]
```

Possible outcomes:
- Approve fires,
OR
- Reject fires.

Both cannot consume same token simultaneously.

---

# Reading Execution Trace

Execution trace:
> sequence of transition firings.

---

# Example

Initial marking:

```text
(Start •)
```

Trace:

```text
Start
→ Login
→ Validate
→ Dashboard
```

Each firing:
- changes token positions,
- changes system state.

---

# Petri Nets vs FSMs

| FSM | Petri Net |
|---|---|
| Sequential behaviour | Concurrent behaviour |
| One active state | Multiple active states |
| State explosion problem | Compact concurrency modelling |
| Simpler | More expressive |

---

# Why FSM State Explosion Happens

In concurrent systems:
- FSM must represent every combination of states.

Example:

```text
Process A:
2 states

Process B:
2 states
```

Combined FSM may need:

```text
2 × 2 = 4 states
```

Larger systems become extremely complex.

Petri Nets avoid this by:
> representing concurrency directly with tokens.

---

# Petri Net Characteristics

| Characteristic | Meaning |
|---|---|
| Concurrent | Multiple activities simultaneously |
| Distributed | Models independent processes |
| Synchronization support | Coordinates tasks |
| Formal model | Mathematical basis |

---

# Common Uses

- operating systems
- distributed systems
- workflow engines
- manufacturing systems
- concurrent software systems

# Common Beginner Mistakes

## 1. Ignoring Firing Rule

Transition fires only if:
> all required input tokens exist.

---

## 2. Confusing Places and Transitions

| Place | Transition |
|---|---|
| Condition/state | Event/action |

---

## 3. Treating Like Flowchart

Petri Nets focus on:
> tokens and concurrency,
not simple step-by-step flow.

---

# Important Insight

Petri Nets model:
> concurrent and synchronized system behaviour using token-based state transitions.
