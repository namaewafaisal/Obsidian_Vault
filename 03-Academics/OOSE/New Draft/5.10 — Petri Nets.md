# 5.10 — Petri Nets

Petri Nets:
> model concurrent and synchronized system behaviour.

Focus:
- concurrency
- parallel execution
- synchronization
- resource sharing

---

# Main Components

| Component | Meaning |
|---|---|
| Place | State/condition |
| Transition | Event/action |
| Token | Current state marker |
| Arc | Connection/flow |

---

# Basic Structure

```text
(Place) --> [Transition] --> (Place)
```

Convention:
- circles = places
- rectangles = transitions
- dots = tokens

---

# Simple Example

```text
   (Idle •)
        |
        v
   [Start Process]
        |
        v
   (Running)
```

Token moves from:
- Idle
to
- Running

---

# Concurrency Example

```text
           (Order Placed •)
                |
        -------------------
        |                 |
        v                 v
   [Send Email]     [Update Inventory]
        |                 |
        v                 v
   (Email Sent)     (Inventory Updated)
```

Both processes can happen simultaneously.

---

# Synchronization Example

```text
(Email Sent) ----\
                  > [Complete Order] --> (Finished)
(Inventory Done)-/
```

Transition activates only if:
- both inputs are ready.

---

# Petri Net vs FSM

| FSM | Petri Net |
|---|---|
| Sequential states | Concurrent states |
| Simpler | More powerful |
| Single active state | Multiple simultaneous states |

---

# Important Insight

Petri Nets are useful for:
- distributed systems
- workflow engines
- concurrent systems
- synchronization problems

Focus:
> modelling simultaneous activities safely.
