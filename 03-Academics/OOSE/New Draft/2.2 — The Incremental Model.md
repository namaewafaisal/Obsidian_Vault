# 2.2 — The Incremental Model

A software process model where the system is developed and delivered in smaller functional parts called increments.

Each increment adds new functionality.

---

# Core Idea

Build software:
- partially
- release it
- collect feedback
- continue adding features

---

# Increment vs Iteration

## Increment
Adds:
> New functionality

Example:
- adding payment feature

---

## Iteration
Improves:
> Existing functionality

Example:
- improving payment UI

---

# Process Flow

For each increment:

Requirements
→ Design
→ Implementation
→ Testing
→ Deployment

Then repeat for the next increment.

---

# Characteristics

- software delivered in parts
- early working software
- continuous feedback
- flexible to changes
- reduced project risk

---

# Advantages

- customer sees software early
- easier to handle changing requirements
- lower risk
- easier testing/debugging
- better feedback cycle

---

# Disadvantages

- requires strong architecture
- integration can become complex
- increment planning is difficult
- continuous management needed

---

# Suitable For

- web applications
- mobile apps
- startups
- SaaS products

Projects with:
- evolving requirements
- frequent updates

---

# Waterfall vs Incremental

| Waterfall | Incremental |
|---|---|
| Full delivery once | Partial deliveries |
| Rigid | Flexible |
| Late feedback | Early feedback |
| High risk | Lower risk |

---

# Important Insight

Incremental development accepts that:
> Requirements change after users see working software.
