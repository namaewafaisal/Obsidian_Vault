# 5.6 — Communication Diagrams

Communication Diagram:
> behavioural UML diagram showing how objects communicate during runtime.

Focus:
> object relationships and message exchange.

---

# Main Idea

- objects shown as nodes
- messages shown as numbered arrows
- emphasizes collaboration structure

---

# Communication vs Sequence Diagram

| Sequence Diagram | Communication Diagram |
|---|---|
| Emphasizes time order | Emphasizes object relationships |
| Vertical timeline | Network-style layout |
| Easier for workflow | Easier for collaboration view |

Both contain:
> same interaction information.

---

# Main Components

| Component | Meaning |
|---|---|
| Object | Participating entity |
| Link | Communication connection |
| Message | Interaction between objects |
| Numbering | Execution order |

---

# Object Notation

```text
+----------------+
| :OrderService  |
+----------------+
```

---

# Message Numbering (IMPORTANT)

Used to show execution order.

Examples:

```text
1
1.1
1.2
2
2.1
```

Meaning:

| Number | Meaning |
|---|---|
| 1 | First message |
| 1.1 | Nested call inside 1 |
| 2 | Next top-level message |

---

# Example — Online Shopping System

```mermaid
flowchart LR

Customer["Customer"]
UI["ShoppingUI"]
Order["OrderService"]
Payment["PaymentGateway"]

Customer -->|1: placeOrder()| UI
UI -->|1.1: createOrder()| Order
Order -->|1.1.1: processPayment()| Payment
Payment -->|1.1.2: paymentStatus()| Order
Order -->|1.2: orderConfirmation()| UI
UI -->|2: displayConfirmation()| Customer
```

---

# Flow Explanation

```text
1 → Customer places order
1.1 → UI creates order
1.1.1 → Payment processing
1.1.2 → Payment response
1.2 → Confirmation generated
2 → Confirmation displayed
```

---

# Nested Calls

```text
1
 ├── 1.1
 ├── 1.2
      └── 1.2.1
```

Shows:
> sub-operations occurring inside a parent operation.

---

# When To Use

Use Communication Diagram when:
- object collaboration matters,
- relationship visibility is important,
- interaction network is the focus.

Use Sequence Diagram when:
- exact execution timeline matters more.

---

# Communication Diagram Characteristics

| Characteristic | Meaning |
|---|---|
| Behavioural UML | Shows runtime interaction |
| Relationship-focused | Collaboration emphasis |
| Uses numbering | Represents sequence |
| Network layout | No vertical lifeline |

---

# Common Mistakes

- forgetting message numbering
- confusing with class diagrams
- overcrowding too many objects/messages

---

# Important Insight

Communication Diagrams show:
> how objects collaborate and exchange messages during execution.
