# 2.5 — Comparing the Process Models

Different process models are designed for different project needs.

Main models:
- Waterfall
- Incremental
- RAD
- Specialized Models

---

# Waterfall Model

## Main Idea
Sequential phase-by-phase development.

## Strength
- strong structure
- heavy documentation

## Weakness
- very inflexible

## Best For
- stable requirements
- safety-critical systems

---

# Incremental Model

## Main Idea
Deliver software in smaller increments.

## Strength
- early working software
- easier requirement changes

## Weakness
- integration complexity
- architecture management needed

## Best For
- evolving applications
- modern software systems

---

# RAD Model

## Main Idea
Rapid development using prototyping and reuse.

## Strength
- very fast delivery
- continuous customer feedback

## Weakness
- architecture quality may suffer

## Best For
- short-deadline projects
- UI-heavy systems

---

# Specialized Models

## CBSE
Focus:
- reusable components

## Formal Methods
Focus:
- mathematical correctness

## AOD
Focus:
- cross-cutting concerns

---

# Comparison Table

| Feature | Waterfall | Incremental | RAD |
|---|---|---|---|
| Development Style | Sequential | Incremental delivery | Rapid prototyping |
| Flexibility | Low | Medium/High | High |
| Customer Feedback | Late | Early | Continuous |
| Delivery Speed | Slow | Medium | Very Fast |
| Documentation | Heavy | Moderate | Light |

---

# Important Trade-Offs

## Flexibility
Ability to handle changing requirements.

## Customer Visibility
How early users see working software.

## Risk
Incremental delivery reduces project risk.

## Documentation
Waterfall has the heaviest documentation.

---

# Important Insight

No process model is universally best.

Choice depends on:
- project type
- requirement stability
- deadline pressure
- team experience
- customer involvement

---
