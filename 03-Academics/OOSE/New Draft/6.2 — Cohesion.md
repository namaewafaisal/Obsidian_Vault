# 6.2 — Cohesion

Cohesion measures:
> how strongly related responsibilities inside a module are.

Good design prefers:
> High Cohesion

---

# High Cohesion Example

```text
AuthService
- login()
- logout()
- resetPassword()
- verifyOTP()
```

All functions belong to:
> authentication responsibility.

---

# Low Cohesion Example

```text
UserService
- login()
- processPayment()
- sendEmail()
- generateInvoice()
```

Mixed unrelated responsibilities.

---

# Benefits of High Cohesion

- easier maintenance
- easier testing
- better readability
- reduced side effects
- improved modularity

---

# Types of Cohesion
(Worst → Best)

---

# 1. Coincidental Cohesion

Unrelated tasks grouped randomly.

```text
Utility.java
- encryptPassword()
- calculateSalary()
- sendEmail()
```

---

# 2. Logical Cohesion

Related logically but controlled by conditions/flags.

```text
process(inputType)
```

Handles multiple input types in same module.

---

# 3. Temporal Cohesion

Tasks grouped because they occur at same time.

```text
initializeLogger()
initializeCache()
initializeDatabase()
```

---

# 4. Procedural Cohesion

Grouped because execution order matters.

```text
validateInput()
calculate()
printResult()
```

---

# 5. Communicational Cohesion

Operations use same data.

```text
fetchUser()
updateUser()
deleteUser()
```

---

# 6. Sequential Cohesion

Output of one part becomes input of next.

```text
tokenize()
parseTokens()
generateAST()
```

---

# 7. Functional Cohesion (Best)

Everything contributes to one single task.

```text
calculateTax()
```

---

# Cohesion Hierarchy

```text
Coincidental
→ Logical
→ Temporal
→ Procedural
→ Communicational
→ Sequential
→ Functional
```

Higher is better.

---

# Cohesion vs Coupling

| Cohesion | Coupling |
|---|---|
| Inside module | Between modules |
| Internal relatedness | Dependency between modules |
| Prefer High | Prefer Low |

---

# Important Insight

High cohesion creates:
- focused modules
- cleaner architecture
- easier maintenance
- better scalability
