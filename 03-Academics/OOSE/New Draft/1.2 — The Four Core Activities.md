# 1.2 — The Four Core Activities

Every software process model is built around four core activities:
1. Specification
2. Design
3. Validation
4. Evolution

---

# 1. Specification

Defines:
> What the system should do.

## Includes
- requirements gathering
- requirement analysis
- constraints

## Example
- User can login
- User can place orders

---

# 2. Design

Defines:
> How the system will be built.

## Includes
- architecture
- database design
- API design
- UI structure

## Example
- choosing backend structure
- designing database schema

---

# 3. Validation

Checks:
> Whether the system works correctly.

## Includes
- testing
- debugging
- reviews
- verification

## Example
- testing login
- checking payment flow

---

# 4. Evolution

Software changes after deployment.

## Includes
- maintenance
- bug fixes
- feature additions
- scalability improvements

## Example
- adding dark mode
- adding new features later

---

# Important Insight

All software process models organize these same four activities differently.

---

# Key Point

Fixing problems earlier is cheaper:
- specification stage → cheap
- production stage → expensive
