# 3.2 — The Agile Manifesto

Created in 2001 as a response to rigid and process-heavy software development.

Focus:
- adaptability
- collaboration
- fast delivery
- continuous feedback

---

# The 4 Agile Values

## 1. Individuals and Interactions
over
Processes and Tools

People and communication are prioritized over rigid bureaucracy.

---

## 2. Working Software
over
Comprehensive Documentation

Main goal:
> deliver working software.

Documentation still matters, but should not become excessive.

---

## 3. Customer Collaboration
over
Contract Negotiation

Customers continuously interact with developers during development.

---

## 4. Responding to Change
over
Following a Plan

Plans are important, but software must adapt to changing requirements.

---

# Important Statement

> There is value in the items on the right, but more value in the items on the left.

Agile does NOT reject:
- planning
- tools
- documentation
- contracts

It changes priorities.

---

# Main Agile Principles

- early and continuous delivery
- embrace changing requirements
- frequent releases
- developer-customer collaboration
- sustainable development pace
- technical excellence
- simplicity
- self-organizing teams
- continuous improvement

---

# Agile Misconceptions

Agile does NOT mean:
- no planning
- no architecture
- no documentation
- chaos

Agile means:
> adaptive and continuous planning.

---

# Traditional vs Agile

| Traditional | Agile |
|---|---|
| Heavy upfront planning | Incremental planning |
| Change resisted | Change embraced |
| Large releases | Frequent releases |
| Documentation-focused | Working software-focused |

---

# Important Insight

Agile changes the question from:
> "How do we prevent change?"

to:
> "How do we adapt to change safely?"

---

# Real Industry Relevance

Modern development commonly uses Agile-inspired practices:
- Scrum
- Kanban
- XP
- CI/CD
- iterative development
