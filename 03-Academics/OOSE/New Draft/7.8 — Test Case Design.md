# 7.8 — Test Case Design

Test Case Design:
> process of creating structured test scenarios to verify software behaviour.

A test case defines:
- input
- execution steps
- expected result

---

# Basic Test Case Structure

| Field | Meaning |
|---|---|
| Test Case ID | Unique identifier |
| Objective | What is being tested |
| Input | Test data |
| Steps | Execution process |
| Expected Result | Expected behaviour |
| Actual Result | Actual output |
| Status | Pass/Fail |

---

# Example

| Field | Value |
|---|---|
| Test Case ID | TC_LOGIN_01 |
| Objective | Verify valid login |
| Input | admin / 1234 |
| Expected Result | Login successful |

---

# Good Test Case Characteristics

- clear
- repeatable
- independent
- understandable
- traceable to requirements

---

# Positive Test Case

Tests valid behaviour.

Example:

```text
Correct username/password
→ Login success
```

---

# Negative Test Case

Tests invalid/error conditions.

Examples:

```text
Wrong password
Empty input
Invalid email
```

---

# Boundary Test Case

Tests edge values.

Example:

```text
Password length:
8–16 valid
```

Test:

```text
7
8
16
17
```

---

# Equivalence Class Testing

Inputs divided into groups.

Example:

```text
Age:
0–120 valid
```

Groups:

```text
<0
0–120
>120
```

Test representative values from each group.

---

# Decision Table Testing

Used when multiple conditions combine.

Example:

```text
Valid User?
Correct Password?
Account Active?
```

---

# State Transition Testing

Used for systems with states.

Examples:
- ATM
- order lifecycle
- login attempt limits

---

# Traceability

Test cases should map to:
> requirements/specifications

Ensures all requirements are tested.

---

# Test Coverage

Measures:
> how much functionality/code is tested

Higher coverage improves confidence,
but does not guarantee bug-free software.

---

# Common Mistakes

- testing only happy paths
- vague expected results
- duplicate test cases

---

# Important Insight

Good Test Case Design ensures:
> systematic, repeatable, and reliable testing
