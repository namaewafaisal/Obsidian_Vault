# 3.1 — Why Agile Exists

Agile was created because traditional plan-driven models failed in many real software projects.

---

# Problem With Plan-Driven Development

Traditional models assumed:
> Requirements can be fully known early and remain stable.

In reality:
- requirements change
- customers change their minds
- markets evolve
- new features appear during development

---

# Cost of Change Problem

In traditional models:
- early changes are cheap
- late changes are expensive

Because changes affect:
- design
- code
- testing
- documentation

---

# Waterfall Strategy

Waterfall tried to:
> prevent change

Using:
- heavy planning
- detailed documentation
- strict phase completion

---

# Agile Insight

Agile says:
> embrace change instead of preventing it.

---

# Agile Thinking

- short development cycles
- continuous feedback
- frequent releases
- adaptive planning

---

# Plan-Driven vs Agile

| Plan-Driven | Agile |
|---|---|
| Predict early | Adapt continuously |
| Heavy upfront planning | Incremental planning |
| Change is risky | Change is expected |
| Late feedback | Continuous feedback |

---

# Chaos Report

The Chaos Report showed many software projects:
- failed
- exceeded budget
- missed deadlines

Main causes:
- changing requirements
- poor communication
- unrealistic planning

---

# Important Clarification

Agile does NOT mean:
- no planning
- no documentation
- chaos

Agile means:
> planning continuously and adapting when needed.

---

# Historical Evolution

Waterfall
→ Incremental
→ RAD
→ Agile

---

# Important Insight

Software requirements are often discovered during development, not fully known at the beginning.
