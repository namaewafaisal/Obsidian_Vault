# 7.4 — Integration Testing

Integration Testing:
> tests interaction between multiple modules/components.

Goal:
> verify modules work correctly together.

---

# Example

```text
Frontend
→ AuthService
→ Database
```

Checks:
- communication
- data exchange
- interface compatibility

---

# Integration Testing vs Unit Testing

| Unit Testing | Integration Testing |
|---|---|
| Single component | Multiple components |
| Isolated | Interaction-focused |
| Uses mocks often | Uses real integrations more |
| Fast | Slower |

---

# Common Problems Found

- API contract mismatch
- database integration issues
- dependency failures
- communication bugs
- data format mismatch

---

# Integration Strategies

---

# 1. Big Bang Integration

All modules integrated together at once.

Advantages:
- simple initially

Disadvantages:
- difficult debugging
- hard fault isolation

---

# 2. Incremental Integration

Modules integrated gradually.

Preferred approach.

Types:
- Top-Down
- Bottom-Up
- Hybrid/Sandwich

---

# Top-Down Integration

Start with higher-level modules.

Lower modules replaced temporarily using:
> stubs

Example:

```text
fake PaymentService
```

---

# Bottom-Up Integration

Start with lower-level modules.

Higher modules replaced temporarily using:
> drivers

Example:

```text
fake controller calling repository
```

---

# API Integration Testing

Checks:
- request/response flow
- authentication
- status codes
- JSON structure

---

# Database Integration Testing

Checks:
- DB connectivity
- transactions
- persistence
- queries

---

# Important Insight

Integration Testing ensures:
> independently working modules collaborate correctly together
