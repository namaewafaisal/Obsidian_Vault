# 2.3 — RAD (Rapid Application Development)

A software process model focused on:
> very fast software development.

RAD emphasizes:
- rapid prototyping
- quick feedback
- fast delivery
- component reuse

---

# Core Idea

Build quickly,
show users early,
improve continuously.

---

# Main Characteristics

- rapid prototyping
- reusable components
- parallel development
- high customer involvement
- short development cycles

---

# Prototype

A prototype is:
> an early simplified version of the system.

Used for:
- feedback
- requirement validation
- improvement

---

# RAD Phases

1. Requirements Planning
2. User Design
3. Construction
4. Cutover

---

# 1. Requirements Planning

Basic requirements gathered quickly.

---

# 2. User Design

Users interact with:
- mockups
- prototypes
- early system versions

Feedback collected continuously.

---

# 3. Construction

Rapid coding and development.

Uses:
- reusable components
- parallel teams
- fast iterations

---

# 4. Cutover

Final activities:
- testing
- deployment
- data conversion
- training

---

# Advantages

- very fast development
- early customer feedback
- flexible to changes
- reusable components reduce effort
- early visibility of software

---

# Disadvantages

- requires skilled developers
- weak architecture possible
- difficult for very large systems
- depends heavily on customer participation

---

# Suitable For

- business applications
- prototypes
- UI-heavy systems
- short-deadline projects

---

# Not Suitable For

- safety-critical systems
- highly complex systems

---

# Important Insight

RAD prioritizes:
> speed and feedback over perfect architecture.

This is both its strength and weakness.
