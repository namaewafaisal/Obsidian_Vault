## LC 154. Find Minimum in Rotated Sorted Array II

### Problem (Statement)

Given a **rotated sorted array** that **may contain duplicates**, find the **minimum element**.

Constraints:
- Array was originally sorted in ascending order
- Rotated unknown number of times
- Duplicates are allowed

---

### Key Observation

> Duplicates **break the strict ordering** used in LC 153.

When:
```
nums[mid] == nums[right]
```
we **cannot determine** which side contains the minimum.

---

### Core Idea (Ambiguous Binary Search)

Use the same logic as LC 153 **except one case**:

- If `nums[mid] > nums[right]`  
  → minimum is in right half
- If `nums[mid] < nums[right]`  
  → minimum is in left half (including mid)
- If `nums[mid] == nums[right]`  
  → **shrink search space safely**

Key rule:
> When equal, decrement `right` by 1 (discard duplicate safely)

---

### Why Shrinking Works

- If `nums[right]` equals `nums[mid]`, it **cannot be the unique minimum**
- Removing it does **not eliminate the true minimum**
- Worst case becomes `O(n)` when all values are same

---

### Algorithm Overview

1. Initialize `left = 0`, `right = n - 1`
2. While `left < right`:
   - Compute `mid`
   - Compare `nums[mid]` with `nums[right]`
   - Handle equality by shrinking `right`
3. Return `nums[left]`

Worst-case Time: `O(n)`  
Average Time: `O(log n)`  
Space: `O(1)`

---

### Final Code (Java)

```java
class Solution {
    public int findMin(int[] nums) {
        int left = 0, right = nums.length - 1;

        while (left < right) {
            int mid = left + (right - left) / 2;

            if (nums[mid] > nums[right]) {
                left = mid + 1;
            } else if (nums[mid] < nums[right]) {
                right = mid;
            } else {
                right--; // eliminate duplicate safely
            }
        }
        return nums[left];
    }
}
```

---

### Common Mistakes

- Applying LC 153 logic directly (fails with duplicates)
- Shrinking both `left` and `right`
- Returning early when `nums[mid] == nums[right]`
- Forgetting worst-case `O(n)` behavior
