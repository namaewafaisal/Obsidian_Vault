## LC 150. Evaluate Reverse Polish Notation

### Problem (Statement)

Given an array of strings `tokens` representing an arithmetic expression in  
**Reverse Polish Notation (RPN)**, evaluate the expression and return the result.

Valid operators:
```
+ - * /
```

Rules:
- Operators always come **after** their operands
- Division truncates toward zero
- The expression is always valid

---

### Input / Output

**Input**
```
tokens = ["2","1","+","3","*"]
```

**Output**
```
9
```

Explanation:
```
(2 + 1) * 3 = 9
```

---

### Key Invariant

> **An operator consumes the previous two numbers and produces one number.**

This reduces the expression step by step.

---

### Thinking Log (Actual Evolution of Thought)

#### Initial Recognition

> *“This is Reverse Polish Notation, so order is implicit.”*

Correct:
- No parentheses
- No precedence rules
- Evaluation is purely sequential

---

#### Data Structure Choice

> *“Stack is used for this.”*

Correct:
- RPN evaluation is **Last In, First Out**
- The most recent operands are used first

---

#### Operator Handling Logic

> *“Whenever I see an operator, I pop two values, apply the operation, and push the result back.”*

Important clarification discovered:
- First pop → **right operand**
- Second pop → **left operand**

So:
```
a op b   (NOT b op a)
````

This matters for `-` and `/`.

---

#### Confusion Raised (Important Learning)

> *“How do I convert the evaluated value back to string to store in the stack?”*

Correction:
- There is **no need** to convert back to string
- The stack should store **integers**, not strings

This clarified the separation between:
- **Parsing phase** (strings → integers)
- **Evaluation phase** (integer arithmetic only)

---

### Important Note (String → Integer Conversion)

Tokens are provided as strings, but:

- **Only operands need parsing**
- Operators stay as strings for branching
- Evaluated results remain integers

Correct approach:
```java
stack.push(Integer.parseInt(token)); // only once
```

Incorrect approach (unnecessary):

```java
stack.push(String.valueOf(eval)); // avoid this
```

Key takeaway:

> **Parse once. Compute using native types. Do not convert back unless required.**

---

### Implementation Strategy

1. Create a `Stack<Integer>`
2. Iterate through each token:

   * If token is an operator:

     * pop two values
     * evaluate
     * push result
   * Else:

     * parse integer and push
3. Final stack value is the result

---

### Final Code (Java)

```java
class Solution {
    public int evalRPN(String[] tokens) {
        Stack<Integer> stack = new Stack<>();

        for (String s : tokens) {
            if (s.equals("+") || s.equals("-") || s.equals("*") || s.equals("/")) {
                int b = stack.pop();
                int a = stack.pop();
                int eval = 0;

                switch (s) {
                    case "+":
                        eval = a + b;
                        break;
                    case "-":
                        eval = a - b;
                        break;
                    case "*":
                        eval = a * b;
                        break;
                    case "/":
                        eval = a / b;
                        break;
                }

                stack.push(eval);
            } else {
                stack.push(Integer.parseInt(s));
            }
        }

        return stack.peek();
    }
}
```

### Why This Solution Is Optimal

* Single pass
* Stack perfectly models RPN behavior
* No unnecessary conversions
* Clean separation of parsing and evaluation

This is the **canonical solution**.

---

### Transferable Insight

This pattern applies to:

* Expression evaluators
* Compilers / interpreters (basic)
* Stack-based machines
* Postfix / Prefix expression problems

Whenever the rule is:

> *“Operators act on the most recent operands”*

→ **Use a stack.**
