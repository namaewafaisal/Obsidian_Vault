# 1909. Remove One Element to Make the Array Strictly Increasing

## Problem (LeetCode Statement)

**Input:**
- `int[] nums` — 0-indexed integer array

**Output:**
- `true` if removing exactly one element makes the array strictly increasing, `false` otherwise

**Task:**
Check if one removal can make the array strictly increasing. Already strictly increasing arrays return true.

---

## Constraints

- `2 <= nums.length <= 1000`
- `1 <= nums[i] <= 1000`
- Only one removal allowed

---

## Examples
```
Input:  nums = [1,2,10,5,7]
Output: true  (remove 10 at index 2 → [1,2,5,7])
```
```
Input:  nums = [2,3,1,2]
Output: false  (no single removal produces strictly increasing)
```
```
Input:  nums = [1,1,1]
Output: false
```

---

## What Actually Matters

- Only one removal allowed — second violation always means false
- When a violation is found, only two candidates to remove: index `i` or index `i-1`
- Local neighbor check is sufficient — if removing an index fixes its immediate neighbors, the rest was already increasing
- O(n) is achievable — no need to re-scan the full array after removal

---

## Core Insight

> At the first violation, try removing either element locally using neighbor check. If neither works, or a second violation appears, return false.

---

## Invariant / Mental Model

> Everything to the left of the first violation is already strictly increasing. So fixing the violation locally (checking just the neighbors of the removed index) is enough — no need to re-verify the whole array.

---

## Thinking Log (Evolution of the Solution)

- **Initial Thought:** Track violations with a count — on first violation try removing left or right index locally
- **Attempted:** O(n²) full re-scan helper after each removal
- **Optimization:** Local neighbor check `nums[ind-1] < nums[ind+1]` is sufficient — left side is already valid, only the join point matters
- **Edge cases:** If `ind-1 < 0` or `ind+1 >= length`, removal is automatically valid (no neighbor on that side to violate)
- **Final Realization:** `count` flag ensures second violation immediately returns false — clean O(n) single pass

---

## Algorithm (High Level)

1. Walk array comparing `nums[i]` and `nums[i+1]`
2. On violation: if `count > 0` and local removal of `i` or `i+1` is valid → decrement count
3. If `count == 0` or neither removal works → set flag false
4. Return flag

---

## Code (Reference Only)
```java
class Solution {
    public boolean canBeIncreasing(int[] nums) {
        boolean flag = true;
        int count = 1;
        for (int i = 0; i < nums.length - 1; i++) {
            if (nums[i] >= nums[i + 1]) {
                if (count > 0 && (isIncreasing(nums, i) || isIncreasing(nums, i + 1))) {
                    count--;
                } else {
                    flag = false;
                }
            }
        }
        return flag;
    }

    public boolean isIncreasing(int[] nums, int ind) {
        if (ind - 1 < 0 || ind + 1 >= nums.length) return true;
        return nums[ind - 1] < nums[ind + 1];
    }
}
```

---

## Edge Cases to Recall

- Already strictly increasing → no violation found → return true
- Violation at index 0 → `ind-1 < 0` → removal always valid locally
- Violation at last index → `ind+1 >= length` → removal always valid locally
- Two violations → count exhausted → return false

---

## One-Line Recall

> On first violation try removing left or right locally via neighbor check — second violation or failed removal returns false.
