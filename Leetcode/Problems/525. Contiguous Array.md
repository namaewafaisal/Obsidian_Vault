## LC 525. Contiguous Array

### Problem (Statement)

Given a **binary array** `nums`, return the **maximum length of a contiguous subarray** that contains an **equal number of 0s and 1s**.

---

### Input / Output

**Input**
```
nums = [0,1,0]
```

**Output**
```
2
```

---

### Constraints

- `1 <= nums.length <= 10^5`
- `nums[i]` is either `0` or `1`
- Array length can be large → solution must be **O(n)**

---

### Examples

**Example 1**
```
Input:  nums = [0,1]
Output: 2
Explanation: The entire array has equal number of 0s and 1s.
```

**Example 2**
```
Input:  nums = [0,1,0]
Output: 2
Explanation: Either [0,1] or [1,0].
```

**Example 3**
```
Input:  nums = [0,0,1,0,0,0,1,1]
Output: 6
Explanation: Subarray [1,0,0,0,1,1].
```

---

### Key Reframing (Critical Insight)

> “Equal number of 0s and 1s” is equivalent to **net balance = 0**.

Transform the array by mapping:
```
1 → +1
0 → -1
```

After transformation:
> The task becomes finding the **longest subarray with sum = 0**.

This reframing is the core breakthrough of the problem.

---

### Core Idea (Prefix Sum Invariant)

Let:
```
prefixSum[i] = sum of values from index 0 to i
```

Invariant:
> If the **same prefix sum occurs at two different indices**,  
> then the subarray between them has sum `0`.

Why:
```
prefix[j] − prefix[i] = 0
```

So the problem reduces to:
> **Find the maximum distance between two equal prefix sums.**

---

### Why a HashMap Is Required

We store:
```
prefixSum → earliest index where it occurred
```

Why earliest?
- Earlier index gives a **longer subarray**
- Later occurrences must not overwrite earlier ones

---

### Mandatory Initialization (Easy to Miss)

Before iteration:
```
map.put(0, -1)
```

Why this is mandatory:
- Handles subarrays that start at index `0`
- If prefix sum becomes `0` at index `i`, length = `i - (-1) = i + 1`

Without this line, valid answers are missed.

---

### Thinking Log (Actual Evolution)

#### Initial intuition (my thinking)

> I need equal number of 0s and 1s, so maybe I can count them in subarrays.

#### Why this fails

- Checking all subarrays is `O(n²)`
- Repeated counting is inefficient

#### Breakthrough

> If I treat `0` as `-1`, then equal 0s and 1s cancel out.

From here, prefix-sum logic naturally applies.

---

### Algorithm Overview

1. Initialize:
   - `sum = 0`
   - `longest = 0`
   - HashMap with `{0 → -1}`
2. Traverse the array:
   - Add `+1` for `1`
   - Add `-1` for `0`
3. If current sum exists in map:
   - Update `longest`
4. Else:
   - Store sum with current index
5. Return `longest`

---

### Final Code (Java — My Version)

```java
class Solution {
    public int findMaxLength(int[] nums) {
        Map<Integer, Integer> map = new HashMap<>();
        int sum = 0;
        int longest = 0;

        // prefix sum 0 seen before array starts
        map.put(0, -1);

        for (int i = 0; i < nums.length; i++) {
            sum += nums[i] == 1 ? 1 : -1;

            if (map.containsKey(sum)) {
                longest = Math.max(longest, i - map.get(sum));
            } else {
                map.put(sum, i);
            }
        }
        return longest;
    }
}
```

### Common Mistakes

- Forgetting to convert `0 → -1`
- Forgetting `map.put(0, -1)`
- Overwriting an existing prefix sum index
- Treating this as a sliding window problem
