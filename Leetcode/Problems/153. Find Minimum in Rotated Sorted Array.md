## LC 153. Find Minimum in Rotated Sorted Array

### Problem (Statement)

Given a **rotated sorted array** of **unique** integers, find the **minimum element**.

Constraints:
- Array was originally sorted in ascending order
- Rotated between `1` and `n` times
- Must run in `O(log n)` time

---

### Key Observation

> A rotated sorted array consists of **two sorted parts**, and the minimum lies at the **rotation pivot**.

The array is **not globally sorted**, but it is **locally monotonic**.

---

### Core Idea (Binary Search Invariant)

Compare `nums[mid]` with `nums[right]`:

- If `nums[mid] > nums[right]`  
  → minimum lies in the **right half**
- Else  
  → minimum lies in the **left half (including mid)**

Invariant:
> The minimum is always inside the current search range.

---

### Why This Works

- Rightmost element belongs to the **smaller sorted segment**
- If `mid` is greater than `right`, pivot is to the right
- Otherwise, the minimum is at `mid` or to the left

---

### Algorithm Overview

1. Initialize `left = 0`, `right = n - 1`
2. While `left < right`:
   - Compute `mid`
   - Compare `nums[mid]` with `nums[right]`
3. Shrink range toward the minimum
4. Return `nums[left]`

Time: `O(log n)`  
Space: `O(1)`

---

### Final Code (Java)

```java
class Solution {
    public int findMin(int[] nums) {
        int left = 0, right = nums.length - 1;

        while (left < right) {
            int mid = left + (right - left) / 2;

            if (nums[mid] > nums[right]) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }
        return nums[left];
    }
}
```

---

### Common Mistakes

- Comparing with `nums[left]` instead of `nums[right]`
- Using `<=` incorrectly
- Forgetting that the array has **no duplicates**
- Returning `nums[mid]` prematurely

---

### One-Sentence Recall

> In a rotated sorted array without duplicates, compare mid with right to binary-search the rotation pivot.
