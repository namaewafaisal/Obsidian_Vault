## LC 438. Find All Anagrams in a String

| **Metric**     | **Value**                              |
| -------------- | -------------------------------------- |
| **Date**       | December 30, 2025                      |
| **Time Taken** | ~45 minutes                            |
| **Difficulty** | Medium                                 |
| **Pattern**    | Sliding Window (Fixed Size) + Hash Map |

---

### Problem (summary)

Given two strings `s` and `p`, return an array of all the start indices of `p`'s **anagrams** in `s`. An anagram is a word formed by rearranging the letters of another word, typically using all the original letters exactly once.

---

### Key Invariant

* **Window Size:** An anagram must be exactly the same length as `p`. Therefore, the window  must always equal `p.length()`.
* **The "Satisfied" Counter:** Instead of comparing maps repeatedly (which is  per move), we only track how many unique characters in the current window meet the frequency requirement of `p`.

---

### Thinking Log (Evolution of the Solution)

* **Initial Observation:** Anagrams have the same character counts. A sliding window is needed to check all substrings of length `n`.
* **The "127" Trap:** Discovered that using `==` to compare `Integer` objects from the Maps fails for counts larger than 127 because Java only caches small integers.
* *Correction:* Always use `.equals()` when comparing values retrieved from a `HashMap<Character, Integer>`.


* **Window Logic Shift:** Started with a variable-sized window that shrunk based on character content.
* *Realization:* This made state management (the `satisfied` counter) extremely complex. Switching to a **Fixed-Size Window** () simplified the logic significantly.


* **The State Transition Bug:** Fixed an issue where `satisfied` wasn't decrementing correctly.
* *Fix:* `satisfied` should only decrease if the count was *exactly* what was required and is now dropping below that requirement.


* **Final Optimization Path:** Recognized that while `HashMap` is functional, using an `int[26]` array would drastically reduce overhead and improve runtime.

---

### Implementation Strategy

1. Pre-count characters in `p` using a Map (`pMap`) and store its size as `required`.
2. Slide the `right` pointer to add characters to the `sMap`.
3. If the count of a character in `sMap` matches its count in `pMap`, increment `satisfied`.
4. **Window Constraint:** If the window size exceeds `p.length()`, remove the character at `left`:
* If that character's count was exactly meeting the requirement, decrement `satisfied`.
* Update the map and increment `left`.


5. If `satisfied == required`, add `left` to the result list.

---

### Final Code (Java)

```java
class Solution {
    public List<Integer> findAnagrams(String s, String p) {
        int left = 0;
        int right = 0;
        List<Integer> result = new ArrayList<>();

        Map<Character, Integer> sMap = new HashMap<>();
        Map<Character, Integer> pMap = new HashMap<>();

        int m = s.length();
        int n = p.length();

        for (int i = 0; i < n; i++) {
            char curr = p.charAt(i);
            pMap.put(curr, pMap.getOrDefault(curr, 0) + 1);
        }
        
        int required = pMap.size();
        int satisfied = 0;

        while (right < m) {
            char curr = s.charAt(right);
            sMap.put(curr, sMap.getOrDefault(curr, 0) + 1);
            
            // Check if adding this character completes a requirement
            if (pMap.containsKey(curr) && sMap.get(curr).equals(pMap.get(curr))) {
                satisfied++;
            }

            // Maintain fixed window size by shrinking from left
            while (right - left + 1 > n) {
                char chl = s.charAt(left);
                // If the character being removed was satisfying a requirement, decrement
                if (pMap.containsKey(chl) && pMap.get(chl).equals(sMap.get(chl))) {
                    satisfied--;
                }
                sMap.put(chl, sMap.get(chl) - 1);
                left++;
            }
            
            // If all character requirements are met, we found an anagram
            if (satisfied == required) {
                result.add(left);
            }

            right++;
        }
        return result;
    }
}

```

### Complexity Analysis

| Metric | Complexity | Reason |
| --- | --- | --- |
| **Time** | O(m + n) | Each character in `s` and `p` is processed once. |
| **Space** | O(K) | Where K is the number of unique characters (max 26 for English letters). |
