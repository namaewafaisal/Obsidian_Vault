## LC 435. Non-overlapping Intervals

| **Metric**     | **Value**                    |
| -------------- | ---------------------------- |
| **Date**       | December 27, 2025            |
| **Time Taken** | 12 minutes                   |
| **Difficulty** | Medium                       |
| **Pattern**    | Greedy / Interval Scheduling |

---

### Problem (summary)

Given an array of intervals, find the **minimum number** of intervals you need to remove to make the rest of the intervals non-overlapping. Intervals that touch at a single point are considered non-overlapping.

---

### Example

Input: `intervals = [[1,2],[2,3],[3,4],[1,3]]`

Output: `1`

Explanation: Removing `[1,3]` makes the rest non-overlapping.

---

### Pattern Classification

* **Greedy:** Local optimal choice (choosing the earliest end time) leads to the global maximum of non-overlapping intervals.
* **Interval Scheduling:** Maximizing the "kept" intervals is mathematically equivalent to minimizing "removals."

---

### Key Invariant

* To leave the most "empty space" for future intervals, always prioritize keeping the interval that **finishes earliest**.
* By sorting by `end` time, the first interval that doesn't overlap with the previous selection is guaranteed to be the most optimal greedy choice.

---

### Thinking Log (Evolution of the Solution)

* **User Idea:** Should I find which interval overlaps more times and remove that? Or check if the right one overlaps with its own right?
* **AI Response:** Looking ahead is O(n²) and complex. You need a "proxy" to predict future overlaps without seeing them.
* **User Insight:** I'll keep the smaller duration interval ().
* **AI Response:** Duration is a trap. A "long" interval that ends at 10 is safer than a "short" one that ends at 11, because only the **end time** restricts future options.
* **User Insight:** So I check and remove the maximum of the ends.
* **AI Response:** Exactly. When two overlap, "discard" the space-hog (the one ending later) to clear the path.
* **User Realization:** If I sort by end time, I finish the earliest things first and don't even have to manually decide which one to "remove" during a collision—I just skip the ones that don't fit.

---

### Implementation Strategy

1. **Sort** the intervals based on their **end times** ().
2. Initialize `lastEnd` to `Integer.MIN_VALUE` and `count` to the total number of intervals.
3. Iterate through the sorted intervals:
* If an interval starts after or at the current `lastEnd`, it is valid.
* Update `lastEnd` to this interval's end and **decrement** the removal count (since we are "keeping" it).


4. Return the remaining `count`.

---

### Code

```java
class Solution {
    public int eraseOverlapIntervals(int[][] intervals) {
        // Sort by end time to finish tasks as early as possible
        Arrays.sort(intervals, (a,b) -> Integer.compare(a[1],b[1]));
        
        int count = intervals.length;
        int lastEnd = Integer.MIN_VALUE;

        for(int[] curr : intervals) {
            // If the current interval starts after the last one ended, we keep it
            if(curr[0] >= lastEnd) {
                lastEnd = curr[1];
                // Since we start with 'count' as total, each kept interval reduces removals
                count--;
            }
        }
        return count;
    }
}

```
