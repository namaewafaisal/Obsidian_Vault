## LC 334. Increasing Triplet Subsequence

### Problem (Statement)

Given an integer array `nums`, return `true` if there exists a **strictly increasing subsequence of length 3**.

That is, find indices `i < j < k` such that:
```
nums[i] < nums[j] < nums[k]
```

Otherwise, return `false`.

Constraints:
- Subsequence is **not required to be contiguous**
- Only existence matters, not the actual subsequence
- `nums.length` can be large → brute force is not feasible

---

### Key Observation

> We do **not** need to find the triplet — only to know **whether one can exist**.

This allows us to track **possibility**, not an actual sequence.

---

### Core Idea (Greedy Invariant)

Maintain two values while scanning the array:

- `first`  → smallest value seen so far
- `second` → smallest value seen so far that is **greater than some earlier `first`**

Invariant:
> At any time, `first` is the best possible start, and `second` represents the existence of a valid increasing pair in the past.

If we ever find a value greater than `second`, a triplet must exist.

---

### Thinking Log (Mandatory)

#### Initial confusion (your words, summarized)

> I thought of counting increasing numbers or using a stack, but both fail because the subsequence is not contiguous and values can reset.  
> Updating the first value seemed to break the logic for the second.

---

#### Resolution / insight

- Updating `first` does **not** invalidate `second`
- `second` only means:
  > “There exists *some* earlier index where `first < second`”
- Once such a pair exists, finding any value greater than `second` completes a triplet

The algorithm tracks **historical feasibility**, not a concrete sequence.

---

### Why `<=` Is Used Instead of `<` (Important Detail)

```java
if (i <= first) {
    first = i;
}
else if (i <= second) {
    second = i;
}
```

Reason:

> We must **prevent duplicates from falsely advancing the sequence**.

Using `<=` ensures:
- Equal values **replace** `first` or `second`
- They do **not** move us closer to forming a triplet

Example:
```
[1, 1, 2]
```

If `<` were used:
- `first = 1`
- `second = 1` (wrong)
- `2 > second` → falsely returns true

Using `<=` avoids this by keeping:
```
first = 1, second = 2
```
(no triplet yet)

So:
> `<=` maintains strictness of the final comparison.

---

### Algorithm Overview

1. Initialize:
   - `first = +∞`
   - `second = +∞`
2. Traverse the array:
   - If current ≤ `first` → update `first`
   - Else if current ≤ `second` → update `second`
   - Else → current > `second` → triplet exists
3. If traversal ends → return `false`

Time: `O(n)`  
Space: `O(1)`

---

### Final Code (Java)

```java
class Solution {
    public boolean increasingTriplet(int[] nums) {
        int first = Integer.MAX_VALUE;
        int second = Integer.MAX_VALUE;

        for (int i : nums) {
            if (i <= first) {
                first = i;
            } else if (i <= second) {
                second = i;
            } else {
                return true;
            }
        }
        return false;
    }
}
```

### Common Mistakes

- Using `<` instead of `<=`
- Trying to build the actual subsequence
- Using DP or stacks unnecessarily
- Assuming contiguous increase is required
