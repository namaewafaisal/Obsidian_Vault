## LC 48. Rotate Image

### Problem (Statement)

Given an `n x n` **square matrix**, rotate the image **90 degrees clockwise**, **in place**.

Constraints:
- Must modify the original matrix
- No extra matrix allowed
- Exactly 90° clockwise rotation

---

### Input / Output

**Input**
```
[
  [1, 2, 3],
  [4, 5, 6],
  [7, 8, 9]
]
```

**Output**
```
[
  [7, 4, 1],
  [8, 5, 2],
  [9, 6, 3]
]
```

---

### Key Invariant

> **Rotation is an index mapping problem, not a traversal problem.**

For any cell `(r, c)` in an `n x n` matrix:
```
(r, c) → (c, n - 1 - r)
```

Applying this mapping **four times** returns to the original position  
→ elements move in **4-cycles**.

---

### Thinking Log (Actual Evolution, Mistakes Included)

#### Initial Intuition (Correct but Hard to Execute)

> *“I can traverse like spiral and move each value to its next position.”*

Why this became difficult:
- Spiral traversal is about **visiting**
- Rotation is about **transforming**
- Trying to “move values step by step” caused confusion and fatigue

---

#### ❌ Mistake #1 — Thinking in terms of traversal

> *“Each element swaps to the next and next… boundary stuff.”*

Why this failed:
- Elements don’t move sequentially
- Each element belongs to a **fixed 4-cycle**
- Traversal logic creates unnecessary state

**Correction:**  
Stop thinking in terms of walking the matrix.

---

#### ❌ Mistake #2 — Trying to rotate one cell repeatedly

> *“Loop 4 times and keep swapping.”*

Why this failed:
- `r` and `c` didn’t change
- Same cell was rotated 4 times
- No notion of layer or offset

**Correction:**  
Rotation must be done **per layer, per offset**, not per cell.

---

#### ❌ Mistake #3 — Not separating layers and offsets

> *“I know there are corners and sides, but I can’t write it.”*

Why this happened:
- Missing the concept of:
  - **layer** (outer square, inner square)
  - **offset** (position within that layer)

**Correction:**  
Explicitly define:
```
first = layer
last  = n - 1 - layer
offset = i - first
```

---

#### Key Breakthrough

> *“For each position, it can have 4 sides or no movement needed.”*

This was the correct realization:
- Each element is part of **exactly one 4-cycle**
- Center element (odd `n`) does not move
- Layers collapse inward

---

### Correct Mental Model (Must Relearn)

- Process the matrix **layer by layer**
- For each layer:
  - iterate along the top edge
  - rotate **4 corresponding positions**
- Use **one temp variable**
- Never traverse the whole matrix
- Never use extra space

---

### Final Correct Code (Java)

```java
class Solution {
    public void rotate(int[][] matrix) {
        int n = matrix.length;

        for (int layer = 0; layer < n / 2; layer++) {
            int first = layer;
            int last = n - 1 - layer;

            for (int i = first; i < last; i++) {
                int offset = i - first;

                int top = matrix[first][i];

                matrix[first][i] = matrix[last - offset][first];
                matrix[last - offset][first] = matrix[last][last - offset];
                matrix[last][last - offset] = matrix[i][last];
                matrix[i][last] = top;
            }
        }
    }
}
```
