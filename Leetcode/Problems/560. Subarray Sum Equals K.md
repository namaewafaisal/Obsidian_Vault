## Problem (summary)

Given an integer array `nums` and an integer `k`, return the **total number of continuous subarrays** whose sum equals `k`.

* Subarrays must be **contiguous**
* Numbers may include **negatives and zeros**

---

## Example

**Input:**
`nums = [3, 4, -7, 1, 3, 3, 1, -4]`, `k = 7`

**Output:**
`4`

---

## Pattern Classification

* Prefix Sum
* HashMap (Frequency Counting)
* Non-monotonic Subarray Problem

---

## Key Invariant

At index `i`:

```
Sum(j+1 → i) = prefixSum[i] - prefixSum[j]
```

To satisfy:

```
prefixSum[i] - prefixSum[j] = k
⇒ prefixSum[j] = prefixSum[i] - k
```

---

## Why Sliding Window Fails

* Sliding window requires **monotonic behavior**
* Negative numbers break monotonicity
* No valid expand / shrink invariant exists
* Greedy window logic becomes incorrect

---

## Core Insight

Instead of controlling a window:

* **Count how many valid starting points already exist**
* Use prefix sums to represent all past states

---

## HashMap Meaning

```
map[prefixSum] = frequency
```

Interpretation:

> How many times this prefix sum has appeared **before** the current index

Each occurrence represents a **distinct subarray start**.

---

## Thinking Log (Evolution of the Solution)

### Initial Thought

* Use sliding window to expand/shrink until sum = k

### Correction

* Negative numbers invalidate sliding window invariants

### Brute Force

* Try all subarrays using nested loops

### Correction

* Time complexity O(n²) → too slow

### The Insight

* Subarray sum can be expressed using prefix sums
* Instead of searching starts explicitly, **count them**

---

## Implementation Strategy

1. Initialize:

   * `prefixSum = 0`
   * `map = {0 : 1}`
   * `count = 0`

2. Traverse array:

   * Update prefix sum
   * Look for `prefixSum - k` in map
   * Add its frequency to count
   * Update map with current prefix sum

---

## Why `{0 : 1}` Is Mandatory

* Represents prefix sum **before index 0**
* Enables subarrays that start at index `0`
* Without it, valid subarrays are missed

---

## Why Frequency Is Added (Not +1)

If:

```
map[prefixSum - k] = f
```

Then:

* There are `f` different starting indices
* All produce valid subarrays ending at current index

So:

```
count += f
```

---

## Order Dependency (Critical)

* **Check map first**
* **Update map after**

Reason:

* Prevents counting empty subarrays
* Ensures only past prefix sums are used

---
## Code
```java
class Solution {
    public int subarraySum(int[] nums, int k) {
        Map<Integer, Integer> freq = new HashMap<>();
        int count = 0;
        int currSum = 0;
        freq.put(0,1);
        for(int i = 0; i<nums.length; i++){
            currSum += nums[i];
            int key = currSum - k;
            //if(freq.get(key))
            count += freq.containsKey(key) ? freq.get(key) : 0;
            freq.put(currSum, freq.getOrDefault(currSum,0)+1);
        
        }
        return count;
    }
}
```
