## LC 141. Linked List Cycle

### Problem (Statement)

Given the head of a **singly linked list**, determine if the list contains a **cycle**.

A cycle exists if:
- while traversing the list, you encounter the **same node again**
- traversal would never reach `null`

---

### Input / Output

**Input**
```
head = [3,2,0,-4], pos = 1
```

**Output**
```
true
````

(`pos` indicates the node where the tail connects, but is **not given** in the function.)

### Key Invariant

> **A cycle exists if and only if the same node reference is visited more than once.**

* Node **values do not matter**
* Only **node identity (address / reference)** matters

---

### Thinking Log (Evolution of the Solution)

#### Initial Thought

> *“These kinds of seeing the past or remembering if we passed it is lookup, and I mostly do it using hashmap.”*

This correctly identifies the problem as:

* a **visited-before** problem
* suitable for **hash-based lookup**

---

#### Early Misconception

> *“If the values are distinct, I can store them as keys.”*

**Correction:**

* Values are **not guaranteed to be distinct**
* Different nodes may share the same value
* Cycles are about **revisiting the same node**, not the same value

So the correct unit of storage is:

* the **node reference itself**

---

#### Clarification That Unlocked It

> *“Ohhh… addresses are the node references themselves.”*

In Java:

* `ListNode` objects are already references
* `HashSet<ListNode>` stores node identities directly

No extra mapping or index is required.

---

#### Final Mental Model

* Traverse the list node by node
* Store each **node reference** in a `HashSet`
* If the current node already exists in the set → cycle detected
* If traversal reaches `null` → no cycle

---

### Implementation Strategy

1. Create a `HashSet<ListNode>` to store visited nodes
2. Traverse the list using `head`
3. At each step:

   * If `head` is already in the set → return `true`
   * Otherwise, add it to the set
4. If traversal ends (`head == null`) → return `false`

---

### Final Code (Java)

```java
public class Solution {
    public boolean hasCycle(ListNode head) {
        Set<ListNode> seen = new HashSet<>();

        while (head != null) {
            if (seen.contains(head)) {
                return true;
            }
            seen.add(head);
            head = head.next;
        }

        return false;
    }
}
```

---

### Complexity Analysis

| Metric    | Complexity |
| --------- | ---------- |
| **Time**  | O(n)       |
| **Space** | O(n)       |

---

### Why This Solution Is Correct

* HashSet provides **O(1)** average lookup
* Node references uniquely identify positions in the list
* No modification of the list is required
* Terminates safely for both cyclic and non-cyclic lists

---

### Why HashSet (Not HashMap)

* Only **existence check** is required
* No associated value needed
* `HashSet` internally uses a `HashMap` anyway

---

### Transferable Insight

This “seen before” pattern applies to:

* Graph cycle detection
* Detecting repeated states
* Visited-node tracking in DFS/BFS

Whenever the question is:

> *“Have I been here before?”*

A hash-based lookup is a natural fit.
