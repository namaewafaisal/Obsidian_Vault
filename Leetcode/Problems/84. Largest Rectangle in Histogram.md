## LC 84. Largest Rectangle in Histogram

### Problem (Statement)

Given an array `heights` representing a histogram where:
- Each bar has width `1`
- Bars are adjacent
- Height of a rectangle is limited by the **shortest bar** in the chosen range

Return the **maximum rectangular area** that can be formed.

---

### Key Observation

> The largest rectangle is not determined by choosing a range, but by choosing a **bar as height** and finding how far it can extend **left and right** before a smaller bar blocks it.

This reframes the problem from **range-based** to **per-bar boundary-based**.

---

### Core Idea (Monotonic Stack Invariant)

> Each bar waits until a **smaller bar appears on its right**.  
> When that happens, its maximum rectangle is **finalized**.

We maintain a **monotonic increasing stack of indices**:
- Stack bottom → smaller heights
- Stack top → larger heights

This guarantees:
- Taller bars get finalized sooner
- Each bar is pushed once and popped once → `O(n)`

---

### Thinking Log (Mandatory)

#### My initial thinking (your words)

> This feels like Container With Most Water.  
>  
> I can take the full array and use the smallest height inside it to compute area.  
> Shrink left or right based on smaller height, similar to two pointers.  
>  
> To track the smallest bar inside a range, I thought of using a min heap with indices.  
>  
> Later I thought: for each index, I can expand left and right until a smaller bar appears.

---

#### Why this thinking breaks (correction)

- LC 84 is **not** like Container With Most Water:
  - In water container, only boundary bars matter
  - In histogram, **any internal bar** can limit height
- Sorting or using a heap destroys **contiguity**
- Expanding left/right per index causes **O(n²)** time
- The real question is not “what’s the smallest in this range?” but:
  
  > **For this bar, where are the first smaller bars on the left and right?**

---

#### Corrected mental model

> A bar’s **left boundary** is fixed when it is pushed into the stack.  
> A bar’s **right boundary** is fixed when it is popped from the stack.

Stack invariant:
- After popping taller bars, the stack top (if any) is the **nearest smaller bar on the left**
- Current index is the **first smaller bar on the right**

---

### Boundary Logic (The Heart of the Problem)

When popping a bar at index `hIndex`:

- `height = heights[hIndex]`
- `rightBoundary = currentIndex`
- `leftBoundary = stack.peek()` after pop, or `-1` if stack is empty

Width:
```
rightBoundary - leftBoundary - 1
```

Area:
```
height × width
```

The `-1` excludes the blocking smaller bar.

---

### Sentinel Trick (Critical Detail)

Bars that never encounter a smaller bar on the right must still be finalized.

Solution:
> Pretend a bar of height `0` exists at the end.

This forces all remaining bars in the stack to be popped and evaluated.

---

### Algorithm Overview

1. Traverse bars left → right
2. Maintain a monotonic increasing stack of indices
3. While current bar is smaller than stack top:
   - Pop stack top
   - Compute area using finalized boundaries
4. Push current index
5. Use a sentinel `0` height at the end to flush the stack

Time: `O(n)`  
Space: `O(n)` (stack)

---

### Final Code (Java)

```java
class Solution {
    public int largestRectangleArea(int[] heights) {
        Stack<Integer> stack = new Stack<>();
        int maxArea = 0;

        for (int i = 0; i <= heights.length; i++) {
            int currHeight = (i == heights.length) ? 0 : heights[i];

            while (!stack.isEmpty() && currHeight < heights[stack.peek()]) {
                int hIndex = stack.pop();
                int height = heights[hIndex];

                int rightBoundary = i;
                int leftBoundary = stack.isEmpty() ? -1 : stack.peek();

                int width = rightBoundary - leftBoundary - 1;
                maxArea = Math.max(maxArea, height * width);
            }
            stack.push(i);
        }
        return maxArea;
    }
}
```

### Common Mistakes

- Treating this like a two-pointer or sliding window problem
- Using sorting or heaps (breaks contiguity)
- Computing left boundary incorrectly (using index instead of stack top)
- Forgetting the sentinel `0`
- Assuming stack size has spatial meaning
