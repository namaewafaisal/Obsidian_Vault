## Problem (summary)

Given an array of `intervals` where `intervals[i] = [start, end]`, merge all overlapping intervals and return an array of the non-overlapping intervals that cover all the input intervals.

* Intervals are overlapping if `start_next <= end_current`.
* Input is not guaranteed to be sorted.

---

## Example

**Input:**
`intervals = [[1,3],[2,6],[8,10],[15,18]]`

**Output:**
`[[1,6],[8,10],[15,18]]`

---

## Pattern Classification

* Sorting (Custom Comparator)
* Linear Scan (Single Pass)
* Greedy (Local merging)

---

## Key Invariant

After sorting by start time:
For any two consecutive intervals `current` and `next`:

```
If next[start] <= current[end] 
=> Overlap exists.

```

The merged interval will be:
`[current[start], max(current[end], next[end])]`

---

## Why Sorting Is Required

* Without sorting, overlapping intervals can be anywhere in the input.
* Sorting transforms a global search for overlaps into a **local comparison** between adjacent elements.
* It guarantees that if `intervals[i]` doesn't overlap with `intervals[i+1]`, it cannot overlap with any `intervals[j]` where `j > i+1`.

---

## Core Insight

The start of a merged interval is always determined by the **first** interval in the sequence. The end is determined by the **maximum** end value encountered so far in that sequence of overlapping intervals.

---

## Thinking Log (Evolution of the Solution)

### Initial Thought

* Check `interval[i][end]` against `interval[i+1][start]`. If the difference is , they overlap.

### Correction

* Realized input like `[[4,7],[1,4]]` breaks this because it's unsorted.

### Brute Force Attempt

* Flatten everything into a 1D array and sort.

### Correction

* Flattening loses the pairing of start and end. If I have `[[1,4], [2,3]]`, a 1D sort gives `[1, 2, 3, 4]`, but doesn't tell me which numbers belonged together.

### The Insight

* Sort the 2D array based on the **first element** (start time) of each sub-array.
* Once sorted, I only need to track the "current" merging interval and compare it to the "next" one in a single pass.

---

## Implementation Strategy

1. **Sort:** Use `Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]))`.
2. **Initialize:** Create a `List<int[]>` to store results. Add the first interval to the list as a starting point.
3. **Traverse:** Iterate through the rest of the intervals:
* Get the `lastMerged` interval from the list.
* If `current[start] <= lastMerged[end]`: Update `lastMerged[end]` to `Math.max(lastMerged[end], current[end])`.
* Else: Add `current` as a new interval to the list.


4. **Convert:** Transform the `List<int[]>` back to `int[][]`.

---

## Data Structure Choice: `List<int[]>`

* **Why:** The number of merged intervals is unknown until the end.
* **Java Constraint:** Primitive arrays are fixed-length; a `List` allows dynamic growth.
* **Efficiency:** Storing `int[]` inside the list avoids the overhead of wrapping every single number in an `Integer` object.

---
## Code

```java
class Solution {
    public int[][] merge(int[][] intervals) {
        Arrays.sort(intervals, (a,b) -> Integer.compare(a[0],b[0]));

        List<int[]> result = new ArrayList<>();

        int[] current = intervals[0];

        for(int i = 1; i<intervals.length; i++) {
            int[] next = intervals[i];

            if(next[0] <= current[1]){
                current[1] = Math.max(current[1],next[1]);
            }
            else{
                result.add(current);
                current = next;
            }
        }
        result.add(current);
        return result.toArray(new int[result.size()][]);

    }
}
```
