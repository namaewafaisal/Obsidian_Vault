### Problem (Statement)

Given the heads of two **sorted singly linked lists** `list1` and `list2`,
merge the two lists into **one sorted list** and return its head.

- The new list must be made by **splicing together the nodes of the first two lists**
- No new nodes should be created

---

### Input / Output

**Input**
```

list1 = [1,2,4]
list2 = [1,3,4]

```

**Output**
```

[1,1,2,3,4,4]

````

### Key Invariant

> **The merged list grows only through `tail.next`.
> Reassigning pointers alone does NOT build the list.**

---

### Thinking Log (Actual Evolution of Thought)

#### Initial Idea (Correct Direction)

> *“I don’t create a new list. I just rearrange the links.”*

Correct:

* Reuse existing nodes
* Compare heads
* Advance pointers

This was the **right high-level idea**.

---

#### Confusion About `tail`

> *“What is tail here? If I don’t create a node, is tail the lesser value?”*

Clarification:

* `tail` is **not a new node**
* `tail` is a **pointer to the last node of the merged list**
* The merged list itself is built using **existing nodes**

---

#### Major Mistake #1 — Reassigning `tail` Instead of Linking

Buggy thinking:

```java
tail = list1;
```

Why this is wrong:

* This only moves the pointer
* It does NOT connect the node to the merged list
* The structure of the merged list does not change

Correction:

```java
tail.next = list1;
tail = tail.next;
```

---

#### Major Mistake #2 — Wrong Remainder Handling

Buggy prototype:

```java
while (list1 != null) {
    tail = list1;
    list1 = list1.next;
}
```

Why this is wrong:

* No `.next` assignment
* Nodes are never attached
* Loop does nothing structurally

Correction:

* Remaining nodes are already sorted
* Attach them in **one step**

```java
tail.next = list1; // or list2
```

---

#### Realization

> *“I actually had the correct solution structure but was far away.”*

Correction:

* You were **not far away**
* The mistake was **mechanical pointer discipline**
* The algorithm was already in your head

---

### Implementation Strategy (Final)

1. Handle null list edge cases
2. Pick the smaller head as the merged `head`
3. Maintain a `tail` pointer
4. While both lists have nodes:

   * attach the smaller node using `tail.next`
   * advance `tail`
5. Attach the remaining list in one step

---

### Final Correct Code (Java)

```java
class Solution {
    public ListNode mergeTwoLists(ListNode list1, ListNode list2) {
        if (list1 == null) return list2;
        if (list2 == null) return list1;

        ListNode head;
        if (list1.val <= list2.val) {
            head = list1;
            list1 = list1.next;
        } else {
            head = list2;
            list2 = list2.next;
        }

        ListNode tail = head;

        while (list1 != null && list2 != null) {
            if (list1.val <= list2.val) {
                tail.next = list1;
                list1 = list1.next;
            } else {
                tail.next = list2;
                list2 = list2.next;
            }
            tail = tail.next;
        }

        tail.next = (list1 != null) ? list1 : list2;
        return head;
    }
}
```

### Transferable Insight

This exact pointer invariant appears in:

* Reordering lists
* Merging k sorted lists
* Partitioning linked lists
* List-based merge sort

If you forget everything else, remember this:

> **Data structures grow through links, not variable reassignment.**
