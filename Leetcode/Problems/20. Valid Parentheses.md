### Problem (Statement)

Given a string `s` containing only the characters:

```

( ) { } [ ]

```

Determine if the input string is **valid**.

A string is valid if:
1. Every opening bracket has a corresponding closing bracket.
2. Brackets are closed in the **correct order**.
3. The closing bracket must match the **same type** of opening bracket.

---

### Input / Output

**Input**
```
s = "()[]{}"
```

**Output**
```
true
```

**Input**
```
s = "(]"
```

**Output**
```
false
````

### Key Invariant

> **The most recent opening bracket must be the first one to close.**

This is exactly **LIFO (Last In, First Out)** behavior.

---

### Thinking Log (Actual Evolution of Thought)

#### Initial Understanding

> *“I know that stack is used for this.”*

Correct:

* The problem is about **nested structure**
* Nested problems map naturally to a **stack**

---

#### Core Logic (My Words)

> *“Whenever it’s an opening bracket I push it.
> Whenever it’s a closing bracket then I check if the top of the stack is the matching opening bracket and if so then pop.”*

This captures the full logic:

* Opening → wait for closure
* Closing → must match the **latest** opening

---

#### Failure Conditions Identified

> *“When the string ends and stack not empty or closing and the opening in the top don’t match then it’s false else true.”*

Correct failure cases:

* Closing bracket with **empty stack**
* Mismatched bracket type
* Stack not empty at the end

---
### Data Structure Choice
- `Stack<Character>`
Why:

  * Needs ordered removal
  * Most recent opening must close first
  * No random access needed

---

### Java Syntax Used

```java
Stack<Character> stack = new Stack<>();
```

Operations:

* `push()` → opening bracket
* `peek()` → check match
* `pop()` → matched pair
* `isEmpty()` → safety check

---

### Important Clarification (Character vs char)

Concern raised:

> *“There is no unboxing error like Integer?”*

Clarification:

* `stack.peek()` returns a **Character**
* Comparing with `'{'`, `'('`, `'['` (primitive `char`)
* Java performs **safe auto-unboxing**
* This results in `char == char` comparison

So this is **safe**:

```java
stack.peek() == '{'
```

No reference comparison issue exists here.

---

### Final Code (Java)

```java
class Solution {
    public boolean isValid(String s) {
        Stack<Character> stack = new Stack<>();

        for (char c : s.toCharArray()) {
            if (c == '{' || c == '(' || c == '[') {
                stack.push(c);
            }
            else if (!stack.isEmpty() &&
                    ((c == '}' && stack.peek() == '{') ||
                     (c == ')' && stack.peek() == '(') ||
                     (c == ']' && stack.peek() == '['))) {
                stack.pop();
            }
            else {
                return false;
            }
        }
        return stack.isEmpty();
    }
}
```
