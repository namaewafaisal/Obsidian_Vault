# 210. Course Schedule II

## Problem (LeetCode Statement)

**Input:**
- `int numCourses` — number of courses labeled 0 to numCourses-1
- `int[][] prerequisites` — pairs where `[a,b]` means take b before a

**Output:**
- Valid ordering of courses to take, or empty array if impossible

**Task:**
Return a topological ordering of courses given their dependencies. If a cycle exists, return empty array.

---

## Constraints

- `1 <= numCourses <= 2000`
- `0 <= prerequisites.length <= 5000`
- No duplicate edges, no self-loops

---

## Examples
```
Input:  numCourses = 4, prerequisites = [[1,0],[2,0],[3,1],[3,2]]
Output: [0,2,1,3] or [0,1,2,3]
```
```
Input:  numCourses = 2, prerequisites = [[1,0],[0,1]]
Output: []  (cycle)
```

---

## What Actually Matters

- Same as Course Schedule I but need actual order, not just true/false
- Kahn's BFS naturally produces the order as a byproduct — nodes are processed in valid dependency order
- Cycle detection is free — if not all nodes are processed, a cycle exists
- Multiple valid orderings exist — any is acceptable

---

## Core Insight

> Process nodes with no remaining dependencies first (indegree 0). As each node is processed, reduce its neighbors' indegrees. Nodes that hit indegree 0 are ready next. If all nodes are processed, return the order — otherwise a cycle exists.

---

## Invariant / Mental Model

> `indegree[i]` always reflects how many unprocessed prerequisites course `i` still has. A node enters the queue exactly when all its prerequisites are done.

---

## Thinking Log (Evolution of the Solution)

- **Prior Knowledge:** Already implemented `topoSort` using Kahn's BFS in Graph.java
- **Key Insight:** Topological sort naturally gives the ordering — Course Schedule I only needed true/false, this needs the actual sequence
- **Approach:** Kahn's BFS over DFS — BFS produces order directly in queue poll sequence, DFS needs post-order reversal
- **Cycle Detection:** If `index != numCourses` after BFS, some nodes were never processed — cycle exists, return empty array
- **Final Realization:** Exact same logic as Graph.java `topoSort` — just return `int[]` instead of `List<Integer>`

---

## Algorithm (High Level)

1. Build adjacency list from prerequisites — `pre[1] → pre[0]`
2. Compute indegree for every node
3. Offer all indegree-0 nodes to queue
4. While queue not empty: poll node, add to result, decrement neighbors' indegrees, offer any that hit 0
5. If `index == numCourses` return result, else return empty array

---

## Code (Reference Only)
```java
class Solution {
    public int[] findOrder(int numCourses, int[][] prerequisites) {
        int[] indegree = new int[numCourses];
        List<List<Integer>> graph = new ArrayList<>();

        for (int i = 0; i < numCourses; i++) {
            graph.add(new ArrayList<>());
        }
        for (int[] pre : prerequisites) {
            graph.get(pre[1]).add(pre[0]);
            indegree[pre[0]]++;
        }

        Queue<Integer> q = new ArrayDeque<>();
        for (int i = 0; i < numCourses; i++) {
            if (indegree[i] == 0) q.offer(i);
        }

        int[] result = new int[numCourses];
        int index = 0;
        while (!q.isEmpty()) {
            int node = q.poll();
            result[index++] = node;
            for (int nei : graph.get(node)) {
                indegree[nei]--;
                if (indegree[nei] == 0) q.offer(nei);
            }
        }

        return index == numCourses ? result : new int[0];
    }
}
```

---

## Edge Cases to Recall

- No prerequisites → all indegrees 0 → all offered immediately → any order valid
- Cycle → some nodes never reach indegree 0 → `index < numCourses` → return `new int[0]`
- Single course → no prerequisites → return `[0]`

---

## One-Line Recall

> Kahn's BFS — process indegree-0 nodes first, decrement neighbors, if all processed return order else cycle exists return empty.
