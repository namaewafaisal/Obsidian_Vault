## LC 98. Validate Binary Search Tree

### Problem (Statement)

Given the `root` of a binary tree, determine whether it is a **valid Binary Search Tree (BST)**.

BST rules (strict):
- All nodes in the left subtree are **strictly less** than the node
- All nodes in the right subtree are **strictly greater** than the node
- Both subtrees must also be valid BSTs
- **Duplicates are not allowed**

---

### Input / Output

**Input**
```
        10
       /  \
      5   15
          /
         6
```

**Output**
```
false
```

Reason: `6` is in the right subtree of `10` but `6 < 10`.

---

### Key Invariant

> **Every node must satisfy:** `min < node.val < max`,  
> where `min` and `max` are determined by all ancestors, not just the parent.

This is a **global ordering constraint**, not a local one.

---

### Thinking Log (Actual Evolution, Mistakes Included)

#### Initial Intuition (Incorrect)

> *“Check if `left.val < root.val` and `right.val > root.val`, then recurse.”*

Why this failed:
- BST validity is **not local**
- A node can violate an ancestor’s constraint while still satisfying its parent’s
- This misses deep violations

---

#### ❌ Mistake #1 — Using only parent-child comparison

Why it failed:
- Does not propagate ancestor constraints
- Allows invalid trees to pass

Example failure:
```
10
 \
  15
 /
6
```

---

#### ❌ Mistake #2 — Trying to fix with a global flag

Why this failed:
- Flags help stop recursion, not fix logic
- If the wrong condition never triggers, the flag never flips

---

#### ❌ Mistake #3 — Using inclusive bounds

Used logic:
```
min <= node.val <= max
```

Why this failed:
- Allows duplicates
- Violates strict BST definition

---

### Key Breakthrough

> *“Each recursive call must carry the valid value range allowed by all ancestors.”*

This led to:
- Passing `min` and `max` down recursion
- Using **strict** inequality
- Composing results using logical AND

---

### Correct Mental Model (Must Lock In)

- Treat recursion as a **contract enforcer**
- Each call guarantees:
  - “This subtree contains only values in `(min, max)`”
- Empty subtree is always valid
- Any violation invalidates the entire tree

---

### Final Correct Code (Java)

```java
class Solution {
    public boolean isValidBST(TreeNode root) {
        return helper(root, Long.MIN_VALUE, Long.MAX_VALUE);
    }

    private boolean helper(TreeNode root, long min, long max) {
        if (root == null) return true;

        if (root.val <= min || root.val >= max) {
            return false;
        }

        return helper(root.left, min, root.val)
            && helper(root.right, root.val, max);
    }
}
```

---

### Why This Works

- `long` bounds safely exceed possible node values
- Strict inequalities enforce BST definition
- AND-composition ensures **all** subtrees are valid
- Ancestor constraints are never lost

---

### Common Mistakes (Explicit)

- Checking only immediate children
- Allowing equality in comparisons
- Using `Integer.MIN_VALUE / MAX_VALUE`
- Treating empty subtree as invalid
- Using flags instead of invariants

---

### One-Sentence Recall

> LC 98 works by enforcing that every node lies strictly within the value range allowed by all its ancestors.
