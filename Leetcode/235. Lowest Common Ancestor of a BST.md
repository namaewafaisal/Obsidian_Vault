## LC 235. Lowest Common Ancestor of a Binary Search Tree

### Problem (Statement)

Given the `root` of a **Binary Search Tree (BST)** and two nodes `p` and `q` that **exist in the tree**, return their **lowest common ancestor (LCA)**.

- A node can be an ancestor of itself
- Tree is a **valid BST**
- `p` and `q` are given as **node references**, not values

---

### Input / Output

**Input**
```
        6
       / \
      2   8
         /
        7

p = 7, q = 8
```

**Output**
```
8
```

---

### Key Invariant

> **In a BST, the LCA is the first node where the paths to `p` and `q` split.**

That split happens **only** when:
```
min(p.val, q.val) ≤ root.val ≤ max(p.val, q.val)
```

---

### Thinking Log (Actual Evolution, Mistakes Included)

#### Initial Intuition (After Noticing BST)

> *“If root lies between `p` and `q`, then root is the answer.”*

This intuition was **correct**, but the first implementation used a **weaker condition**.

---

#### ❌ Mistake #1 — Using an incorrect split condition

Used condition:
```
root ≤ p AND q ≥ root
```

Why this was wrong:
- This only checks that `root` is **not greater than both**
- It does **not** guarantee `root` is *between* `p` and `q`
- Allowed cases where **both `p` and `q` are on the same side**

---

#### ❌ Failing Case (Critical)

BST:
```
        6
         \
          8
         /
        7
```

`p = 7`, `q = 8`

Wrong logic:
- Condition passes at `root = 6`
- Returns `6`

Correct answer:
- Both nodes are in the **right subtree**
- Correct LCA is `8`

This exposed that the split-condition was **too weak**.

---

### Key Breakthrough

> *“Split means root is between `p` and `q`, not just ‘not outside both’.”*

This led to the correct invariant:
```
(p ≤ root ≤ q) OR (q ≤ root ≤ p)
```

---

### Correct Mental Model (Must Lock In)

- Use **BST ordering**, not traversal
- At each node:
  - If both `p` and `q` are **greater** → go right
  - If both are **smaller** → go left
  - Otherwise → this node is the LCA
- Never return early unless the **true split condition** is met

---

### Final Correct Code (Java)

```java
class Solution {
    public TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {

        if ((p.val <= root.val && root.val <= q.val) ||
            (q.val <= root.val && root.val <= p.val)) {
            return root;
        }

        if (p.val > root.val && q.val > root.val) {
            return lowestCommonAncestor(root.right, p, q);
        }

        return lowestCommonAncestor(root.left, p, q);
    }
}
```

---

### Why This Works

- BST property guarantees ordering
- Explicit split-condition prevents premature return
- Recursion only descends when **both nodes are on one side**
- First split encountered is the **lowest** one by definition

---

### Common Mistakes (Explicit)

- Forgetting it is a BST
- Using weak inequalities for split detection
- Returning root too early
- Treating it like generic binary tree LCA

---

### One-Sentence Recall

> LC 235 works because in a BST, the lowest common ancestor is the first node whose value lies between `p` and `q`.
