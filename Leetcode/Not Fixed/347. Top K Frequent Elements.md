## LC 347. Top K Frequent Elements

| **Metric** | **Value** |
| --- | --- |
| **Date** | December 31, 2025 |
| **Time Taken** | ~25 minutes |
| **Difficulty** | Medium |
| **Pattern** | Frequency Map + Min-Heap (Top-K Selection) |

---

### Problem (summary)

Given an integer array `nums` and an integer `k`, return the  most frequent elements. You may return the answer in any order.

---

### Key Invariant

* **The Top-K Filter:** To find the  highest values, we use a **Min-Heap** of size . By always removing the smallest element when the size exceeds , the heap is forced to retain only the largest  elements encountered so far.
* **Global vs. Local:** Unlike a threshold check (frequency ), Top-K requires a global comparison of all frequencies.

---

### Thinking Log (Evolution of the Solution)

* **Initial Understanding (Incorrect):** I’ll make a frequency map. Whenever a number’s frequency reaches `k`, I’ll add it to the result.
* *Correction:* I realized `k` is not a frequency threshold; it is the **count of elements** I need to return.


* **Correct Restatement:** I need to rank all frequencies and select the **top ** among them.
* **Data Structure Selection:**
* **HashMap:** Necessary for counting frequencies, but cannot rank them.
* **List/Deque:** Can store data, but no efficient way to maintain a global ranking.
* **Heap (Priority Queue):** Perfect. It allows fast insertion and removal while giving controlled access to the "worst" (least frequent) element to discard it.


* **Min-Heap vs. Max-Heap:**
* A **Max-Heap** would keep the most frequent at the top, but if I need to discard elements, I need to remove the *least* frequent.
* A **Min-Heap** (Top = lowest frequency) allows me to `poll()` the weakest elements, leaving only the  strongest in the heap.


* **Heap Design:** The heap must store `int[] {number, frequency}` and use a safe comparator: `Integer.compare(a[1], b[1])`.
* **The "Aha!" Moment:** Add every element to the heap, but if we ever exceed , remove the weakest one immediately.

---

### Implementation Strategy

1. Build a frequency map of all numbers in `nums`.
2. Initialize a `PriorityQueue` (Min-Heap) comparing the frequency values.
3. Iterate through the `map.entrySet()`:
* Offer a new `int[]{number, frequency}` to the heap.
* If `heap.size() > k`, `poll()` the top (the current least frequent element).


4. Extract the numbers from the remaining  heap elements into a result array.

---

### Final Code (Java)

```java
class Solution {
    public int[] topKFrequent(int[] nums, int k) {
        Map<Integer, Integer> map = new HashMap<>();
        // Min-Heap based on frequency (index 1 of the int array)
        PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> Integer.compare(a[1], b[1]));

        // 1. Build frequency map
        for (int i : nums) {
            map.put(i, map.getOrDefault(i, 0) + 1);
        }

        // 2. Maintain a heap of size K
        for (Map.Entry<Integer, Integer> entry : map.entrySet()) {
            heap.offer(new int[]{entry.getKey(), entry.getValue()});

            // If we have more than K elements, remove the one with the smallest frequency
            if (heap.size() > k) {
                heap.poll();
            }
        }

        // 3. Convert heap to result array
        int i = 0;
        int[] result = new int[k];
        while (!heap.isEmpty()) {
            result[i++] = heap.poll()[0];
        }
        
        return result;
    }
}

```

### Transferable Insight

When a problem asks for **"Top K"**, **"Largest K"**, or **"Closest K"**, your brain should immediately think **Heap**.

* Use a **Min-Heap** to find the **Top  Largest**.
* Use a **Max-Heap** to find the **Top  Smallest**.
