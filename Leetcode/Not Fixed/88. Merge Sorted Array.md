## LC 88. Merge Sorted Array

### Problem (Statement)

You are given two **sorted** integer arrays:

- `nums1` of size `m + n`, where the first `m` elements are valid
- `nums2` of size `n`

Merge `nums2` into `nums1` as one sorted array **in-place**.

Constraints:
- You must not use extra arrays
- Final result must be stored in `nums1`
- Order must be **sorted**

---

### Key Observation

> Since `nums1` has extra space at the end, merging must be done **from the back**, not from the front.

Front-to-back merging would overwrite unprocessed values.

---

### Core Idea (Invariant-Based Thinking)

We maintain three pointers:

- `i` → last valid element in `nums1` (`m - 1`)
- `j` → last element in `nums2` (`n - 1`)
- `k` → last position in `nums1` (`m + n - 1`)

Invariant:

> After each step, indices `> k` contain the **largest elements in correct sorted order**.

This invariant guarantees correctness and prevents overwriting.

---

### Thinking Log (Mandatory)

#### My initial thinking (your words, summarized)

> I thought of merging like normal merge sort from the front.  
>  
> But since `nums1` already contains elements, writing from the front overwrites values that are not yet compared.  
>  
> I wasn’t fully clear on what “in-place” meant and where it was safe to write.

---

#### Correction / refinement

- In-place does **not** mean “no overwriting at all”  
- It means **overwrite only when the value is no longer needed**
- The safe overwrite direction is from the **end**, because:
  - The largest elements belong at the end
  - We never need to read values beyond the current `i` and `j`

Once this is understood, the problem becomes mechanical.

---

### Algorithm Overview

1. Set pointers:
   - `i = m - 1`
   - `j = n - 1`
   - `k = m + n - 1`
2. While both arrays have elements:
   - Compare `nums1[i]` and `nums2[j]`
   - Place the larger at `nums1[k]`
   - Move the corresponding pointer
3. If `nums2` still has elements:
   - Copy them into `nums1`
4. Done (remaining `nums1` elements are already in place)

Time: `O(m + n)`  
Space: `O(1)`

---

### Final Code (Java)

```java
class Solution {
    public void merge(int[] nums1, int m, int[] nums2, int n) {
        int i = m - 1;
        int j = n - 1;
        int k = m + n - 1;

        while (i >= 0 && j >= 0) {
            if (nums1[i] > nums2[j]) {
                nums1[k] = nums1[i];
                i--;
            } else {
                nums1[k] = nums2[j];
                j--;
            }
            k--;
        }

        while (j >= 0) {
            nums1[k] = nums2[j];
            j--;
            k--;
        }
    }
}
```

### Common Mistakes

- Trying to merge from the front
- Using an extra array (violates in-place constraint)
- Forgetting that remaining `nums1` elements are already sorted
- Misunderstanding what “safe overwrite” means

---

### Pattern Connection

- Reverse two-pointer technique
- In-place merging
- Similar reasoning applies to:
  - Merging intervals backwards
  - Filling arrays from the end when space is reserved
