## LC 57. Insert Interval

| **Metric**     | **Value**                      |
| -------------- | ------------------------------ |

| **Difficulty** | Medium                         |

---

### Problem (summary)

You are given a list of non-overlapping intervals, sorted by start time, and a new interval to insert. After insertion, the intervals must remain sorted and non-overlapping. You must merge overlapping intervals if necessary.

---

### Example

Input: `intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]]`, `newInterval = [4,8]`

Output: `[[1,2],[3,10],[12,planation: The new interval `[4,8]` overlaps with `[3,5]`, `[6,7]`, and `[8,10]`, merging them into `[3,10]`.

---

### Pattern Classification

* Interval Manipulation
* Greedy Linear Scan (Merge-on-the-fly)
* One-Pass Sorting Preservation

---

### Key Invariant

* At any point in the loop, `newInterval` represents the **combined merge** of itself and all overlapping intervals encountered so far.
* It is inserted into the result list **exactly once**, only after all possible overlaps are resolved.

---

### The Three Valid Cases (Logic Flow)

For each interval `curr` in the list:

1. **Completely Before:** `curr.end < newInterval.start`. No overlap. Add `curr` to result.
2. **Completely After:** `curr.start > newInterval.end`. Overlaps are finished. Insert `newInterval` (if not already added) and then add `curr`.
3. **Overlapping:** Otherwise. Expand `newInterval` to cover `curr`:
* `newInterval.start = min(newInterval.start, curr.start)`
* `newInterval.end = max(newInterval.end, curr.end)`



---

### Thinking Log (Evolution of the Solution)

* **Initial Thought:** Just insert the interval where it fits based on start time, then run the LC 56 "Merge Intervals" logic.
* *Correction:* While this works ( due to sorting or  if inserted carefully), it’s more efficient to merge as we scan since the input is already sorted.
* **Early Confusion:** How do I know when to stop merging?
* *Correction:* Once an interval's start time is greater than our (possibly expanded) `newInterval.end`, all overlaps are guaranteed to be finished because the input is sorted.
* **Edge Case Alert:** What if the new interval is the very last one?
* *Correction:* If the loop finishes and we haven't hit "Case 2" (Completely After), we must add the `newInterval` at the very end.

---

### Implementation Strategy

1. Initialize an empty list for the result and a boolean flag `newAdded`.
2. Iterate through the existing intervals.
3. Implement the three-case logic:
* If `curr` is before, add it.
* If `curr` is after, add `newInterval` (if flag is false), then add `curr`.
* If overlapping, update `newInterval` boundaries.


4. After the loop, check the flag; if false, append `newInterval`.
5. Convert the list back to a 2D array.

---

### Code

```java
class Solution {
    public int[][] insert(int[][] intervals, int[] newInterval) {
        List<int[]> result = new ArrayList<>();
        boolean newAdded = false;

        for (int[] curr : intervals) {
            // Case 1: curr is completely after newInterval
            if (curr[0] > newInterval[1]) {
                if (!newAdded) {
                    result.add(newInterval);
                    newAdded = true;
                }
                result.add(curr);
            }
            // Case 2: curr is completely before newInterval
            else if (curr[1] < newInterval[0]) {
                result.add(curr);
            }
            // Case 3: overlapping intervals - update the merge target
            else {
                newInterval[0] = Math.min(newInterval[0], curr[0]);
                newInterval[1] = Math.max(newInterval[1], curr[1]);
            }
        }

        // If newInterval was never added (it belongs at the end)
        if (!newAdded) {
            result.add(newInterval);
        }

        return result.toArray(new int[result.size()][]);
    }
}

```
