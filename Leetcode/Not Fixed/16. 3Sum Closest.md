## LC 16. 3Sum Closest

### Problem (Statement)

Given an integer array `nums` and an integer `target`, find **three distinct elements** whose **sum is closest to `target`**.

Constraints:
- Exactly one answer exists
- Return the **sum**, not the indices or the triplet
- Closeness is defined by minimum `|sum − target|`

---

### Key Observation

> Sorting enables monotonic control of the sum, while absolute difference is used **only to evaluate**, not to navigate.

This problem is structurally identical to **3Sum**, except:
- We **do not stop** on equality
- We **track the closest sum**, not exact matches

---

### Core Idea (Separation of Concerns)

There are **two independent logics**:

1. **Navigation logic** (same as 3Sum):
   - If `sum < target` → move `left++`
   - If `sum > target` → move `right--`

2. **Evaluation logic** (new part):
   - Measure closeness using `abs(sum - target)`
   - Update best answer when this distance improves

Mixing these two causes bugs.

>

---

#### Correction / refinement

- The **difference (`diff`) is only a metric**, not the answer
- The **answer is always the `sum`** that produced the smallest difference
- Returning `diff` answers the wrong question (“how close?” instead of “which sum?”)
- Pointer movement **must not depend on difference**, only on comparison with `target`

Correct invariant:

> Whenever a smaller `|sum − target|` is found, replace the stored **best sum**.

---

### Algorithm Overview

1. Sort the array
2. For each index `i`:
   - Fix `nums[i]`
   - Use two pointers (`left`, `right`) on the remaining range
3. For each triplet:
   - Compute `sum`
   - Compute `abs(sum - target)`
   - Update best sum if closer
4. Move pointers exactly as in 3Sum
5. Return the stored best sum

Time: `O(n²)`  
Space: `O(1)` (ignoring sort)

---

### Final Code (Java)

```java
class Solution {
    public int threeSumClosest(int[] nums, int target) {
        Arrays.sort(nums);
        int dif = Integer.MAX_VALUE;
        int result = 0;

        for (int i = 0; i < nums.length - 2; i++) {
            int left = i + 1;
            int right = nums.length - 1;

            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];
                int curDif = Math.abs(sum - target);

                if (curDif < dif) {
                    dif = curDif;
                    result = sum;
                }

                if (sum > target) {
                    right--;
                } else {
                    left++;
                }
            }
        }
        return result;
    }
}
```

### Common Mistakes

- Returning the **difference** instead of the **sum**
- Letting difference affect pointer movement
- Overthinking duplicate handling (not required here)
- Treating this as a new pattern instead of a 3Sum variant

### Pattern Connection

- LC 15 (3Sum): exact match, unique triplets
- LC 16 (3Sum Closest): best approximation, no uniqueness requirement

Same navigation invariant, different evaluation rule.
