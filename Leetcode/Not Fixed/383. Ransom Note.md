## LC 383. Ransom Note

| **Metric**     | **Value**                    |
| -------------- | ---------------------------- |
| **Date**       | 2026-01-15                   |
| **Time Taken** | ~10 minutes                  |
| **Difficulty** | Easy                         |
| **Pattern**    | Hashing / Frequency Counting |

---

### Problem (summary)

Given two strings `ransomNote` and `magazine`, determine if `ransomNote` can be constructed using characters from `magazine`.

* Each character in `magazine` can be used **at most once**.
* Extra characters in `magazine` are allowed and irrelevant.

---

### Key Invariant

> **Ransom note characters are a demand; magazine characters are the supply.**

* Every character required by `ransomNote` must exist in `magazine`
* **Frequency must be sufficient**
* Supply may exceed demand, but never the reverse

---

### Thinking Log (Evolution of the Solution)

* **Initial Observation:**
  Order does not matter — only character counts matter.

* **Important Distinction from Anagram:**
  Unlike anagrams, **length equality is NOT required**.
  Extra characters in `magazine` do not affect feasibility.

* **Correct Mental Model:**
  This is a **subset frequency check**, not equality.

* **Data Structure Choice:**
  Since characters are lowercase English letters, a fixed `int[26]` array is sufficient.
  This is faster and simpler than a `HashMap`.

* **Supply Phase (`magazine`):**
  Count available characters.

* **Demand Phase (`ransomNote`):**
  Consume characters by decrementing frequency.

  * If any count drops **below zero**, demand exceeded supply → return `false` immediately.

* **Final State:**
  If all characters are consumed successfully, construction is possible.

---

### Implementation Strategy

1. Create an integer array of size 26.
2. Increment counts for each character in `magazine`.
3. Traverse `ransomNote`:

   * Decrement the corresponding count.
   * If any count becomes negative, return `false`.
4. If traversal completes, return `true`.

---

### Final Code (Java)

```java
class Solution {
    public boolean canConstruct(String ransomNote, String magazine) {
        int[] mag = new int[26];

        for (char c : magazine.toCharArray()) {
            mag[c - 'a']++;
        }
        for (char c : ransomNote.toCharArray()) {
            if (--mag[c - 'a'] < 0) {
                return false;
            }
        }
        return true;
    }
}
```

---

### Complexity Analysis

| Metric    | Complexity | Reason                             |
| --------- | ---------- | ---------------------------------- |
| **Time**  | O(n + m)   | One pass over both strings         |
| **Space** | O(1)       | Fixed-size array (26 letters only) |

---

### Why This Solution Is Optimal

* No sorting
* No hash maps
* Constant extra space
* Early exit on failure
* Directly models **supply vs demand**

This is the **canonical optimal solution** for this problem.

---

### Transferable Insight

This exact logic applies to:

* **LC 242 — Valid Anagram** (with length equality)
* **LC 438 — Find All Anagrams in a String**
* Any problem where **availability vs requirement** is the core constraint

Once you see *supply vs demand*, the problem collapses.
