## LC 105. Construct Binary Tree from Preorder and Inorder Traversal

### Problem (Statement)

Given two arrays:
- `preorder` — preorder traversal of a binary tree
- `inorder` — inorder traversal of the same tree

All values are **unique**.

Construct the original binary tree and return its root.

---

### Input / Output

**Input**
```
preorder = [3, 9, 20, 15, 7]
inorder  = [9, 3, 15, 20, 7]
```

**Output**
```
        3
       / \
      9  20
         / \
        15  7
```

---

### Key Invariant

> **Preorder tells *which* node to create.  
> Inorder tells *where* that node splits the tree.**

These two roles must never be mixed.

---

### Thinking Log (Actual Evolution, Mistakes Included)

#### Initial Block (Mental, Not Conceptual)

> *“I know preorder and inorder, but my mind is blank.”*

Why this happened:
- Tried to think about recursion, indices, arrays, and tree shape at once
- Mixed **traversal thinking** with **construction thinking**

This caused overload, not lack of understanding.

---

#### ❌ Mistake #1 — Thinking preorder and inorder both control recursion

Why this failed:
- Preorder is **global order**, not subtree-specific
- Inorder defines **subtree boundaries**
- Treating both symmetrically caused confusion

---

#### ❌ Mistake #2 — Not realizing recursion works on inorder ranges

Why this was blocking:
- Inorder is one array
- But recursion needs **local responsibility**
- Missing idea: each recursive call owns `inorder[left … right]`

---

### Key Breakthrough

> *“Each recursion builds a subtree using a slice of inorder,  
> while preorder advances globally.”*

Once this clicked:
- Root selection became trivial
- Recursion became mechanical
- No backtracking or guessing needed

---

### Correct Mental Model (Must Lock In)

- Maintain a **global index** into `preorder`
- Build a map from value → index for `inorder`
- Recursive function:
  - Responsible only for `inorder[left … right]`
- Base case:
  - `left > right` → no subtree

At each call:
1. Take next value from `preorder` → root
2. Find root index in `inorder`
3. Split inorder into left and right ranges
4. Recurse left first, then right
5. Return root

---

### Final Correct Code (Java)

```java
class Solution {
    int index = 0;
    int[] preorder;
    Map<Integer, Integer> map = new HashMap<>();

    public TreeNode buildTree(int[] preorder, int[] inorder) {
        this.preorder = preorder;

        for (int i = 0; i < inorder.length; i++) {
            map.put(inorder[i], i);
        }

        return helper(0, inorder.length - 1);
    }

    private TreeNode helper(int left, int right) {
        if (left > right) return null;

        int rootVal = preorder[index++];
        int mid = map.get(rootVal);

        TreeNode root = new TreeNode(rootVal);
        root.left = helper(left, mid - 1);
        root.right = helper(mid + 1, right);

        return root;
    }
}
```

---

### Why This Works

- Each preorder value is consumed **exactly once**
- Inorder indices enforce correct structure
- Left subtree is always built before right (preorder invariant)
- No array slicing → O(n) time

---

### Common Mistakes (Explicit)

- Trying to slice preorder arrays
- Resetting preorder index in recursion
- Using inorder to pick root
- Forgetting left-first recursion
- Not using a hashmap for inorder indices

---

### One-Sentence Recall

> LC 105 works by using preorder to decide node creation order and inorder to decide subtree boundaries.
