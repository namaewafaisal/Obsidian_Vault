# 35. Search Insert Position

## Problem (LeetCode Statement)

**Input:**  
- Sorted integer array `nums` (ascending order)  
- Integer `target`

**Output:**  
- Return the index if `target` is found  
- Otherwise, return the index where it would be inserted in order

**Task:**  
Determine the position of `target` in a sorted array.  
If not present, return the position where it should be inserted.

---

## Constraints

- `1 ≤ nums.length ≤ 10^4`
- `-10^4 ≤ nums[i] ≤ 10^4`
- `nums` is sorted in strictly increasing order
- `-10^4 ≤ target ≤ 10^4`

---

## Examples

```
Input:  nums = [1,3,5,6], target = 5
Output: 2
```

```
Input:  nums = [1,3,5,6], target = 2
Output: 1
```

```
Input:  nums = [1,3,5,6], target = 7
Output: 4
```

```
Input:  nums = [1,3,5,6], target = 0
Output: 0
```

---

## What Actually Matters

- Array is sorted
- Need the **first index where nums[i] ≥ target**
- If none found → insert at end

---

## Core Insight

> This is a **lower bound** problem.

We are searching for:
```
first element ≥ target
```

If such element exists → return its index  
Otherwise → return `nums.length`

---

## Invariant / Mental Model

> The correct insertion position is the first index where the array value is not smaller than the target.

This guarantees:
- Sorted order is preserved
- No shifting logic needed in this problem

---

## Thinking Log (Evolution of the Solution)

### Initial Understanding (your words)

> “If I find an element greater than or equal to target, I return that index.”

Correct — that directly matches the lower bound idea.

---

### Final Edge Case

> “If no such element exists, return nums.length.”

Correct — because target belongs at the end.

---

## Algorithm (High Level)

1. Traverse array from left to right
2. If `nums[i] ≥ target`, return `i`
3. If loop finishes, return `nums.length`

Time: `O(n)`  
Space: `O(1)`

---

## Code (Reference Only)

```java
class Solution {
    public int searchInsert(int[] nums, int target) {
        for (int i = 0; i < nums.length; i++) {
            if (nums[i] >= target) {
                return i;
            }
        }
        return nums.length;
    }
}
```

---

## Important Note

Although this solution works, the expected optimal solution uses **binary search** with `O(log n)` time.

This version is correct but not optimal.

## Edge Cases to Recall

- Target smaller than all elements
- Target larger than all elements
- Target equal to first element
- Target equal to last element

> Return the first index where value ≥ target; if none, return array length.
