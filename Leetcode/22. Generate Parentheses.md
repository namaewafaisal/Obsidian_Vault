## LC 22. Generate Parentheses

### Problem (Statement)

Given `n` pairs of parentheses, generate all combinations of **well-formed parentheses**.

Rules:
- Each opening parenthesis `'('` must be closed by a corresponding `')'`
- Parentheses must be **balanced and properly nested**
- Output order does not matter

---

### Key Observation

> A valid parentheses string is defined not by placement, but by **constraints on counts**.

At any point:
- You cannot place more than `n` opening parentheses
- You cannot place more closing parentheses than opening ones

This turns the problem into **state-constrained recursion**, not brute-force generation.

---

### Core Idea (State Invariant)

Track two counts:
- `op` → number of `'('` used
- `cp` → number of `')'` used

Invariant:
```
0 ≤ cp ≤ op ≤ n
```

Any recursive path that violates this invariant is **pruned immediately**.

---

### Thinking Log (Mandatory)

#### My initial thinking (your words)

> I can generate all combinations of '(' and ')' of length `2n` and then check validity.

---

#### Why this thinking breaks (correction)

- Total combinations = `2^(2n)` (exponential blow-up)
- Most combinations are invalid
- Validity checking happens **after generation**, wasting work

The correct approach:
> **Generate only valid prefixes**.

---

#### Corrected mental model

> Each recursive call represents a **partial valid prefix**.  
> Invalid prefixes are never generated.

This is why backtracking is efficient here.

---

### Decision Tree (Backtracking Logic)

At each recursion step, you have **two possible choices**:

#### Choice 1: Add `'('`
Allowed only if:
```
op < n
```

#### Choice 2: Add `')'`
Allowed only if:
```
cp < op
```

These two conditions fully encode parentheses validity.

---

### Base Case

When:
```
op == n AND cp == n
```

- A valid parentheses string of length `2n` is formed
- Add it to the result list
- Return

---

### Why This Pruning Works

- Prevents invalid states like `")("`
- Ensures every generated string is valid
- Eliminates need for post-validation
- Time complexity reduces to **Catalan number growth**, not `2^(2n)`

---

### Algorithm Overview

1. Start with empty string
2. Track counts of `'('` and `')'`
3. Recurse only when constraints allow
4. Collect results at valid terminal states

Time: `O(Cₙ)` (Catalan number)  
Space: `O(n)` recursion depth

---

### Final Code (Java)

```java
class Solution {
    List<String> lst;

    public List<String> generateParenthesis(int n) {
        lst = new ArrayList<>();
        recursion("", 0, 0, n);
        return lst;
    }

    public void recursion(String str, int op, int cp, int n) {
        if (op == n && cp == n) {
            lst.add(str);
            return;
        }

        if (op < n) {
            recursion(str + "(", op + 1, cp, n);
        }

        if (cp < op) {
            recursion(str + ")", op, cp + 1, n);
        }
    }
}
```

---

### Common Mistakes

- Generating all combinations and validating later
- Allowing `')'` when `cp > op`
- Forgetting that `op` must never exceed `n`
- Thinking this is a string problem instead of a **state problem**
