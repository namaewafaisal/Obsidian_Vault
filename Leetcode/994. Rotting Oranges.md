## LC 994. Rotting Oranges

### Problem (Statement)

Given a grid where:
- `0` = empty cell
- `1` = fresh orange
- `2` = rotten orange

Every minute:
- A rotten orange turns all **adjacent (up/down/left/right)** fresh oranges rotten.

Return the **minimum number of minutes** required to rot all oranges,  
or `-1` if impossible.

---

### Key Invariant

> **This is multi-source BFS where each BFS level represents exactly one minute.**

Time does **not** increase per node —  
it increases per **layer**.

---

### Mental Model

- Treat the grid as a graph
- All initial rotten oranges are **starting points**
- BFS spreads rot uniformly
- New rotten oranges are processed in the **next minute**

---

### Why `size = queue.size()` Matters

- All nodes currently in the queue belong to the **same minute**
- Newly added nodes belong to the **next minute**
- Processing exactly `size` nodes keeps time accurate

---

### Why `fresh > 0` Is Required

- Time should advance **only while work remains**
- If no fresh oranges are left:
  - stop immediately
  - avoid adding an extra minute

---

### Stopping Conditions

- If BFS ends but fresh oranges remain → return `-1`
- If all fresh oranges rot → return minutes elapsed

---

### Common Mistakes

- Incrementing time per node instead of per level
- Forgetting multi-source initialization
- Missing the `fresh > 0` condition
- Treating this like DFS

---

### One-Sentence Recall

> LC 994 works because BFS spreads from all rotten oranges simultaneously, and each BFS layer corresponds to one minute.
