## Trees – Recursion & Mental Model (Foundation Notes)

### Purpose of This Note

This note captures:
- **How recursion actually works on trees**
- **Where my thinking went wrong initially**
- **The correct mental model to use going forward**

This is **not tied to a single problem**, but to understanding trees in general.

---

## Core Realization

> Tree recursion works through **in-place mutation of node links**, not through returned values.

This was the key concept that was unclear initially.

---

## What I Initially Thought (Where I Went Wrong)

### ❌ Mistake 1 — Thinking I need a separate recursive helper

> *“I probably need another function for recursion, and return the root from this one.”*

Why this was wrong:
- The function itself **is** the recursive function
- Trees don’t need helpers unless:
  - extra state is required
  - results must be combined
- LC 226 does not require any external state

**Correction:**  
One function is enough. The same function calls itself.

---

### ❌ Mistake 2 — Overthinking the `return root`

> *“The return is part of the recursion logic.”*

Why this was wrong:
- The recursion does **not** depend on the return value
- All changes happen via **pointer mutation**
- The return exists only to satisfy the **method contract**

**Correct understanding:**
- Recursive calls ignore the returned value
- Only the **outermost caller** cares about the return

---

### ❌ Mistake 3 — Thinking in terms of “going down then coming back up”

> *“I go to the bottom, then when I return I do the operation.”*

Why this was misleading:
- That is **postorder traversal**, but not required here
- The operation (swap) does not depend on children’s results
- Operation timing is **independent** of DFS itself

**Correction:**  
At each node:
- do the operation
- recurse
No need to wait for return.

---

### ❌ Mistake 4 — Visualization problem

> *“Swapping is easy, but visualizing what happens is hard.”*

Why this felt hard:
- Trees are **pointer-based**
- Nodes do not move
- Only **references (links)** are swapped

Once I saw it as:
> “I am flipping arrows, not moving values”

the confusion disappeared.

---

## Correct Mental Model (Locked In)

### How to think about tree recursion

For any tree problem:
1. Ask: **What should happen at one node?**
2. Apply that logic at the current node
3. Recursively apply the same logic to subtrees

You are not “controlling” recursion.
You are **describing a rule that applies everywhere**.

---

### What recursion actually does for trees

- Traverses the structure automatically
- Ensures every node is visited exactly once
- Handles depth implicitly

You only focus on **local correctness**.

---

## DFS vs BFS (Clarified)

- **DFS**: go deep first (recursion-friendly)
- **BFS**: go level by level (queue-based)

Important distinction:
> Traversal order ≠ operation timing

DFS does **not** mean “bottom-up” by default.  
You decide **when** the operation happens.

---

## Why LC 226 Works Without Using Return Values

- The tree is mutated in place
- Child links are swapped directly
- Recursive calls operate on the same objects

Returning `root`:
- is required by the function signature
- is only meaningful for the **top-level call**

---

## One-Sentence Lock-In

> Tree recursion works because the same local rule is applied to every node through pointer mutation, not because values are returned.
