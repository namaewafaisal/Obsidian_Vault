# 198. House Robber

## Problem (LeetCode Statement)

**Input:**
- `int[] nums` — array of non-negative integers representing money in each house

**Output:**
- Maximum amount of money you can rob without robbing two adjacent houses

**Task:**
Given a row of houses with money, find the maximum you can steal such that no two robbed houses are adjacent.

---

## Constraints

- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 400`
- Cannot rob two directly adjacent houses

---

## Examples
```
Input:  nums = [2, 7, 9, 3, 1]
Output: 12  (rob index 0, 2, 4 → 2+9+1)
```
```
Input:  nums = [2, 1, 1, 2]
Output: 4   (rob index 0 and 3 → 2+2)
```

---

## What Actually Matters

- You move left to right only — no backtracking or skipping around
- Greedy fails — always picking the larger neighbor doesn't work (e.g. `[2,1,1,2]` → greedy gives 3, answer is 4)
- At every house you have exactly two choices: rob it or skip it
- You only ever look back 2 steps — full array can be replaced with two variables

---

## Core Insight

> At each house, the best you can do is either rob it (take its value plus the best from two houses back) or skip it (carry forward the best from one house back). `dp[i] = max(nums[i] + dp[i-2], dp[i-1])`

---

## Invariant / Mental Model

> `dp[i]` always holds the maximum money robbable from houses `0` through `i`. By the time you reach house `i`, the best solutions for all previous houses are already finalized.

---

## Thinking Log (Evolution of the Solution)

- **Initial Thought:** At each house, take max of current plus `dp[i-1]` — build up the best total going forward
- **Issue:** Transition was imprecise — "max(dp[i], dp[i-1])" doesn't capture the skip-two logic correctly
- **Correction:** Two explicit choices at every house — rob it (`nums[i] + dp[i-2]`) or skip it (`dp[i-1]`). Take the max of both
- **Dry run `[2,1,1,2]`:** dp = [2, 2, 3, 4] — correctly picks houses 0 and 3
- **Final Realization:** Base cases `dp[0] = nums[0]` and `dp[1] = max(nums[0], nums[1])` cover all edge cases — no need for explicit length guards. And since you only look back 2 steps, the array collapses to two variables for O(1) space

---

## Algorithm (High Level)

1. Set `dp[0] = nums[0]`, `dp[1] = max(nums[0], nums[1])`
2. For each house from index 2 onward: `dp[i] = max(nums[i] + dp[i-2], dp[i-1])`
3. Return `dp[nums.length - 1]`

---

## Code (Reference Only)
```java
class Solution {
    public int rob(int[] nums) {
        if (nums.length == 1) return nums[0];
        int prev2 = nums[0];
        int prev1 = Math.max(nums[0], nums[1]);
        for (int i = 2; i < nums.length; i++) {
            int curr = Math.max(nums[i] + prev2, prev1);
            prev2 = prev1;
            prev1 = curr;
        }
        return prev1;
    }
}
```

---

## Edge Cases to Recall

- Single house → return `nums[0]` directly, loop never runs
- Two houses → `dp[1] = max(nums[0], nums[1])`, loop never runs
- All equal values → alternating pattern naturally gives the max

---

## One-Line Recall

> At each house take `max(rob it + best two back, skip it)`, carry only two variables for O(1) space.
