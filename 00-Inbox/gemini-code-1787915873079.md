## 1. Computer Networks (CN)

### What is a Network, LAN, WAN, MAN?
- **Computer Network:** A collection of interconnected devices (nodes) that communicate and share resources using a set of rules (protocols)[cite: 2].
- **LAN (Local Area Network):** Covers a small geographic area like an office, home, or school. High data transfer rates and low latency (e.g., Ethernet, Wi-Fi)[cite: 2].
- **MAN (Metropolitan Area Network):** Covers a larger area than a LAN, such as a city or campus network (e.g., cable TV networks)[cite: 2].
- **WAN (Wide Area Network):** Spans large physical distances across countries or continents. The Internet is the largest example of a WAN[cite: 2].

### OSI Model (7 Layers)
The **Open Systems Interconnection (OSI)** model standardizes communication functions into seven distinct logical layers[cite: 2]:

| Layer | Name | Primary Function | Data Unit |
| :--- | :--- | :--- | :--- |
| **7** | **Application** | Provides network services directly to end-user applications (HTTP, SMTP, FTP). | Data |
| **6** | **Presentation** | Handles data translation, formatting, encryption, and compression (SSL/TLS, JPEG). | Data |
| **5** | **Session** | Establishes, manages, and terminates persistent session connections between applications. | Data |
| **4** | **Transport** | End-to-end communication, segmentation, flow control, and error correction (TCP, UDP). | Segment (TCP) / Datagram (UDP) |
| **3** | **Network** | Logical addressing, routing, and packet forwarding across networks (IP, ICMP). | Packet |
| **2** | **Data Link** | Physical addressing (MAC), framing, hop-to-hop transfer, and error detection (Ethernet, Wi-Fi). | Frame |
| **1** | **Physical** | Transmission of raw unstructured bit streams over physical media (Cables, Fiber, Radio). | Bits |

### TCP/IP Model vs OSI Model
The TCP/IP model is a practical, 4-layer framework used in modern network protocol suites[cite: 2]:

```
+-------------------------+-------------------------+
|     OSI 7-Layer Model   |   TCP/IP 4-Layer Model  |
+-------------------------+-------------------------+
| Layer 7: Application    |                         |
| Layer 6: Presentation   | Application Layer       |
| Layer 5: Session        |                         |
+-------------------------+-------------------------+
| Layer 4: Transport      | Transport Layer         |
+-------------------------+-------------------------+
| Layer 3: Network        | Internet Layer          |
+-------------------------+-------------------------+
| Layer 2: Data Link      | Network Interface Layer |
| Layer 1: Physical       | (Link Layer)            |
+-------------------------+-------------------------+
```

### IP Address Basics (IPv4)
- **IP Address:** A logical 32-bit numerical identifier assigned to every device on an IP network, formatted as four octets separated by dots (e.g., `192.168.1.1`)[cite: 2].
- **IPv4 Classes:**[cite: 2]
  - **Class A:** `1.0.0.0` to `126.255.255.255` (Huge networks; Default mask: `/8` or `255.0.0.0`)[cite: 2]
  - **Class B:** `128.0.0.0` to `191.255.255.255` (Medium/Large networks; Default mask: `/16` or `255.255.0.0`)[cite: 2]
  - **Class C:** `192.0.0.0` to `223.255.255.255` (Small networks; Default mask: `/24` or `255.255.255.0`)[cite: 2]
  - **Class D:** `224.0.0.0` to `239.255.255.255` (Reserved for Multicast)[cite: 2]
  - **Class E:** `240.0.0.0` to `255.255.255.255` (Experimental)[cite: 2]
- **Public vs. Private IP:**[cite: 2]
  - **Public IP:** Globally unique address routable over the Internet[cite: 2].
  - **Private IP:** Non-routable on the public Internet; reserved for local internal networks[cite: 2].
    - Class A Private: `10.0.0.0` – `10.255.255.255`[cite: 2]
    - Class B Private: `172.16.0.0` – `172.31.255.255`[cite: 2]
    - Class C Private: `192.168.0.0` – `192.168.255.255`[cite: 2]

### Subnetting (Basic Concept)
Subnetting is the practice of dividing a single large logical IP network into multiple smaller, logically isolated sub-networks (subnets)[cite: 2].
- **Subnet Mask:** A bitmask that separates an IP address into two parts: the **Network ID** and the **Host ID**[cite: 2].
- **Purpose:** Prevents IP address waste, reduces broadcast network traffic, and improves administrative security[cite: 2].

### MAC Address vs IP Address
| Feature | MAC Address (Media Access Control) | IP Address (Internet Protocol) |
| :--- | :--- | :--- |
| **Layer** | Layer 2 (Data Link) | Layer 3 (Network) |
| **Type** | Physical / Hardware Address | Logical / Software Address |
| **Format** | 48-bit (6 hex pairs, e.g., `AA:BB:CC:DD:EE:FF`) | 32-bit (IPv4) or 128-bit (IPv6) |
| **Assignment** | Burned into the Network Interface Card (NIC). | Assigned dynamically (DHCP) or statically by admin. |
| **Scope** | Local communication within the same network segment. | Global end-to-end communication across networks. |

### TCP vs UDP
- **TCP (Transmission Control Protocol):**[cite: 2]
  - Connection-oriented protocol (requires handshake before data transfer)[cite: 2].
  - Reliable (guarantees delivery, ordering, error checking via ACKs)[cite: 2].
  - Overhead: Higher due to headers and state tracking[cite: 2].
  - Use Cases: Web traffic (HTTP/HTTPS), file transfers (FTP), email (SMTP), SSH[cite: 2].
- **UDP (User Datagram Protocol):**[cite: 2]
  - Connectionless protocol (sends data without initial connection)[cite: 2].
  - Unreliable (no delivery guarantee, no packet ordering, lightweight)[cite: 2].
  - Overhead: Very low latency[cite: 2].
  - Use Cases: Video streaming, VoIP, online multiplayer games, DNS lookups[cite: 2].

### TCP 3-Way Handshake
Before TCP transfers data, a connection is established using a 3-way exchange[cite: 2]:
1. **SYN (Synchronize):** The client sends a TCP segment with `SYN` flag set and an initial sequence number $x$ to the server[cite: 2].
2. **SYN-ACK (Synchronize-Acknowledge):** The server responds with `SYN` flag, sequence number $y$, and `ACK` acknowledging $x+1$[cite: 2].
3. **ACK (Acknowledge):** The client sends an `ACK` segment acknowledging sequence number $y+1$. Connection established![cite: 2]

```
Client                                  Server
  |                                       |
  | ------------ SYN (seq=x) -----------> |
  |                                       |
  | <------- SYN-ACK (seq=y, ack=x+1) ----|
  |                                       |
  | ------------ ACK (ack=y+1) ---------> |
  |                                       |
```

### DNS (Domain Name System) & URL Resolution
- **DNS:** The internet's phonebook; converts human-readable domain names (e.g., `example.com`) into IP addresses (e.g., `93.184.216.34`)[cite: 2].
- **URL Resolution Process:**[cite: 2]
  1. User enters `https://example.com` in a web browser[cite: 2].
  2. Browser checks **Local Cache** (Browser cache -> OS cache -> Router cache)[cite: 2].
  3. If missing, a query goes to the **Recursive Resolver** (ISP / 8.8.8.8)[cite: 2].
  4. Resolver queries **Root Nameserver** (`.`). Root returns **TLD Nameserver** (`.com`)[cite: 2].
  5. Resolver queries **TLD Nameserver**, which directs to the **Authoritative Nameserver** for `example.com`[cite: 2].
  6. Authoritative Nameserver returns the IP address[cite: 2].
  7. Resolver caches the IP and sends it back to the browser[cite: 2].
  8. Browser establishes TCP connection and fetches content[cite: 2].

### HTTP vs HTTPS
- **HTTP (HyperText Transfer Protocol):**[cite: 2]
  - Plaintext communication protocol on Port `80`[cite: 2].
  - Insecure; vulnerable to eavesdropping and man-in-the-middle attacks[cite: 2].
- **HTTPS (HTTP Secure):**[cite: 2]
  - Runs HTTP over **TLS/SSL** encryption layer on Port `443`[cite: 2].
  - Provides confidentiality (encryption), integrity (data tampering check), and authentication (digital certificate verification)[cite: 2].

### Client-Server Model
A distributed application structure that partitions tasks between providers of a resource/service (**Servers**) and service requesters (**Clients**)[cite: 2].
- **Client:** Initiates requests, renders UI, handles user input[cite: 2].
- **Server:** Processes incoming requests, performs business logic, queries database, returns responses[cite: 2].

### Common Network Ports
A **Port** is a 16-bit logical endpoint used by the transport layer to route traffic to specific applications or services on a machine[cite: 2].
- `80` — **HTTP** (Unencrypted web traffic)[cite: 2]
- `443` — **HTTPS** (Encrypted web traffic)[cite: 2]
- `22` — **SSH** (Secure Shell for remote terminal access)[cite: 2]
- `21` — **FTP** (File Transfer Protocol control channel)[cite: 2]

## 2. Database Management Systems (DBMS)

### Database, DBMS vs RDBMS
- **Database:** An organized collection of structured data stored electronically for efficient retrieval and management[cite: 2].
- **DBMS (Database Management System):** Software used to store, retrieve, update, and manage databases (e.g., MongoDB, Redis)[cite: 2].
- **RDBMS (Relational DBMS):** A specific type of DBMS that organizes data into relational tables (rows and columns) linked via keys and enforces strict structure/constraints (e.g., PostgreSQL, MySQL, Oracle)[cite: 2].

### Tables, Rows, Columns & Keys
- **Table (Relation):** Matrix structured with rows and columns[cite: 2].
- **Row (Record / Tuple):** A single data entity instance within a table[cite: 2].
- **Column (Attribute):** A specific property or field belonging to all records[cite: 2].
- **Keys:**[cite: 2]
  - **Primary Key (PK):** A unique, non-null attribute (or set of attributes) that uniquely identifies each row in a table[cite: 2].
  - **Foreign Key (FK):** An attribute in one table that references the Primary Key of another table, establishing a relationship[cite: 2].
  - **Candidate Key:** Any attribute or minimal combination of attributes capable of uniquely identifying a record. One candidate key is chosen as the Primary Key[cite: 2].

### SQL Basics
SQL (Structured Query Language) is used to perform Operations on Relational Databases[cite: 2]:

```sql
-- SELECT: Retrieve data from a table
SELECT name, email FROM users WHERE status = 'ACTIVE';

-- INSERT: Insert a new record
INSERT INTO users (id, name, email) VALUES (101, 'Alice', 'alice@example.com');

-- UPDATE: Modify existing records
UPDATE users SET status = 'INACTIVE' WHERE id = 101;

-- DELETE: Remove records
DELETE FROM users WHERE id = 101;
```

### SQL JOINs
JOINs merge columns from one or more tables based on a shared relationship column[cite: 2].

```
       INNER JOIN                   LEFT JOIN                  RIGHT JOIN
     +---+     +---+              +---+     +---+            +---+     +---+
    /     \   /     \            /     \   /     \          /     \   /     \
   (   A   ( X )  B  )          (  A A  ( X )  B  )        (   A   ( X ) B B )
    \     /   \     /            \     /   \     /          \     /   \     /
     +---+     +---+              +---+     +---+            +---+     +---+
   Matching rows only           All A + Matching B          All B + Matching A
```

```sql
-- INNER JOIN Example: Returns records with matching keys in both tables
SELECT orders.id, customers.name 
FROM orders 
INNER JOIN customers ON orders.customer_id = customers.id;
```

### Normalization (1NF, 2NF, 3NF)
Normalization is the process of organizing data in a database to reduce redundancy and eliminate unwanted anomalies (Insert, Update, Delete anomalies)[cite: 2].
- **1NF (First Normal Form):** Atomic values only (no lists/arrays in a single column) and unique record identification[cite: 2].
- **2NF (Second Normal Form):** Must be in 1NF **AND** all non-key attributes must be fully functionally dependent on the primary key (no partial dependencies)[cite: 2].
- **3NF (Third Normal Form):** Must be in 2NF **AND** no transitive dependencies exist (non-key columns must not depend on other non-key columns)[cite: 2].

### ACID Properties
Four core properties ensuring transaction reliability in a database[cite: 2]:
- **Atomicity:** "All or nothing." Either the whole transaction succeeds completely, or all modifications are fully rolled back[cite: 2].
- **Consistency:** Database transitions strictly from one valid state to another, preserving all schema invariants and constraints[cite: 2].
- **Isolation:** Concurrent execution of transactions yields the same result as if executed sequentially[cite: 2].
- **Durability:** Once committed, transaction data updates persist permanently, even in the event of power loss or crash[cite: 2].

### Entity-Relationship (ER) Diagrams
A conceptual modeling tool used to map database structures visually[cite: 2]:
- **Entity (Rectangle):** A real-world object or concept (e.g., `Student`, `Course`)[cite: 2].
- **Attribute (Oval):** A property of an entity (e.g., `student_id`, `email`)[cite: 2].
- **Relationship (Diamond):** How entities interact with each other (e.g., `Student` *Enrolls In* `Course`)[cite: 2].

## 3. Operating Systems (OS)

### OS & Main Functions
An **Operating System (OS)** is system software acting as an intermediary between user applications and system hardware resources[cite: 2].
- **Core Functions:**[cite: 2]
  1. Process Management (Scheduling, execution, synchronization)[cite: 2].
  2. Memory Management (RAM allocation, virtual memory paging)[cite: 2].
  3. File System Management (Storage abstraction, directories)[cite: 2].
  4. Device/IO Management (Drivers, buffering, interrupts)[cite: 2].
  5. Security & Protection (Access control, privileges)[cite: 2].

### Process vs Program vs Thread
- **Program:** A passive binary executable file stored on disk (e.g., `app.exe`)[cite: 2].
- **Process:** An active program instance in execution with allocated RAM memory resources (Address Space, PCB, File Descriptors)[cite: 2].
- **Thread:** The smallest execution unit within a process ("lightweight process")[cite: 2]. Threads within the same process share code, global memory, and open files, but maintain individual stacks and program counters[cite: 2].

### Process States
A process transitions through states during its lifecycle[cite: 2]:
- **New:** Process is being created[cite: 2].
- **Ready:** Loaded into memory, waiting to be assigned to CPU core[cite: 2].
- **Running:** CPU is executing process instructions[cite: 2].
- **Waiting (Blocked):** Waiting for an I/O operation or signal[cite: 2].
- **Terminated:** Execution finished; OS cleaning up PCB and resources[cite: 2].

```
+-----+       +-------+  Scheduler Dispatch  +---------+
| New | ----> | Ready | -------------------> | Running | ----> [Terminated]
+-----+       +-------+                      +---------+
                 ^                                |
                 |---- Waiting I/O Completed <----| (Needs I/O)
```

### CPU Scheduling Algorithms
Mechanisms used by OS to allocate CPU execution time among processes[cite: 2]:
1. **First-Come, First-Served (FCFS):** Non-preemptive. Executes processes in exact order of arrival. Simple, but susceptible to "Convoy Effect" (long tasks block short tasks)[cite: 2].
2. **Shortest Job First (SJF):** Chooses process with smallest execution run time next. Optimal average waiting time, but can cause starvation for longer tasks[cite: 2].
3. **Round Robin (RR):** Preemptive. Allocates a fixed CPU execution time window (**Time Quantum**) to each process in turn. Excellent for interactive systems[cite: 2].

### Deadlock & 4 Necessary Conditions
A state where two or more processes are permanently blocked because each is waiting for a resource held by the other[cite: 2].
- **4 Necessary Conditions (Coffman Conditions):**[cite: 2]
  1. **Mutual Exclusion:** Resources cannot be shared simultaneously[cite: 2].
  2. **Hold and Wait:** A process holds at least one resource while waiting for additional held resources[cite: 2].
  3. **No Preemption:** Resources cannot be forcibly taken away from a process before completion[cite: 2].
  4. **Circular Wait:** Closed cycle where $P_0$ waits for $P_1$, $P_1$ waits for $P_2$, and $P_n$ waits for $P_0$[cite: 2].

### Memory Management & Virtual Memory
- **RAM Allocation:** Dynamic management of Physical Memory allocation to running processes[cite: 2].
- **Virtual Memory:** A storage allocation technique allowing an OS to address more memory than physically present in RAM by substituting high-speed storage (SSD/HDD swap space). Provides isolated address spaces for each process[cite: 2].

### Paging Concept
A non-contiguous memory allocation technique[cite: 2]:
- Physical memory is broken into fixed-size blocks called **Frames**[cite: 2].
- Logical process memory is broken into equal-sized blocks called **Pages**[cite: 2].
- **Page Table:** OS data structure mapping process logical **Pages** to physical memory **Frames**[cite: 2].

## 4. Object-Oriented Programming (OOPs)

### Class vs Object
- **Class:** A user-defined blueprint or template containing properties (attributes) and behaviors (methods)[cite: 2].
- **Object:** A concrete instance of a class occupying memory space created from the class blueprint[cite: 2].

### The 4 Pillars of OOP
1. **Encapsulation:** Bundling data (fields) and methods operating on that data into a single unit (class) while restricting direct external access using private visibility modifiers[cite: 2].
   - *Example:* A `BankAccount` class hiding internal `balance` field and providing `deposit()` and `withdraw()` public methods[cite: 2].
2. **Abstraction:** Hiding complex implementation details and exposing only essential functional interfaces to the user[cite: 2].
   - *Example:* Driving a car using pedals and steering wheel without needing internal mechanics knowledge of the engine block[cite: 2].
3. **Inheritance:** Enabling a new child class to acquire state and behavioral methods of an existing parent class, facilitating code reuse[cite: 2].
   - *Example:* Class `Dog` inherits from parent class `Animal`[cite: 2].
4. **Polymorphism:** The ability of a message, method, or object to take on multiple forms depending on execution context[cite: 2].
   - *Example:* Shape interface with `draw()` implemented differently by `Circle` and `Square`[cite: 2].

### Constructor
A special initialization method called automatically when an object instance is instantiated[cite: 2]:
- Shares the exact name of the class[cite: 2].
- Does not return any explicit value (not even `void`)[cite: 2].
- Primary use: Initialize object attributes upon instantiation[cite: 2].

### Method Overloading vs Overriding
| Feature | Method Overloading | Method Overriding |
| :--- | :--- | :--- |
| **Type** | Compile-time (Static) Polymorphism | Run-time (Dynamic) Polymorphism |
| **Location** | Occurs within the *same* class. | Occurs across *Parent* and *Child* subclass hierarchy. |
| **Method Signature** | Same method name, **different** parameters (count or types). | **Identical** method name, parameters, and return type. |
| **Purpose** | Adds multi-type capabilities for a single behavior name. | Provides specific implementation of inherited behavior in child class. |
