# 39. Combination Sum

## Problem (LeetCode Statement)

**Input:**
- `int[] candidates` — array of distinct integers
- `int target` — target sum

**Output:**
- All unique combinations where chosen numbers sum to target. Same number may be used unlimited times.

**Task:**
Find all combinations (not permutations) from candidates that sum to target, with reuse allowed.

---

## Constraints

- `1 <= candidates.length <= 30`
- `2 <= candidates[i] <= 40`
- All elements distinct
- `1 <= target <= 40`
- Less than 150 valid combinations guaranteed

---

## Examples

```
Input:  candidates = [2,3,6,7], target = 7
Output: [[2,2,3],[7]]
```

```
Input:  candidates = [2,3,5], target = 8
Output: [[2,2,2,2],[2,3,3],[3,5]]
```

---

## What Actually Matters

- Combinations not permutations — `[2,2,3]` and `[2,3,2]` are the same, only one should appear
- Reuse allowed — recurse with same index `i`, not `i+1`
- No duplicates — always recurse forward (start from `i`) never backward
- Always remove after recursion — forgetting the remove corrupts current for subsequent iterations

---

## Core Insight

> Backtrack with a start index. For each position, either include the element and recurse (staying at same index for reuse) or skip it. Never go back — start index only moves forward, eliminating duplicate combinations.

---

## Invariant / Mental Model

> At every recursive call, you only consider candidates from `start` onward. This guarantees combinations are built in non-decreasing index order — `[2,3]` is generated once, never as `[3,2]`.

---

## Thinking Log (Evolution of the Solution)

- **Prior Knowledge:** Already knew backtracking skeleton from permutations
- **Key Difference 1:** Reuse allowed — pass `i` not `i+1` when recursing
- **Key Difference 2:** No duplicate combinations — passing `start=i` ensures you never pick elements before current position
- **Bug:** When `sum + candidates[i] == target`, added to result but forgot to remove from current — corrupted subsequent iterations
- **Fix:** Move base case to top of function — when sum equals target, add to result and return. Loop only runs when not yet at target. Remove always executes after recursion

---

## Algorithm (High Level)

1. Base case: if `sum == target` → add copy of current to result, return
2. For each index `i` from `start` to end:
   - If `sum + candidates[i] <= target` → add to current, recurse with same `i`, remove after
3. Skip candidates that would overshoot

---

## Code (Reference Only)

```java
class Solution {
    public List<List<Integer>> combinationSum(int[] candidates, int target) {
        List<List<Integer>> result = new ArrayList<>();
        backtrack(candidates, 0, target, 0, result, new ArrayList<>());
        return result;
    }

    public void backtrack(int[] candidates, int start, int target, int sum,
                          List<List<Integer>> result, List<Integer> current) {
        if (sum == target) {
            result.add(new ArrayList<>(current));
            return;
        }
        for (int i = start; i < candidates.length; i++) {
            if (sum + candidates[i] <= target) {
                current.add(candidates[i]);
                backtrack(candidates, i, target, sum + candidates[i], result, current);
                current.remove(current.size() - 1);
            }
        }
    }
}
```

---

## Edge Cases to Recall

- No combination sums to target → base case never hit → return empty list
- Single candidate equals target → `[[candidate]]`
- Always pass `new ArrayList<>(current)` to result — passing `current` directly stores a reference that gets mutated later

---

## One-Line Recall

> Backtrack with start index — recurse at same index for reuse, move start forward to prevent duplicate combinations, always remove after recursion.
