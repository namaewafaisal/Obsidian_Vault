## Part 2: What "completing a topic" actually means

This is the question nobody answers clearly. Here's the honest answer — a topic is complete when you can do all three of these:

**Level 1 — Understand:** You can explain the data structure or algorithm from scratch to someone who doesn't know it. No code, just words. Example: "A sliding window keeps a subarray of elements in view and expands/shrinks the window based on a condition, instead of re-scanning from scratch every time." If you can't explain it, you haven't learned it yet.

**Level 2 — Recognize:** Given a new problem you've never seen, you can identify _which pattern_ it belongs to within 2-3 minutes. This is the actual interview skill. Signs you're here: when you read a problem and feel "oh this is a two-pointer thing" or "this is basically a BFS on a graph."

**Level 3 — Solve unseen variants:** You can solve medium-difficulty problems you've never seen before in that topic, possibly with hints but without needing to look up the full solution.

You move on from a topic when you hit Level 2-3, not when you've memorized every solution. If you cannot explain binary search to a beginner, mastery hasn't happened, no matter how many LeetCode problems you've completed.

## Part 3: Your weekly system (the actual schedule)

This directly mirrors what the paid program sells — one topic per week, structured practice, no randomness.

**The week structure (minimum 3 hours, ideally 5-7):**

Monday/Tuesday — **Learn the concept.** Watch Striver's video for the topic (1-1.5 hours). Code the data structure from scratch yourself (not copy-paste — type it out). Understand the time/space complexity. Write a 3-sentence explanation in your own words in Obsidian.

Wednesday/Thursday — **Solve easy problems in that topic.** Do 3-5 easy problems from NeetCode's list for that pattern. When you get stuck for more than 20 minutes: write down what you tried, _then_ watch NeetCode's video. After watching, close it and re-solve from scratch without looking.

Friday — **Solve medium problems.** Do 2-3 mediums from the same topic. Same rule — 20 min cap before getting a hint, but try to avoid the full solution video.

Saturday — **Solve one unseen problem.** Go to LeetCode, filter by the topic tag, sort by acceptance rate, pick a problem you haven't done. Set a 45-minute timer. This simulates the interview condition. Track metrics: time per problem, success rate on first attempts, number of repeated mistakes.

Sunday — **Review and prepare next week.** Re-solve 2 problems from this week from memory without looking at your notes. If you can't, you haven't internalized the pattern. Write what you'd tell a friend about this topic in 5 sentences.

## Part 5: The "mentor" replacement — how to get unstuck without paying anyone

When you're stuck on a problem, follow this exact sequence:

1. Spend 20 minutes genuinely trying. Write your thoughts — even wrong ones.
2. Look at the NeetCode hints section (free) or read only the first line of the editorial.
3. If still stuck, watch only the first 2 minutes of the NeetCode YouTube video for that problem — enough to know the approach but not the code.
4. Close the video. Try to solve from that direction.
5. If still stuck after another 20 minutes, watch the full video. Then close it. Code the solution yourself from memory 24 hours later.

## Part 6: The mistake log — the most underrated tool

Track mistakes by type: off-by-one errors, unhandled edge cases, wrong data structure choice, miscalculated complexity.

Every time you fail to solve a problem or get the wrong approach, write it in Obsidian under a "Mistake Log" note:

- What the problem was
- What pattern I missed
- What I should have recognized

Review this every Sunday. Log errors in a mistake journal to revisit next week. Steady improvement comes from scheduled review, not just more new problems.
