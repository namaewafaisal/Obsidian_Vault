# [[Change Control]]

## Definition
Formal process used to manage modifications to software systems.

---

# Purpose
- control software changes
- reduce risks
- maintain stability
- ensure traceability

---

# Need for Change Control
Changes may occur due to:
- bug fixes
- new features
- requirement changes
- security updates

---

# Types of Changes

## Corrective Change
Fixes defects.

## Adaptive Change
Adjusts software for environment changes.

## Perfective Change
Improves performance or usability.

## Preventive Change
Reduces future risks/problems.

---

# Change Control Process

## 1. Change Request
Request for modification submitted.

## 2. Impact Analysis
Analyze:
- cost
- risk
- affected modules

## 3. Approval
Approve/reject change.

Usually handled by:
- Change Control Board (CCB)

## 4. Implementation
Develop approved change.

## 5. Testing
Verify correctness.

## 6. Deployment
Release into system.

## 7. Documentation
Update records and documents.

---

# Change Control Board (CCB)

## Definition
Group responsible for reviewing and approving changes.

---

# Relation with Version Control

## Version Control
Tracks changes.

## Change Control
Controls approval and release process.

---

# Benefits
- controlled modifications
- reduced failures
- traceability
- better software quality

---

# Important Definitions

## Change Control
Formal process for managing software changes.

## Change Request
Request submitted for modification.

## CCB
Group responsible for approving changes.
