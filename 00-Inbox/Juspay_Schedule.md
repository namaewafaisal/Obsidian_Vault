# 100-Hour Juspay Prep — 6hrs/Day Schedule
> ~17 days. Flexible — shift hours between days if one topic clicks faster or slower.

---

## Day 1 (6h) — Tree Foundations
- Preorder, Inorder, Postorder (recursive + iterative) — 2h
- Level Order Traversal (master this template) — 2h
- Maximum Depth, Same Tree, Symmetric Tree — 2h

## Day 2 (6h) — Tree Core
- Balanced Binary Tree, Diameter — 2h
- BST Search, Insert, Validate BST — 2h
- Kth Smallest in BST — 1h
- Revise Day 1 cold (no notes) — 1h

## Day 3 (6h) — Tree Medium-Hard
- LCA (BST + general tree) — 2h
- Root to Node Path, Max Path Sum — 2h
- BST Delete — 1h
- Zigzag Traversal — 1h

## Day 4 (6h) — Tree Hard + Wrap
- Top View, Bottom View, Vertical Order — 3h
- Boundary Traversal — 1.5h
- Serialize/Deserialize (understand approach, don't grind) — 1h
- Full tree topic revision, timed — 0.5h

## Day 5 (6h) — Arrays + Strings Patterns
- Two pointers, sliding window — 2h
- Prefix sum, sorting-based tricks — 2h
- Practice "twisted input" variants — disguised versions of basic problems (this is your TCS-NQT fix) — 2h

## Day 6 (6h) — Graphs Core
- BFS/DFS on graphs (not just trees) — 2h
- Shortest path (Dijkstra basics) — 2h
- Cycle detection, topological sort — 2h

## Day 7 (6h) — DP Core Part 1
- 0/1 Knapsack + variations — 2h
- Coin change — 2h
- Longest Common Subsequence — 2h

## Day 8 (6h) — DP Core Part 2 + Linked Lists
- Longest Increasing Subsequence, Grid DP — 2h
- Linked list: fast/slow pointer, reversal — 2h
- Monotonic stack, top-K with heaps — 2h

## Day 9 (6h) — Mixed Timed Practice (Round 1)
- 4-5 random problems across trees/arrays/graphs/DP, strict timer, talk out loud — 5h
- Review mistakes — 1h

## Day 10 (6h) — System Design Deep Dive Part 1
- Caching strategies (cache-aside, write-through), Redis use cases — 2h
- Message queues — Kafka basics, producer/consumer/partition — 2h
- Rate limiting (token bucket) + API idempotency — 2h

## Day 11 (6h) — System Design Deep Dive Part 2
- CAP theorem, why payments are CP systems — 1h
- Build the full Fraud Detection System design end-to-end — 3h
- Practice explaining it out loud, twice — 2h

## Day 12 (6h) — System Design Stress Test
- Re-design fraud detection with twists ("what if multi-region?" "what if 10x traffic?") — 3h
- Draw it from memory, no notes — 1h
- SOLID principles + 3 design patterns (Factory, Strategy, Observer) tied to Spring Boot — 2h

## Day 13 (6h) — Project Ownership (CodeDash)
- Re-read your entire codebase with "why is this here" lens — 3h
- Write out answers: PostgreSQL vs Mongo, RBAC failure modes, scaling to 10k users — 1.5h
- ACID transactions, REST idempotency tied to CodeDash — 1.5h

## Day 14 (6h) — Behavioral + Mixed Revision
- Write out all 4 STAR stories fully — 2h
- Revise weakest DSA topic from Days 1-8 (whichever felt shaky) — 3h
- Light review of VDart internship talking points — 1h

## Day 15 (6h) — Mixed Timed Practice (Round 2)
- 5-6 random problems, harder mix, strict timer — 5h
- Review mistakes, note patterns you keep missing — 1h

## Day 16 (6h) — Mock Interview Simulation
- Full mock: 1 coding problem (45min) + system design (30min) + behavioral (15min), simulate real pressure — 3h
- Review performance honestly — 1h
- Patch weakest area found in mock — 2h

## Day 17 (6h) — Final Consolidation
- Quick-fire revision: one problem per tree pattern, cold — 2h
- Re-explain fraud detection system one final time, no notes — 1h
- Re-read CodeDash "why" answers — 1h
- Rest, light review only, no new learning — 2h

---

## Flex Rules
- If trees take longer than Day 1-4, borrow from Day 5 (arrays) — trees matter more.
- If DP feels shaky, take an extra half-day from Day 14's buffer.
- Days 9, 15, 16 (timed/mock practice) are **non-negotiable** — this is what fixes the "twisted problem" issue specifically. Don't cut these to add more raw topics.
- Skip Rust, ML, Kubernetes hands-on entirely. Not in this schedule on purpose.

---

*Total: 17 days × 6h = 102 hours, with 2 buffer hours built in.*
