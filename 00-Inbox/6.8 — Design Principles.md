# 6.8 — Design Principles

Design Principles:
> guidelines for creating maintainable and scalable software.

They reduce:
- complexity
- tight coupling
- poor architecture

---

# Abstraction

Expose:
- essential behaviour

Hide:
- implementation details

Example:

```java
car.start()
```

User does not need engine internals.

---

# Encapsulation

Combine:
- data
- related behaviour

inside same class.

```java
class BankAccount {
    private double balance;

    public void deposit(double amount) {}
}
```

Protects internal data.

---

# Separation of Concerns (SoC)

Different modules handle:
> different responsibilities

Example:

```text
AuthService
PaymentService
NotificationService
```

Avoid mixing unrelated logic.

---

# Information Hiding

Expose:
- required interfaces only

Hide:
- internal implementation

Example:

```java
public void login()
```

Internal methods hidden:

```java
private validatePassword()
private generateJWT()
```

---

# Single Responsibility Principle (SRP)

A module/class should have:
> one reason to change

---

# Good Example

```text
NotificationService
- sendEmail()
- sendSMS()
```

Single responsibility:
- notifications

---

# Bad Example

```text
UserService
- login()
- processPayment()
- generateInvoice()
```

Mixed unrelated responsibilities.

---

# Principle Summary

| Principle | Focus |
|---|---|
| Abstraction | Hide complexity |
| Encapsulation | Protect internal state |
| SoC | Separate responsibilities |
| Information Hiding | Hide implementation |
| SRP | One responsibility per module |

---

# Important Insight

Good design principles improve:
- maintainability
- modularity
- scalability
- readability
- testing

Violating them often causes:
- technical debt
- tightly coupled systems
- difficult maintenance
