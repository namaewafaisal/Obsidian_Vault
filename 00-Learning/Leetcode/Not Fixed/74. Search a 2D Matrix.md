## LC 74. Search a 2D Matrix

### Problem (Statement)

You are given an `m x n` matrix with two properties:

1. Each row is sorted in ascending order.
2. The first element of each row is greater than the last element of the previous row.

Given an integer `target`, return `true` if it exists in the matrix, otherwise return `false`.

---

### Input / Output

**Input**
```
matrix = [
[1,  3,  5,  7],
[10, 11, 16, 20],
[23, 30, 34, 60]
]
target = 13
```

**Output**
```
false
````

---

### Key Invariant

> **Because of the matrix properties, the entire matrix is totally ordered and can be treated as a single sorted 1D array.**

Index mapping:
- `row = mid / cols`
- `col = mid % cols`

---

### Thinking Log (Actual Evolution, Mistakes Included)

#### Initial Overthinking

> *“I can find the row first, then do a binary search inside that row.”*

This is valid (two-phase binary search), but it complicates reasoning.

---

#### Mixed Strategy Confusion

> *“I’ll compute `mid`, convert to row/column, then fix the row and do a normal binary search.”*

Mistake:
- This **mixes two different strategies**
- Either:
  - do a **single flattened binary search**, or
  - do a **row search first, then column search**
- Mixing them creates unnecessary branching and confusion

---

#### Key Realization

> *“The matrix already behaves like one sorted array.”*

Once this clicked:
- No need to “fix a row”
- No need to reason about row boundaries
- Just binary search on indices `[0 … m*n-1]`

---

#### Clarifying `low` / `high` Updates

Earlier confusion:
> *“If mid is 11 and target is 13, should low become 6?”*

Dry run confirmed:
- `low = mid + 1`
- `high = mid - 1`
- Termination happens naturally when `low > high`

This proved the invariant was intact.

---

#### Final Understanding

> *“This is just normal binary search.  
I was overcomplicating the explanation.”*

The difficulty was **conceptual framing**, not implementation.

---

### Final Correct Code (Java)

```java
class Solution {
    public boolean searchMatrix(int[][] matrix, int target) {
        int rows = matrix.length;
        int cols = matrix[0].length;

        int low = 0;
        int high = rows * cols - 1;

        while (low <= high) {
            int mid = low + (high - low) / 2;
            int row = mid / cols;
            int col = mid % cols;

            int value = matrix[row][col];

            if (value == target) {
                return true;
            } else if (value < target) {
                low = mid + 1;
            } else {
                high = mid - 1;
            }
        }
        return false;
    }
}
````

---

### Complexity Analysis

* **Time:** `O(log(m * n))`
* **Space:** `O(1)`

---

### Final Lock-In Lessons

* When a structure guarantees **global order**, reduce it to **1D binary search**
* Do **not** mix multiple binary-search strategies
* `low` and `high` always move based on `mid`, nothing else
* Conceptual simplicity often comes *after* overthinking once

---

### One-Sentence Recall

> LC 74 is binary search on a flattened matrix; the 2D view is just an index mapping.
