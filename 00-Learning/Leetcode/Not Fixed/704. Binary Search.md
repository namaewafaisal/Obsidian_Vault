## LC 704. Binary Search

### Problem (Statement)

Given a **sorted array of integers** `nums` and an integer `target`,
return the **index** of `target` if it exists in the array.
Otherwise, return `-1`.

The array is sorted in **ascending order** and contains **distinct elements**.

---

### Input / Output

**Input**
```
nums = [-1,0,3,5,9,12]
target = 9
```

**Output**
```
4
```

**Input**
```
nums = [-1,0,3,5,9,12]
target = 2
```

**Output**
```
-1
````

---

### Key Invariant

> **The target, if it exists, always lies within the range `[low, high]`.**

Binary search works by **shrinking this range** every iteration.

---

### Thinking Log (Actual Evolution)

#### Initial Implementation (Buggy)

I implemented binary search using `low`, `high`, and `mid`:

```java
int mid = (high - low) / 2;
````

At first glance, this looked correct, but the solution resulted in **Time Limit Exceeded**.

---

#### What Went Wrong

The formula above computes an **offset**, not an index.

When `low` becomes non-zero:

* `mid` no longer lies inside `[low, high]`
* The search range does not shrink correctly
* `low` and `high` can get stuck
* Result: **infinite loop → TLE**

This breaks the core binary search invariant.

---

#### Realization

> *“`mid` must always be inside the current search range.”*

So `mid` must be calculated **relative to `low`**, not from `0`.

---

#### Correction

Correct and safe calculation:

```java
int mid = low + (high - low) / 2;
```

This guarantees:

* `mid ∈ [low, high]`
* No integer overflow
* Correct boundary reduction

---

### Important Note (Common Confusion)

I also considered:

```java
int mid = (low + high) / 2;
```

This **works logically**, but is **unsafe** due to potential integer overflow.

Industry-standard and interview-safe version is always:

```java
low + (high - low) / 2
```

---

### Final Correct Code (Java)

```java
class Solution {
    public int search(int[] nums, int target) {
        int low = 0;
        int high = nums.length - 1;

        while (low <= high) {
            int mid = low + (high - low) / 2;

            if (nums[mid] == target) {
                return mid;
            } else if (nums[mid] > target) {
                high = mid - 1;
            } else {
                low = mid + 1;
            }
        }
        return -1;
    }
}
```

---

### Complexity Analysis

* **Time:** `O(log n)`
* **Space:** `O(1)`

---

### Transferable Insight

Binary search fails silently when:

* `mid` is calculated incorrectly
* boundaries do not shrink
* invariants are violated

Core rule to remember:

> **If `mid` ever falls outside `[low, high]`, the algorithm is broken.**

This same invariant applies to:

* rotated arrays
* lower/upper bound problems
* search on answer space

---

### Final Lock-In Sentence

> Binary search is not about the loop — it is about preserving invariants.
