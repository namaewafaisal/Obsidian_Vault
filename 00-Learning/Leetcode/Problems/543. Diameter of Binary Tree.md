# 543. Diameter of Binary Tree

## Problem (LeetCode Statement)

**Input:**
- `TreeNode root` — root of a binary tree

**Output:**
- Length of the longest path between any two nodes, measured in edges

**Task:**
Find the diameter — the longest path between any two nodes, which may or may not pass through the root.

---

## Constraints

- `0 <= number of nodes <= 10^4`
- `-100 <= Node.val <= 100`
- Path length is in edges, not nodes

---

## Examples
```
Input:  [1,2,3,4,5]
Output: 3  (path: 4→2→1→3)
```
```
Input:  [1,2]
Output: 1
```

---

## What Actually Matters

- The longest path does NOT have to pass through the root — it can be entirely within a subtree
- At every node, the diameter candidate is `left depth + right depth` — two branches combined
- What you return upward (depth) and what you track as diameter are different things — return is one branch, diameter is two
- Root alone is not enough — a deep internal node may have a larger diameter than what the root sees

---

## Core Insight

> At every node, the diameter candidate is `left + right`. The answer is the max candidate across all nodes. Use DFS post-order — compute left and right depths first, update global max, then return depth to parent.

---

## Invariant / Mental Model

> Every DFS call does two jobs: updates the global diameter with `left + right`, and returns `1 + max(left, right)` as depth to its parent. These are two separate responsibilities at every node.

---

## Thinking Log (Evolution of the Solution)

- **Initial Thought:** At each node, sum left and right depths — that gives the path through the node. Take the max across all nodes
- **Confusion:** Thought returning root's value would capture the global max — since root sees its own left+right, maybe that's always the answer
- **Issue:** Root only sees its two direct branches — it can't see the diameter of a deep internal node whose combined subtree depths are larger
- **Correction:** Need a global variable updated at every node — not just the root
- **Key Distinction:** Return value = depth (one branch, for parent to use). Global update = diameter candidate (two branches combined). Two different things at the same node
- **Final Realization:** Post-order DFS — left and right depths come back first, update global with their sum, return `1 + max(left, right)` upward

---

## Algorithm (High Level)

1. Initialize global `maxDiameter = 0`
2. DFS post-order: recurse left, recurse right
3. At each node: `maxDiameter = max(maxDiameter, left + right)`
4. Return `1 + max(left, right)` to parent
5. Return `maxDiameter` after DFS completes

---

## Code (Reference Only)
```java
class Solution {
    int maxDepth;

    public int diameterOfBinaryTree(TreeNode root) {
        maxDepth = 0;
        dfs(root);
        return maxDepth;
    }

    public int dfs(TreeNode root) {
        if (root == null) return 0;
        int left = dfs(root.left);
        int right = dfs(root.right);
        maxDepth = Math.max(maxDepth, left + right);
        return 1 + Math.max(left, right);
    }
}
```

---

## Edge Cases to Recall

- Single node → left=0, right=0, diameter=0, returns 1
- Null root → dfs returns 0, maxDepth stays 0
- Skewed tree → diameter candidate at every node is 0+depth, max is at the deepest internal node

---

## One-Line Recall

> DFS post-order — at every node update global with `left+right` (diameter), return `1+max(left,right)` (depth) — two responsibilities, one pass.
