# 207. Course Schedule

## Problem (LeetCode Statement)

**Input:**
- `int numCourses` — number of courses labeled 0 to numCourses-1
- `int[][] prerequisites` — pairs where `[a,b]` means take b before a

**Output:**
- `true` if all courses can be finished, `false` otherwise

**Task:**
Determine if a valid course ordering exists — equivalent to detecting if the directed graph has a cycle.

---

## Constraints

- `1 <= numCourses <= 2000`
- `0 <= prerequisites.length <= 5000`
- `prerequisites[i].length == 2`
- No duplicate edges, no self-loops

---

## Examples
```
Input:  numCourses = 2, prerequisites = [[1,0]]
Output: true  (take 0 then 1)
```
```
Input:  numCourses = 2, prerequisites = [[1,0],[0,1]]
Output: false  (cycle: 0 needs 1, 1 needs 0)
```

---

## What Actually Matters

- Problem reduces entirely to cycle detection in a directed graph
- Cycle = impossible to finish, no cycle = always possible
- Graph may be disconnected — must run DFS from every unvisited node
- `visited` alone fails for directed graphs — a node reachable via two paths looks like a cycle but isn't

---

## Core Insight

> Cycle in directed graph = some node is reachable from itself. Detect by tracking which nodes are on the current DFS path — if you reach a node already on your active path, you've found a cycle.

---

## Invariant / Mental Model

> Two arrays serve different purposes:
> - `visited` = node fully processed, safe, never revisit — optimization
> - `path` = node currently on active DFS stack — cycle detector
>
> Cycle condition: reach a neighbor where `path[nei] == true` — you've looped back to an ancestor.

---

## Thinking Log (Evolution of the Solution)

- **Prior Knowledge:** Already implemented `hasCycleDirected` with `visited` + `path` arrays in Graph.java
- **Key Question:** Why not just `visited`? — A node reachable from two separate paths gets marked visited after the first path. Second path sees it as visited and incorrectly flags a cycle
- **Fix:** `path[]` tracks only the current DFS stack. When DFS finishes a node, `path[node] = false` — so other paths reaching it won't false-positive
- **Graph Construction:** `prerequisites[i] = [a,b]` means b→a. So `graph.get(pre[1]).add(pre[0])`
- **Final Realization:** Exact same logic as Graph.java — just wrap it in LeetCode's class structure and build the graph from the input array

---

## Algorithm (High Level)

1. Build adjacency list from prerequisites — `pre[1] → pre[0]`
2. For every unvisited node, run DFS cycle detection
3. In DFS: mark node in `visited` and `path`, recurse neighbors
4. If neighbor is unvisited → recurse; if in `path` → cycle found
5. On DFS exit, set `path[node] = false`
6. If any DFS finds a cycle → return false, else return true

---

## Code (Reference Only)
```java
class Solution {
    public boolean canFinish(int numCourses, int[][] prerequisites) {
        List<List<Integer>> graph = new ArrayList<>();
        for (int i = 0; i < numCourses; i++) {
            graph.add(new ArrayList<>());
        }
        for (int[] pre : prerequisites) {
            graph.get(pre[1]).add(pre[0]);
        }

        boolean[] visited = new boolean[numCourses];
        boolean[] path = new boolean[numCourses];

        for (int i = 0; i < numCourses; i++) {
            if (!visited[i]) {
                if (hasCycle(i, graph, visited, path)) return false;
            }
        }
        return true;
    }

    private boolean hasCycle(int node, List<List<Integer>> graph,
                              boolean[] visited, boolean[] path) {
        visited[node] = true;
        path[node] = true;

        for (int nei : graph.get(node)) {
            if (!visited[nei]) {
                if (hasCycle(nei, graph, visited, path)) return true;
            } else if (path[nei]) {
                return true;
            }
        }

        path[node] = false;
        return false;
    }
}
```

---

## Edge Cases to Recall

- No prerequisites → no edges → no cycle → return true
- Disconnected graph → outer loop over all nodes ensures every component is checked
- Same node reachable via two paths → `visited` prevents reprocessing, `path` prevents false cycle detection

---

## One-Line Recall

> Build directed graph from prerequisites, DFS with `visited` (don't reprocess) and `path` (detect back edge to ancestor) — cycle means false.
