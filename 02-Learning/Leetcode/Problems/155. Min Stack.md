# LC 155. Min Stack

## Problem (LeetCode Statement)

**Input:**  
A sequence of stack operations:

- `push(val)`
- `pop()`
- `top()`
- `getMin()`

**Output:**  
Each operation should work in **O(1)** time.

**Task:**  
Design a stack that supports retrieving the **minimum element** in constant time.

---

## Constraints

- `-2^31 ≤ val ≤ 2^31 - 1`
- At most `3 * 10^4` operations
- `pop`, `top`, and `getMin` are always called on non-empty stacks

---

## Examples

```
push(-2)
push(0)
push(-3)
getMin() -> -3
pop()
top() -> 0
getMin() -> -2
```

---

## What Actually Matters

- A normal stack cannot track minimum efficiently
- Recomputing minimum each time would be `O(n)`
- The solution must maintain minimum **incrementally**

---

## Core Insight

> Maintain a second stack that stores only values that could become the minimum.

---

## Invariant / Mental Model

> The top of the min stack always contains the minimum value of the main stack.

---

## Thinking Log (Evolution of the Solution)

### Initial Thought (your words)

> If I don’t push the bigger values in the min stack then later when the smaller leaves I might not have the bigger one available.

This is a very natural concern.

At first glance it seems we need **all elements sorted in the min stack**, which would require expensive operations.

---

### Attempted Idea (your commented code)

You considered keeping the min stack **sorted**:

```
pop elements until correct place
insert
push back
```

This would maintain a sorted stack but costs **O(n)**.

---

### Realization (your words)

> The bigger values never need to be stored because they can never become the minimum while the smaller value is still in the stack.

And the key part:

> When the smaller value leaves, the bigger values above it would have already been popped.

This observation unlocks the correct design.

---

### Correct Rule

Only push a value into the **min stack** when it becomes a **new minimum**.

When popping:

- If the popped value equals the current minimum
- Pop it from the min stack as well

This keeps both stacks synchronized.

---

## Algorithm (High Level)

1. Maintain two stacks:
   - Main stack
   - Min stack
2. On push:
   - Push to main stack
   - Push to min stack only if value ≤ current minimum
3. On pop:
   - If popped value equals min stack top → pop min stack
4. `top()` returns main stack top
5. `getMin()` returns min stack top

---

## Code (Reference Only)

```java
class MinStack {
    Stack<Integer> st; 
    Stack<Integer> mst;

    public MinStack() {
        st = new Stack<>();
        mst = new Stack<>();
    }

    public void push(int val) {
        st.push(val);
        if(mst.isEmpty() || val <= mst.peek()){
            mst.push(val);
        }
    }
    
    public void pop() {
        if(mst.peek().equals(st.peek())){
            mst.pop();
        }
        st.pop();
    }
    
    public int top() {
        return st.peek();
    }
    
    public int getMin() {
        return mst.peek();
    }
}
```

---

## Edge Cases to Recall

- Duplicate minimum values
- Negative numbers
- Single element stack
- Minimum value being removed

---

## One-Line Recall

> Track minimums with a second stack that stores only values that become new minimums.
