## LC 567. Permutation in String

### Problem (Statement)

Given two strings `s1` and `s2`, determine if **any permutation of `s1`** exists as a **contiguous substring** of `s2`.

Constraints:
- Only lowercase English letters
- `s1.length ≤ s2.length`
- Output is **boolean**

---

### Key Observation

> A permutation match requires **exact character frequencies** over a **fixed-length window**.

This is **not** a dynamic window problem.  
The window size is **always `len(s1)`**.

---

### Core Idea (Fixed-Size Sliding Window Invariant)

> At any moment, the window represents a candidate substring of length `len(s1)` and is valid **only if its frequency balance matches `s1` exactly**.

Instead of:
- resetting on failure  
we:
- **slide one step at a time**
- **undo the effect of the left character**
- **apply the effect of the right character**

---

### Thinking Log (Mandatory)

#### My initial thinking (your words)

> I’ll create a frequency array for `s1`.  
> I’ll traverse `s2` and keep a **temporary copy** of the frequency array.  
>  
> If the current character is not in `s1`, I reset the temp counts.  
> If it is, I decrement the count.  
>  
> When all counts become zero, I return true.  
> I track zeros using a size variable so I know when everything is matched.

---

#### Why this thinking is flawed (correction)

- Resetting only on “character not in `s1`” is insufficient  
  → characters **can be in `s1` but still violate frequency limits**
- Copying arrays indicates **restart-based thinking**, not window-based thinking
- “All counts zero” works only accidentally unless:
  - window size is fixed
  - negative counts are controlled
- Overlapping permutations break this approach

This logic **fails silently** on cases like:
```
s1 = "ab"
s2 = "aaab"
```

---

#### Corrected mental model

> Do not reset.  
> Maintain a **fixed-size window** and **slide it deterministically**.  
> Every character added must be balanced by removing exactly one character.

---

### Algorithm Overview

1. Build frequency array from `s1`
2. Maintain two pointers: `left`, `right`
3. Track:
   - `needed` = number of characters still required to form a permutation
4. For each `right`:
   - Consume character
   - Reduce `needed` if valid
5. When window size exceeds `len(s1)`:
   - Remove `left` character
   - Restore `needed` if necessary
6. If `needed == 0` at any point → permutation exists

Time: `O(n)`  
Space: `O(1)` (26-length array)

---

### Final Code (Java)

```java
class Solution {
    public boolean checkInclusion(String s1, String s2) {
        if (s1.length() > s2.length()) return false;

        int[] freq = new int[26];
        for (char c : s1.toCharArray()) {
            freq[c - 'a']++;
        }

        int left = 0, right = 0;
        int needed = s1.length();

        while (right < s2.length()) {
            char c = s2.charAt(right);
            if (freq[c - 'a'] > 0) {
                needed--;
            }
            freq[c - 'a']--;
            right++;

            if (needed == 0) return true;

            if (right - left == s1.length()) {
                char lc = s2.charAt(left);
                if (freq[lc - 'a'] >= 0) {
                    needed++;
                }
                freq[lc - 'a']++;
                left++;
            }
        }
        return false;
    }
}
```

### Common Mistakes

- Resetting frequency array instead of sliding
- Forgetting to undo left pointer effects
- Allowing window to grow beyond `len(s1)`
- Checking “all zeros” without fixed window size

---

### One-Sentence Recall

> LC 567 works by sliding a fixed-size window of `len(s1)` over `s2` and maintaining exact frequency balance without ever resetting the state.
