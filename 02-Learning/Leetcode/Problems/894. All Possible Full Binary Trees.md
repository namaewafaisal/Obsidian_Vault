# 894. All Possible Full Binary Trees

## Problem

**Input:** integer `n`

**Output:** all possible **full binary trees** with exactly `n` nodes

```
Input:  n = 7
Output: all structurally unique full binary trees with 7 nodes
```

Related: [[Pattern - Divide and Conquer (Generate All Structures)]]

---

## Core Insight

> A full binary tree requires every node to have either **0 or 2 children**. After choosing one node as the root, the remaining `n-1` nodes must be split into an **odd number of nodes on the left** and an **odd number on the right**. Generate all left trees × all right trees and combine them.

---

## Thinking Log

- Initial thought: This looked almost the same as LC 95, but instead of choosing every value as the root, the root is always the same (`0`).
- Issue: The split is no longer by value range. We only know how many nodes remain.
- Realization: The recursive state is simply **"how many nodes are available"**.
- Key insight: A full binary tree can only have an **odd number of nodes**, so even `n` immediately returns no trees.
- Final understanding: Split the remaining nodes into every valid odd `(leftNodes, rightNodes)` pair, recursively generate both sides, then take their cross-product.

---

## State / Split / Base / Combine

| Pillar | This problem |
|---|---|
| **State** | `n` — number of nodes available |
| **Split point** | every odd `leftNodes` from `1` to `n-2` |
| **Base case** | `n == 1` → single leaf node |
| **Combine** | create one root, attach every left tree with every right tree |

---

## Algorithm

1. If `n` is even, return an empty list.
2. If `n == 1`, return a list containing one leaf node.
3. Try every odd split:
   - `leftNodes`
   - `rightNodes = n - leftNodes - 1`
4. Generate all left and right trees recursively.
5. Cross-product every left tree with every right tree.
6. Memoize by `n` since the same subtree sizes repeat.

---

## Code

```java
class Solution {
    Map<String, List<TreeNode>> dp = new HashMap<>();

    public List<TreeNode> allPossibleFBT(int n) {

        if(dp.containsKey(String.valueOf(n))){
            return dp.get(String.valueOf(n));
        }

        List<TreeNode> result = new ArrayList<>();

        if(n % 2 == 0){
            return result;
        }

        for(int leftNode = 1; leftNode < n; leftNode += 2){
            int rightNode = n - leftNode - 1;

            List<TreeNode> leftTree = allPossibleFBT(leftNode);
            List<TreeNode> rightTree = allPossibleFBT(rightNode);

            for(TreeNode left : leftTree){
                for(TreeNode right : rightTree){
                    TreeNode curr = new TreeNode(0);

                    curr.left = left;
                    curr.right = right;

                    result.add(curr);
                }
            }
        }

        if(n == 1){
            result.add(new TreeNode(0));
        }

        if(n == 0){
            result.add(null);
        }

        dp.put(String.valueOf(n), result);
        return result;
    }
}
```

## Bugs I Actually Hit

- Initially thought about splitting by values like LC 95, but here **values don't matter**, only node counts.
- Easy to forget that **only odd node counts can form full binary trees**.
- Base case `n == 0` must return `[null]`, otherwise the cross-product won't create leaf nodes correctly.
- Memoization key is just `n`, not `(start, end)`, because subtree structure depends only on the number of nodes.

---

## Connection to LC 95

| LC 95 | LC 894 |
|---|---|
| State = `(start, end)` | State = `n` |
| Split by root value | Split by left subtree size |
| Values matter | Values don't matter |
| BST property decides ranges | Full-tree property decides odd splits |
| Combine left × right | Combine left × right |

The recursive pattern is identical—the **state representation** is the only real difference.

## One-Line Recall

> Instead of splitting by value ranges like LC 95, split the remaining **odd node counts**, recursively generate left/right trees, and combine every pair.
