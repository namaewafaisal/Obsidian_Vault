# 241. Different Ways to Add Parentheses

## Problem

**Input:** string `expression` containing digits and `+ - *`
**Output:** all possible results from every valid way of grouping/parenthesizing the operators

```
Input:  "2*3-4*5"
Output: [-34, -14, -10, -10, 10]
```

Related: [[Pattern - Divide and Conquer (Generate All Structures)]]

---

## Core Insight

> Every operator in the string is a potential "last operation" — a potential root of the expression tree. Pick an operator, split the string there, recursively get all possible values of the left half and right half, then combine with that operator. Same shape as [[95. Unique Binary Search Trees II]], just recursing on a **string** instead of a **range**.

---

## Thinking Log

- Initial thought: pre-parse into a `numbers[]` array and an `operators[]` array, then index with start/end like the BST range problem
- Realization: unnecessary — recursing directly on the **substring** already gives everything needed via `substring(0, i)` / `substring(i+1)`
- Key insight: the base case falls out naturally — if a substring has no operator character at all, it's just a number, no separate array needed
- Final understanding: same cartesian-product combine step as BST II, just swap "attach left/right subtree" for "apply the operator to left/right values"

---

## State / Split / Base / Combine

| Pillar | This problem |
|---|---|
| **State** | the substring itself |
| **Split point** | every index `i` where `expression.charAt(i)` is `+`, `-`, or `*` |
| **Base case** | no operator found in the substring → it's a pure number, `Integer.parseInt(expr)` |
| **Combine** | apply the operator to every `(left, right)` value pair: `l+r`, `l-r`, `l*r` |

---

## Algorithm

1. `helper(expression)` returns all possible integer results for that substring
2. Scan for operator characters; for each one found:
   - `left = helper(expression.substring(0, i))`
   - `right = helper(expression.substring(i+1))`
   - combine every `(l, r)` pair using that operator, add to results
3. If no operators were found during the scan, `results` is still empty → base case: parse the whole substring as a number
4. Memoize on the substring itself as the key

---

## Code

```java
class Solution {
    Map<String, List<Integer>> dp = new HashMap<>();

    public List<Integer> diffWaysToCompute(String expression) {
        return helper(expression);
    }

    public List<Integer> helper(String expression) {
        if (dp.containsKey(expression)) return dp.get(expression);

        List<Integer> result = new ArrayList<>();

        for (int i = 0; i < expression.length(); i++) {
            char c = expression.charAt(i);
            if (c == '+' || c == '-' || c == '*') {
                List<Integer> left = helper(expression.substring(0, i));
                List<Integer> right = helper(expression.substring(i + 1));

                for (int l : left) {
                    for (int r : right) {
                        switch (c) {
                            case '+': result.add(l + r); break;
                            case '-': result.add(l - r); break;
                            case '*': result.add(l * r); break;
                        }
                    }
                }
            }
        }

        if (result.isEmpty()) {
            result.add(Integer.parseInt(expression));  // pure number, base case
        }

        dp.put(expression, result);
        return result;
    }
}
```

## One-Line Recall

> Every operator is a possible split point; recurse on substrings, cross-product left values × right values through that operator, and let "no operator found" be the base case.
