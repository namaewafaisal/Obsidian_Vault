# 95. Unique Binary Search Trees II

## Problem

**Input:** integer `n`
**Output:** all structurally unique BSTs storing values `1..n`

```
Input:  n = 3
Output: all 5 unique BST shapes using values 1,2,3
```

Related: [[Pattern - Divide and Conquer (Generate All Structures)]]

---

## Core Insight

> Any value in `1..n` can be the root. Once picked, everything smaller must be the left subtree, everything larger must be the right subtree — this falls straight out of the BST property. So the problem is really: "generate all BSTs for range `(start, end)`" recursively.

---

## Thinking Log

- Initial thought: treat it like generating permutations, track a `used[]` boolean array
- Issue: BSTs from a sorted range aren't permutations — there's no need to track "used" values, the range itself tells you what's available
- Realization: the real recursive unit is a **range**, not a set of used flags
- Key insight: empty subtree isn't "nothing" — it's a valid result that must be represented as `[null]`, a list with one entry, or the combine step's nested loop silently skips it
- Final understanding: for each root, get all left shapes × all right shapes, cross-product them together

---

## State / Split / Base / Combine

| Pillar | This problem |
|---|---|
| **State** | `(start, end)` — the range of values available |
| **Split point** | every value `root` in `[start, end]` |
| **Base case** | `start > end` → empty subtree → return `[null]`, not `[]` |
| **Combine** | `new TreeNode(root)`, attach one `left` and one `right` per pairing |

---

## Algorithm

1. `helper(start, end)` generates all BST shapes for that range
2. If `start > end`, return a list containing just `null` (empty subtree, still a valid "shape")
3. For each `root` in `[start, end]`:
   - get `leftTrees = helper(start, root-1)`
   - get `rightTrees = helper(root+1, end)`
   - for every `(left, right)` pair, build a new node and add to results
4. Memoize on `"start,end"` key — same range gets recomputed across different outer root choices

---

## Code

```java
class Solution {
    Map<String, List<TreeNode>> dp = new HashMap<>();

    public List<TreeNode> generateTrees(int n) {
        if (n == 0) return new ArrayList<>();
        return helper(1, n);
    }

    public List<TreeNode> helper(int start, int end) {
        String key = start + "," + end;
        if (dp.containsKey(key)) return dp.get(key);

        List<TreeNode> trees = new ArrayList<>();

        if (start > end) {
            trees.add(null);
            dp.put(key, trees);   // cache the base case too
            return trees;
        }

        for (int root = start; root <= end; root++) {
            List<TreeNode> leftTree = helper(start, root - 1);
            List<TreeNode> rightTree = helper(root + 1, end);

            for (TreeNode left : leftTree) {
                for (TreeNode right : rightTree) {
                    TreeNode curr = new TreeNode(root);
                    curr.left = left;
                    curr.right = right;
                    trees.add(curr);
                }
            }
        }

        dp.put(key, trees);
        return trees;
    }
}
```

---

## Bugs I Actually Hit

- Used a `boolean[] used` array like a permutation problem — wrong mental model entirely, range already encodes what's available
- First pass forgot to cache the `start > end` base case in `dp` — didn't break correctness, but defeated memoization on that branch

---

## One-Line Recall

> Any value can be root; recurse on `(start, end)`, cross-product left shapes × right shapes, and treat empty subtree as `[null]` not `[]`.
