### Problem (summary)

Given an array of strings `strs`, group the **anagrams** together. You can return the answer in any order. An anagram is a word or phrase formed by rearranging the letters of a different word or phrase, typically using all the original letters exactly once.

---

### Key Invariant

> **Grouping problems are not comparison problems — they are classification problems.**

* Two strings are anagrams **if and only if** they share the exact same character frequency distribution.
* By converting this distribution into a **unique String key**, we create a "fingerprint" for the entire anagram group.

---

### Thinking Log (Evolution of the Solution)

* **Initial Thought (Brute Force Instinct):**
Compare every string with every other string using a frequency array.
*Critique:* Leads to . Does not scale and is hard to implement correctly.
* **Core Realization:**
Instead of asking "Does string A match string B?", ask **"What category does this string belong to?"**
* **Key Question That Changed the Approach:**
"How do I uniquely identify an anagram group?"
*Answer:* Anagrams have the same character frequency distribution.
* **Generating the Shared Key (Critical Insight):**
I could sort the string (), but a **frequency-based key** is .
Example: `eat` → `[1,0,0,0,1,...,1]`.
* **Why a String Key is Needed:**
Arrays in Java use memory addresses for hashing. To group them in a `HashMap`, I must encode the frequency array into a **String** (e.g., `"1#0#0#0#1..."`). This string becomes the "identity" of the group.
* **The "One-Liner" (`computeIfAbsent`):**
"Give me the bucket for this key—if it doesn't exist, create it—then put my item inside." This eliminates null checks and clunky `if-else` blocks.

---

### Implementation Strategy

1. Create a `HashMap<String, List<String>>`.
2. Iterate through each string in `strs`.
3. Build an `int[26]` frequency array for the string.
4. Convert the array into a delimited `StringBuilder` string (e.g., using `#` as a separator).
5. Use `computeIfAbsent` to fetch the list associated with that key and `.add()` the current string.
6. Return a new `ArrayList` containing all `map.values()`.

---

### Final Code (Java)

```java
class Solution {
    public List<List<String>> groupAnagrams(String[] strs) {
        Map<String, List<String>> result = new HashMap<>();

        for (String s : strs) {
            // 1. Build frequency fingerprint
            int[] count = new int[26];
            for (char c : s.toCharArray()) {
                count[c - 'a']++;
            }

            // 2. Convert frequency array to a unique String key
            StringBuilder key = new StringBuilder();
            for (int i = 0; i < 26; i++) {
                key.append(count[i]).append('#');
            }

            // 3. Group by the key (Identity of the anagram)
            result.computeIfAbsent(key.toString(), k -> new ArrayList<>()).add(s);
        }

        return new ArrayList<>(result.values());
    }
}

```

### Transferable Insight

Whenever a problem asks you to **group**, **categorize**, or **collect by similarity**, stop comparing items to each other. Instead, look for an **invariant** (like a sorted string or a frequency count) that you can use as a **Hash Key**.
