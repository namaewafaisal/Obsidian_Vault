# 455. Assign Cookies

## Problem

You are given:
- `g[]`: Each child's minimum cookie size required to be content.
- `s[]`: Available cookie sizes.

Each child can receive at most one cookie, and each cookie can be assigned to at most one child.

Return the maximum number of content children.

**Example:**

```
Input:
g = [1,2,3]
s = [1,1]

Output: 1
```

---

## Pattern

**Greedy + Sorting + Two Pointers**

## Core Idea

- Sort both arrays in ascending order.
- Use `child` to track the current child and `cookie` to track the current cookie.
- If the cookie satisfies the child's greed factor:
  - Assign the cookie.
  - Move to the next child.
  - Increment `count`.
- Otherwise, the cookie is too small, so discard it and try the next cookie.

**Greedy choice:** Always try to satisfy the least greedy child with the smallest available cookie that can satisfy them.

This preserves larger cookies for children who need them.

---

## Dry Run

### Case 1: Not every child gets a cookie

```
g = [1,2,3]
s = [1,1]
```

Both arrays are already sorted.

| child | cookie | Comparison | Action |
|---:|---:|---|---|
| 0 | 0 | 1 <= 1 | Assign; count = 1 |
| 1 | 1 | 2 <= 1 is false | Skip cookie |
| 1 | End | No cookies left | Stop |

```
count = 1
```

### Case 2: All children can be satisfied

```
g = [1,2]
s = [1,2,3]
```

| child | cookie | Comparison | Action |
|---:|---:|---|---|
| 0 | 0 | 1 <= 1 | Assign |
| 1 | 1 | 2 <= 2 | Assign |

```
count = 2
```

## Code

```java
class Solution {
    public int findContentChildren(int[] g, int[] s) {
        Arrays.sort(g);
        Arrays.sort(s);

        int count = 0;
        int cookie = 0;
        int child = 0;

        while(child < g.length && cookie < s.length) {

            if(g[child] <= s[cookie]) {
                count++;
                child++;
            }

            cookie++;
        }

        return count;
    }
}
```

---

## Things to Remember

- Sorting makes the greedy assignment possible.
- A cookie that is too small can never satisfy the current child or any child after them.
- Always move the cookie pointer.
- Move the child pointer only when a child is satisfied.
- Time complexity: \(O(n\log n + m\log m)\), where `n = g.length` and `m = s.length`.
- Auxiliary space: Depends on the sorting implementation; the two-pointer traversal itself uses \(O(1)\) extra space.

## One-Line Recall

> Sort children and cookies, then use two pointers to give each child the smallest cookie that satisfies their greed factor.
