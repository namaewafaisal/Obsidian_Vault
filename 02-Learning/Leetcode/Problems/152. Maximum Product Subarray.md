# LC 152 — Maximum Product Subarray

## Metric

| Metric     | Value                    |
| ---------- | ------------------------ |
| Difficulty | Medium                   |
| Pattern    | Dynamic Programming (1D) |
| Topic      | Array / Greedy / DP      |

---

## Problem Statement

Given an integer array `nums`, find the **contiguous subarray** within the array that has the **largest product**, and return that product.

---

## Input / Output

**Input**

```
nums = [-2, 3, -4]
```

**Output**

```
24
```

---

## Why This Problem Is Tricky

This looks similar to **Maximum Subarray Sum (LC 53)**, but **multiplication behaves differently**:

* Negative × Negative = Positive
* A “bad” (very negative) product can later become the **best**
* Zero completely breaks continuity

Because of this:

* You **cannot discard negative results**
* You **cannot track only one running value**

---

## Key Insight (This Is the Core)

At **every index**, you must know:

1. The **maximum product** of a subarray that **ends at this index**
2. The **minimum product** of a subarray that **ends at this index**

Why both?

* A future **negative number** can flip:

  * min → max
  * max → min

So we track **two local states**, not global ones.

---

## Core Invariant (Must Remember)

At index `i` with value `x = nums[i]`:

Any subarray ending at `i` must be **one of these three**:

1. Start fresh at `x`
2. Extend previous max → `prevMax * x`
3. Extend previous min → `prevMin * x`

So:

* `currMax = max(x, prevMax * x, prevMin * x)`
* `currMin = min(x, prevMax * x, prevMin * x)`

This **automatically handles**:

* positives
* negatives
* zero
* sign flipping

No special casing required.

---

## Final Correct Code (Java)

```java
class Solution {
    public int maxProduct(int[] nums) {
        int prevMax = nums[0];
        int prevMin = nums[0];
        int ans = nums[0];

        for (int i = 1; i < nums.length; i++) {
            int x = nums[i];

            int currMax = Math.max(x, Math.max(prevMax * x, prevMin * x));
            int currMin = Math.min(x, Math.min(prevMax * x, prevMin * x));

            prevMax = currMax;
            prevMin = currMin;

            ans = Math.max(ans, prevMax);
        }

        return ans;
    }
}
```

## Why This Works (Intuition)

* Positive number → order preserved
* Negative number → roles flip automatically
* Zero → forces restart via `x` candidate
* No window shrinking or manual resets needed

Everything is handled by **local state comparison**.

---

## Common Wrong Approaches (You Tried These)

❌ Single running product
❌ Global min / max
❌ Pairing negatives manually
❌ Resetting logic like Kadane sum

All fail because they **lose local information**.
